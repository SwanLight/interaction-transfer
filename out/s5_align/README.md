# S5 命令轴的选型证据（D-65）

`tools/s5_align_probe.py` 在 33 条真实 S4 记录上比较五种把多条示教对齐到同一条
command 轴的做法。完整输出在 `probe.txt`（数值）与 `probe.json`（机器可读）。

**为什么需要这一步**：v1 直接按任务完成度 `progress` 分格，实测抽屉 83.9%、
旋钮 73.3% 的帧落进 32 格里的 2 格，而所有既有校验都通过（P-58）。选型不能靠直觉。

**主判据是 `binJS`** —— 同一条 episode、同一个命令格内，各接触帧的接触分布彼此有多
不一致。它**不受格子大小混淆**，直接回答"这个格有没有把物理上不同的接触状态混进
同一条命令"。副判据是接触格占比（命令通道有多少格真的在描述接触）与空格率。

**没有**用 `within_family_js`（同族两条示教在同一格上的分布差异）当主判据：它会
**奖励退化对齐**——把 84% 的帧倒进 2 个格，得到的分布高度平均、彼此 trivially 相似。
它在抽屉上确实略偏向 v1 的做法（0.301 vs 0.307），这一条如实记在 D-65 里。

结论：`activity`（按 phase 分段 + 段内按累计交互活动量）在三个任务上 binJS 最低或
并列最低，接触格占比 87~100%，空格率 0。已作为 `interaction-transfer-v2` 的对齐轴。
