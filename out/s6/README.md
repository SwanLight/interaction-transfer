# S6 — E-I 交互跟踪执行器（地基完成，训练未跑）

> **这一步的主张是**：每种形态各自训练一个 interaction-conditioned executor，
> 收到同一份 interaction 指令后生成自己的动作。它是最终系统（`plan/README` §8），
> 不是对照实验。

**当前状态：指令来源、指令通道、跟踪 reward、网络与环境都已就位并验过；
PPO 训练循环还没接 rsl_rl。** 下一个人从 `tools/s6_train.py` 末尾那条报错开始。

## 1. 指令来源

| | 份数 | 说明 |
|---|---:|---|
| 探针指令 | **43** | 10 个物体 × 15 条原语，按 `(物体, 原语)` 拆（D-76）。这是"摸索自己形态能力"的主体 |
| 任务指令 | 3 | 抽屉 / 擦拭 / 旋钮，合并五个策略家族——归纳共同的功能要求正是本项目的主张 |

**为什么探针要拆、任务不拆**："戳球"和"滚球"是两种交互，合进一份 envelope 得到的是
一个没有物理意义的平均；而同一个"拉开 20 mm"由五种策略实现，归纳它们的共同要求
才是 `plan/02` §4 要的东西。

calibration 按 `(物体, 原语)` 分层重划到每组 30 条（`probe_split.txt`）。
**只在 train 与 calibration 之间移动，任何 `*_test` 划分一条不碰**，且在任何训练之前做，
所以不存在可以被倒推的结果。43 份里 **6 份**的 region 用了兜底平滑（D-78），
逐份记在 `probe/index.json` 的 `region_smooth_cells` 里。

⚠️ `column/push` 只有 25 条成功、够不上校准下限，排除后 **`push` 在可标定指令集上
只剩 `block` 一个承载物体**。数据集本身的原语覆盖不变，但 E-I 在这条原语上只见过
一种几何——**S7 的 leave-one-primitive 分析必须把它单列**（D-60）。

## 2. 跟踪 reward 的离线体检（`reward_probe.txt`）

**一、在线（跟踪指令）与离线（造指令）是同一个量吗？**

| 任务 | 中位比值 | log 相关 | |
|---|---:|---:|---|
| 抽屉 | 1.000 | 0.931 | ✅ |
| 擦拭 | 0.999 | 0.968 | ✅ |
| 旋钮 | 1.000 | 0.997 | ✅ |

修之前是 **1.753 / 1.660 / 1.481**（相关 0.93~0.98 —— 干净的系统偏差，不是噪声）。
后果本来会是：指令盒在离线值上标定，**一条完美复现 source 的轨迹在线上落在盒外，
`r_mech` 反过来惩罚正确行为**，而训练曲线照样会涨。已按 D-79 换成同一个式子，
并加了 `rtol=1e-9` 的对拍测试。详见 P-72。

**二、reward 分得开"执行自己的指令"和"执行别人的指令"吗？**

| 任务 | 自己的指令 | 错配指令 | AUC |
|---|---:|---:|---:|
| 抽屉 | −0.283 | −0.612 | **0.955** |
| 擦拭 | −0.249 | −12.769 | **1.000** |
| 旋钮 | −0.126 | −1.290 | **1.000** |

**这是最要紧的一节。** 跟踪 reward 若对指令不敏感，训练曲线照样会涨，
而学到的是"做点什么"而不是"实现这份规格"。

**三、各项量级**（用来标定权重，不许拍——D-31 第 2 个洞）：
`{"effect": 0.0852, "region": 0.0405, "mode": 0.0237, "mech": 0.0138}`。
四项落在 0.0007~0.16 之间，没有哪一项会淹没其余。

⚠️ `r_effect` 的形式被 dry-run 改过一次（D-80）。照 D-74 的字面写成"实测与指令之差"时，
环境里它报到 **−26647 且逐步线性增长**，比其余三项大六个数量级——命令格的时长是弹性的，
指令 effect 是"这一格总共要发生多少"而不是速率，而且除以了一个可能趋零的刻度。
改成**本格的完成缺口**（有界 [0,1]、刻度约掉、势函数式）之后，dry-run 上四项都在
0~1 之间。**这一条说明 dry-run 不能省**：离线体检用的是成功示教（effect 一直在推进），
随机策略下的病态区间它根本走不到。

## 3. 三个不能改错的设计点

1. **跟踪项是 hinge，落在标定集合内恰好为零。** `region/allowed`、`mech/*/{lo,hi}`、
   `mode/slip_speed/{lo,hi}` 都是**允许集合**不是点目标。改成"离中位数越近越好"
   就等于把 C4 实现成了 C5（精确复现 source 的力），而 `plan/02` §6 的 C4 vs C5
   对照正是要问"复制 source 是不是多余的"——那个实验会直接失去意义；
2. **动作空间带力**（6 维位姿增量 + 3 维力矢量）。接触力是穿透量的刚性函数：
   `float_ctrl` 里记着实测，推子距表面 0.5 mm 时法向力只有 0.06 N 而目标是 25 N。
   纯位置动作等于要求 PPO 学会亚毫米定位；
3. **窗口按执行器自己的进度推**，判据全部由通用量导出（允许区域内的实测法向力 +
   effect 完成比例）。采集脚本的 `phase`/`progress` 是任务状态机，一律不进观测。
