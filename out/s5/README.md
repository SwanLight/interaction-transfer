# S5 — 从多条示教形成可传递 interaction（全量结果）

> **要看给人读的版本，打开 `out/report.html` 的 S5 段**——那里有允许区域画在物体上的图、
> 命令轴分帧的对比图，每一项检查都写了"在验什么 / 怎么读 / 实测多少"。
> 本文件是技术摘要，保留决策编号与字段名，供改代码的人对照。


契约是 `interaction-transfer-v4`（D-65 / D-66 / D-67 / D-71 / **D-72 / D-73 / D-74**，
早期版本读到即报错）。v3→v4 修的是三个字段各自的**单位与刻度**，见下面第 6 节。
三个任务各从 **train split 全量**构造一份 artifact，**标定烤在 artifact 里**——
`region/allowed` 与 `mech/*/lo,hi` 用**冻结的 calibration 划分**做 split conformal 定出，
E-I 拿到的是有覆盖保证的集合，不是描述性分位数。再在冻结的 test 划分上跑十项闸门。

**判据是退出码，不是这份文件的开头**（P-55）。`bash tools/s5_all.sh` 逐项收退出码，
三个任务的 `eval_*` 目前都非零。DEFER 的项目**不得引用成通过**。

复现（服务器上，系统 python3 没有 numpy，必须指定解释器）：

```bash
IT_PY=/isaac-sim/python.sh ./tools/run_remote.sh \
    "IT_PY=/isaac-sim/python.sh bash tools/s5_all.sh" s5
./tools/s5_fetch.sh          # 取回文本产物；npz 按 D-23 不进版本控制
```

## 3. 三条能直接用的结论

**① region envelope 必须标定，标定之后很紧。** 未标定的描述性超水平集（τ=0.95）在
抽屉上只有 0.844~0.971 的 coverage；在冻结校准集上做 split conformal 之后
（D-67），抽屉 τ*=0.990 给出 0.953~0.971 的留出 coverage，**代价是允许区域仅占物体
表面积的 1.35%——256 个 cell 里平均只有 5 个**。旋钮 1.37%，擦拭 4.42%。
这是 `plan/03` §8.1 那个"在 coverage ≥ 90% 的约束下最小化 width"目标函数的第一组实测值。

**② mechanics 的边缘刻度是准的，缺的是一个显式的联合集合。**

⚠️ **本条此前写反了，已更正（P-65）。** 早先报的"逐点带内率 0.24~0.68 低于名义
0.80，所以逐点边缘分位数这个形式本身不行"是**指标造出来的**：那个数要求
x、y、z **三个分量同时**落在各自的边缘区间里。逐轴分开测的结果是：

| 任务 | x | y | z | 三轴独立时联合应为 | 实测联合 |
|---|---:|---:|---:|---:|---:|
| 抽屉 | 0.811 | 0.757 | 0.746 | 0.458 | 0.521 |
| 擦拭 | 0.869 | 0.876 | 0.893 | 0.679 | 0.765 |
| 旋钮 | 0.811 | 0.805 | 0.811 | 0.529 | 0.614 |

**逐轴刻度正常**（名义 0.80，实测 0.75~0.89），实测联合值还略高于独立乘积，
说明分量间是弱正相关。所以**物体系三维 traction 这个表示没有问题**。

真正缺的是：**从来没有构造过一个联合允许集合**，报告里报的是三个边缘区间的交集，
而它的覆盖率按定义就该显著低于任一单轴的名义值。

集合该长什么形状，由 `tools/s5_mech_setform.py` 在**同一 coverage 目标下比体积**
实测决定（D-71），**不由规格拍板**——坐标只是换基，执行器拿 payload 里的
`surface/normals_obj` 自己就能转，待定的是**形状**不是坐标：

| 集合形状 | 抽屉尺度 | 擦拭尺度 | 旋钮未见策略 coverage |
|---|---:|---:|---:|
| **`box_obj` 物体系轴对齐盒** ← 选中 | **7361** | **1274** | 0.013 |
| `box_surface` 局部系盒 | 9554 | 1274（平板上与前者恒等） | 0.010 |
| `ellipsoid` 马氏椭球 | 8745 | **1065** | 0.007 |
| **`cone`（D-58 原本规定的那种）** | **17764** | **71567** | 0.000 |

**D-58 规定的"法向区间 × 切向幅值 × 方向锥"是四族里最差的**——体积大 2.4×（抽屉）
到 **56×**（擦拭），换不来任何一致的 coverage 收益，已按实测否决。盒与椭球互有胜负
（擦拭椭球小 16%、抽屉大 19%），选盒子是因为它不拟合训练分布的相关结构、实现最简单；
椭球的数字一并落盘，若 S6 显示盒子过松，它是第一顺位备选。

补上标定之后，同一个"带内率"指标从 0.24~0.68 变成 **0.966~0.989**。

**③ 没有严重多峰。** 聚合出的 envelope 到各示教的距离 / 示教两两之间的距离 =
**0.84 / 0.96 / 0.92**，都 < 1，即质心落在示教分布**内部**而不是两峰之间的谷里。
所以 D-63 预留的"改聚类或条件模型"这条路**暂时不需要走**。
⚠️ 这个比值早先用最近邻当分母，得到 3.01~36.9 的假信号（P-61）——最近邻距离随
样本量必然趋于 0，那个数里绝大部分是"323 > 12"本身。

## 4. 两处**不得**当成方法结论的失败

**擦拭 `direct_wipe` 的 0.000 是寄生接触造成的（D-69 / P-64）。** 那批记录里每一帧
都有一个固定在板角 (0.260, 0.200)、法向力 0.196 N（**方差 2%**）的接触，**60 条
episode 全部存在**，占 9~12% 的力，四个 phase 都在——是那块**没被使用的黑板擦**搁在
板上被逐帧记成交互。在"至少 95% 接触质量落入允许集合"的判据下，恒定 10% 的寄生力
足以让**每一条** episode 都不通过。

因此 `plan/02` §7 第 8 条（两种实现的 envelope 可互换）在重采之前**不可评估**，
**既不得报"通过"，也不得报"不可互换"**。检查已拆成 6a（payload 无实现字段，✅ 通过）
与 6b（两实现距离，只报数不判定）。

`tools/s5_parasite_check.py` 把这次的人工排查变成了可重复的检查，已接进
`tools/s5_all.sh`。实测它在 `direct/direct_wipe` 上报 FAIL（接触率 1.000、力 0.200 N、
cv 0.000、位移 std 0.0 mm），而在**其余 19 个分组上全部 PASS**：擦拭五个 `with_tool`
家族、抽屉五个家族、旋钮四个家族、十个探针物体。**寄生接触只限于 `direct_wipe` 一档。**

**子群 coverage 的落差是真的，但不是同一回事。** 抽屉 `pinch_offset` 0.833、
旋钮 `pin_push_dual` 0.685 是**方法层面的实测结果**：conformal 只保证 exchangeability
下的 **marginal** coverage，对任意子群没有条件保证（D-59），实测证实了这一点。
这一条要如实进论文的限制一节，不能靠调 τ* 掩盖。

## 5. 顺带证实的两件事

**同部件池化让 envelope 同时更准更紧（D-68 / P-63）。** 修复前 `parent[level]` 是纯
几何最近邻，黑板 26.0% 的表面点被判给了另一个部件的代表点（20 mm 厚的板 vs 50 mm
的粗粒 pitch）。改成只在同部件内找之后，在同一个 τ* 下：

| | 抽屉 width | 擦拭 `unseen_strategy` coverage | 擦拭 width |
|---|---:|---:|---:|
| 修复前 | 2.25% | 0.655 | 5.86% |
| 修复后 | **1.35%** | **0.997** | **4.42%** |

**P-57 得到直接确证。** 本机重新生成的抽屉/旋钮 surface 与服务器冻结的那份 **points
不一致**（黑板一致）——FPS 的 tie-breaking 确实跨环境改变点序。`tools/s5_freeze_surfaces.py`
已在产生数据的机器上核对 hash 后落盘 9 个 `frozen-surface-v1`，并写回 manifest。

## 6. v3 → v4：三个字段的单位与刻度（D-72 / D-73 / D-74）

**这三条都不报错、都让所有既有校验照常通过。** 共同形状是：单元测试查得了"实现有没有
bug"，查不了"这个量的定义对不对"。可复现的实测在 `units_probe.txt`（进了 `s5_all.sh`）。

**① traction 之前随表面采样分辨率线性放大（P-68）。** 接触力被整个塞进最近的命令格再
除以格面积，于是 `N/m²` 里的 m² 是我们随手选的分辨率。把命令表面从 64 换到 1024 格：

| 池化做法 | 抽屉 | 擦拭 | 旋钮 |
|---|---:|---:|---:|
| `nearest_area`（v3 的实现） | 2.83× | 14.07× | 12.83× |
| `kernel_area` 核散射 + 面积平均 | 2.03× | 11.02× | 4.74× |
| `kernel_point` 取代表点场值 | 退化 | 退化 | 退化 |
| **`kernel_forcew`** ← 选中 | **1.52×** | **1.10×** | **1.25×** |

现在先用**固定物理带宽**（4 mm，跟拟传感 taxel pitch 走，**不跟分辨率走**）的同部件
守恒核散射到冻结表面点，再在格内按 `|f|` 加权池化。`kernel_area` 那一行值得单看：
**它已经在用核了，照样漂 3~11 倍**——核散射是必要条件不是充分条件，池化那一步也得治。

⚠️ **抽屉这一格没通过判据（1.52× 对门槛 1.50×），如实记 FAIL。** 去掉最粗那一档
（256→1024）它是 **1.12×**，而 64 档上抽屉整个把手横杆只落在少数几个 cell 里，
一个格里同时装下好几个互不相干的接触斑块，按 `|f|` 平均会被高 force 的那个拉高。
**那是粗粒化本身的损失，与 P-68 的 1/面积 标度是两回事**，但它仍然是一个真实的
分辨率依赖，**不得靠放宽门槛消掉**（那是 P-11）。S4.5 扫描抽屉时必须把 64 档单列。

**② `mode/prob` 的四档是一个任意阈值的产物（P-69）。** 把 stick/slide 阈值在
1~10 mm/s 之间换，"黏住"占的力比例：抽屉 0.592→0.964（**37.2 pp**）、
旋钮 0.583→0.977（**39.4 pp**）、擦拭 0.1 pp（它一直在滑，不敏感）。
S4 侧一直存着连续量并附敏感度表，**是 S5 这层只导出了切完的标签**。
v4 增加 `mode/slip_speed/{median,lo,hi}`（同一套 split conformal 标定）与闸门第 1c 项；
`mode/prob` 降为诊断字段，`r_mode` 用连续量。

**③ `effect/rigid` 把米和弧度放进同一个 6 维向量（P-70）。** 每个任务恰好只有一路非零：

| 任务 | 平移 p90 | 旋转 p90 | 换算成表面平均位移 |
|---|---:|---:|---:|
| 抽屉 | 0.0458 m | 0 | **0.0458 m** |
| 旋钮 | 0 | 0.9395 rad | **0.0504 m** |
| 擦拭 | 0 | 0 | 0（effect 全在污渍通道，p90 擦净 0.0088 m²） |

直接对 6 维取 L2 就是 D-31 第 2 个洞（量纲失衡）藏在"统一接口"里面。v4 增加
`effect/rigid/metric`（6×6，把 ξ 换算成"物体表面平均移动了多远"）与两路各自的刻度。
换算后抽屉与旋钮从差 **20.5×** 变成差 **1.10×**。

**这三条对 §2 的闸门结论影响很小**（全程同一个 256 档，内部自洽）：抽屉 mechanics
带内率 0.968~0.989 → 0.966~0.981、宽度 10.88 → 10.63。**但 S6 的 `r_mech` / `r_mode` /
`r_effect` 一旦消费旧字段就会继承这三个问题**，所以在 S6 开工之前修。
