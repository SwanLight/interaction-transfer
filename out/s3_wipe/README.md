# S3 · 擦拭 source（主任务）

> ⚠️ **数据集路径已更新**（2026-08-30，S4 收尾）：现行的三份是 `/tmp/s3_drawer_v3` / `/tmp/s3_wipe_v5` / `/tmp/s3_knob_v4`。下文里旧的 `_full` / 无后缀路径是上一轮的版本，**缺 `rel_vel_obj` 与几何/跨实现划分**，不要照着用；擦拭的 `_v5` 比 `_v4` 只多了平面的世界位姿（`source/board_pos_w` / `_quat_w`，P-54 的解法），**两版的验收报告逐字相同**，本文件的数照旧有效。


`plan/01` §0 里擦拭是**主任务**：它是接触主导的，持续接触、有压力、有滑移，
最可能产生正结果。`plan/01` §5.1 允许两种实现，本采集器两种都做：

* **(a) 持工具擦** —— 双板夹住黑板擦，用它的底垫擦；
* **(b) 直擦** —— 不用工具，双板直接用板面擦。

两者产生**同一份记录格式**，因为 `plan/02` §1.1 把擦拭的被操作物体定在
**平面**上：无论中间隔不隔着一块黑板擦，"平面上哪片区域被以什么模式、
什么压力擦过"是同一件事。

**`direct_wipe` 那一档不可省。** `plan/02` §7 第 8 条要求验证
"envelope 与是否使用工具无关"，而那条检查需要真的存在不用工具的示教
才能做——没有它，D-12 的核心主张只能靠嘴说。

## 记什么、不记什么

擦拭的 Object Effect **只有平面上的 dirt 状态变化**（`plan/02` §3.1 经 D-42 修订）。

初版还写了"擦拭接触体相对平面的未来 6D 位姿增量"，那一条**已删除**：
接触体是黑板擦或执行器自己的面，都是 source 侧的东西，写进 effect 等于让
envelope 携带"用什么姿态、沿什么路径移动你的手"——那是动作层面的迁移，
而垫头杆那一格（一个不能抓握的杆子执行同一份 envelope）根本无从执行。
工具位姿只进 `source/tool_pose` 追查字段。

## 夹的是**长侧面**，不是短端面（D-48）

黑板擦本体 90×45×25 mm。两块板夹 ±Y 的两个 **90×25 长侧面**——生活中捏黑板擦
就是捏长边。这不只是像不像的问题：扫掠沿 Y，长侧面的法向也是 Y，
**推力由法向力直接传**；夹 45×25 的短端面时同样的推力只能靠摩擦传，
工具跟不住路径（实测滑脱 13 mm、路径区域内只有 68%，改完是 0.6~0.7 mm / 92.0~92.3%）。

夹持的三个动作有严格先后：**张开 6 mm 落下 → 夹拢 → 再下压**。
直上直下落等于拿板的下边缘楔在工具顶面上，工具会被顶飞；
而先张开落到位再夹，板会一路落到"已经下压"的高度，等夹拢时竖直位置误差
已归零、压力也归零（清除率 0%）。见 P-51。

## 六个策略家族

| 家族 | 做法 | 覆盖 `plan/03` §2.3 的哪一条 |
|---|---|---|
| `tool_center` | 居中夹住黑板擦 | 第 1 条 |
| `tool_offset` | 偏心夹持（沿黑板擦长轴 ±6~10 mm） | 第 2 条 |
| `tool_tilt` | 绕扫掠轴侧倾 3~7°，底垫单边受力更重 | 第 3 条 |
| `tool_heavy_slow` | 高压力、趟数少（走得慢） | 第 4 条 |
| `tool_light_fast` | 低压力、趟数多（走得快） | 第 4 条 |
| `direct_wipe` | **不用工具**，双板直接以板面擦 | 第 6 条 |

"速度"用**蛇形趟数**表达而不是速度倍率：倍率 <1 会让路径根本走不完
（实测清除率卡在 67%），趟数少则每趟走得慢而路径总能走完。

## 控制上的两个关键决定（D-44）

1. **三个轴全部走位置控制**，压力由位置干涉给。Z 走力控时，同一个指令力在
   不同家族上量出来差一个数量级（2.4 N 的指令量到 7.5 N 和 0.67 N）——
   力经"摩擦抓持"传到黑板擦再传到平面，这条链是软的，而力控轴没有位置参考。
2. **"法向力在允许区间内"是逐接触体判的**（`plan/01` §5.3 的"任一接触体"）。
   持工具时接触体只有一个，直擦时是两块板；按总力分摊会让每块板只有 2.5 N，
   低于 3 N 下限，一格都擦不掉——实测直擦清除率因此卡在 26%（见 P-41）。
