# S4 — Oracle Interaction Record

`plan/02` §3 定义的**物体中心交互记录**：effect / region / engage 方向 /
contact mode / mechanics / phase。四份 S3 source 数据集共 **16 640 条 episode**
全部提取完成并通过独立验收。schema 是 **`s4-record-v2`**——
**v1 已作废、读到即报错**（mode 判据换过，两版语义不同，D-52）。

**报告 `out/report.html` 里的 S4 段是给人读的入口**：六个字段各自在回答什么、
怎么看 region 热图、四条验收分别拿什么对拍。本 README 是给接手的人核数用的。

**为什么这份产物不可替代**：S5 的 Functional Envelope、S6 的 E-I 执行器、
S7 的留出任务零样本全部建立在它上面。这一层错了，下游全错，
**而且成功率、接触力、脏帧比例全都看不出来**——D-34 就是那样的教训。
所以本目录里最重要的不是"提取跑通了"，而是下面那张**与 S3 独立对拍**的表。

## 先看这个

| 文件 | 是什么 |
|---|---|
| `extract_<任务>.txt` | 提取侧自报：表面采样、逐家族健康指标、mode 双报、阈值敏感度、接触部位 |
| `verify_<任务>.txt` | **独立验收**：从落盘文件重读，结构/划分/hash/SHA/动力学一致性。条数：抽屉 12 / 旋钮 12 / 擦拭 11 / 探针 block 9，**全部 PASS，0 FAIL**（条数对不上就是有项漏跑） |
| `leak_<任务>.txt` | `plan/02` §7 泄漏检查九条，逐条给状态，末尾给 PASS/FAIL/DEFER **条数** |
| `region_probe_<任务>.txt` | 第 9 条：只看 effect 能不能推出 region |
| `probe/extract_<物体>.txt` | 探针集十个物体各自的提取报告 |

**这四类报告由 `tools/s4_all.sh` 统一驱动，判据是它的退出码**——不是报告里有没有 `PASS`。原因见下面那条警告与 P-55。

数据集本身在服务器 `/tmp/s4_{drawer,wipe,knob,probe}`，按 D-23 不进版本控制。

## 动力学一致性（`plan/02` §8）

| 任务 | 拿什么对拍 | 相关 | 幅值比 |
|---|---|---:|---:|
| **旋钮** | 仿真器记的 `object/axis_torque` | **0.931** | **0.90** |
| 抽屉 | `m·a + c·v` | 0.824 | 2.37 |
| 擦拭 | —— | N/A | N/A |

旋钮这一格是整条提取链最硬的验证：`object/axis_torque` 是关节的广义力，
与"逐接触点的力 × 力臂"是**两条独立路径**，几乎 1:1 对上，说明法向定向
（P-37）、力作用在谁身上、力臂全都没错。

抽屉的幅值比 2.37 是预期的：接触力里含两块板隔着把手互相顶的**内力**和撞击
瞬态（P-22），逐帧幅值本来就不该相等，相关系数才是有意义的那个数。
擦拭平面是 kinematic 刚体，接触力不进入它的运动方程，**如实标 N/A**。

两套都写进记录、报告并排出，不用新判据去掩盖旧判据。

⚠️ **这里的判据换过两次，中间那一版是错的，如实记在 D-49**：
初版用"接触斑块在物体表面上的位移"，它把"平板贴圆柱时接触线随姿态微动而迁移"
误判成滑移，抽屉只给出 35.9% sticking。现在用**两刚体位姿差分**——
它在干净数据（擦拭，板不抖）上与瞬时速度逐帧相关 0.95，且**正是真实装置能测
的量**（面相对物体的位姿，差分即得）。

重判过程中发现两个问题，都记了：
- **P-52**：采集板的角速度在抽屉 96.9%、旋钮 100% 的操作帧顶在 PhysX 的
  100 rad/s 上限，PhysX 报的瞬时相对速度整体虚高（积出来 59 mm 滑移，
  而接触点在物体系里一动没动）。位置量与力不受影响。
- **P-53**：`_pose_slip` 一度把相对速度算在世界系、却拿物体系的法向投影切向
  分量。**零征兆**——逐帧数值、接触部位、动力学一致性、单元测试全部正常，
  只有场景刚体旋转检查抓得到（滑移差 0.17 m/s → 修后 1.0e-05）。

## 第 9 条：region 到底能不能从 effect 推出来（`s4_region_probe.py`）

只看 effect（当前值 + 未来窗口）预测 region 热图，比三个预测器：
`mean`（什么都不看）/ `probe`（只看 effect）/ `family`（作弊，知道策略家族）。
指标是**热图残差的可解释方差**——余弦相似度会饱和（同一任务的热图都压在
同一片区域上，三个预测器差不到 0.02），读不出结论。
每份取 600 条成功 episode，热图池化到 256 点，训练 420 / 留出 180。

| 任务 | probe 可解释方差 | family（家族级参照） | probe / 参照 | 读法 |
|---|---:|---:|---:|---|
| 抽屉 | 0.029 | 0.151 | 19% | effect 基本推不出 region |
| **擦拭** | 0.120 | 0.127 | **95%** | 可解释的那点差异几乎全被 effect 吃掉 |
| **旋钮** | **0.687** | 0.553 | **124%** | effect 相当程度上推得出 region |

⚠️ **这一版的数与本文件上一版（0.050 / 0.114 / 0.344）不一样，以这一版为准。**
上一版来自 P-54 修复**之前**的一次运行；P-54 之后重新提取的记录里，擦拭与探针
物体的接触点位置才是对的。旧数字已作废。

⚠️ **旋钮那一格 124% 说明"作弊上界"这个叫法在这里是错的。** `family` 只知道
**离散的家族标签**，而 effect 是**连续量**——同一家族内部转到哪个角度、盘该往
哪边转，家族标签给不出，effect 给得出，而接触落在销钉的哪一片正是随转角连续
变化的。所以它是**家族级参照**，不是全局上界；旋钮上 effect 携带的 region 信息
**比家族标签还多**。

**两条要正面写进论文，不得掩盖**（`plan/02` §7 第 9 条原文 + Gate G）：

1. **旋钮**：只看"圆盘该怎么转"就能大体预测接触落在销钉的哪一片——
   销钉在盘面上的位置固定、接触位置随转角连续变化，两者本来就是一回事。
   **旋钮基本丧失了检验 region 必要性的能力**（0.687 已经不是"被削弱"的量级），
   在实验一 C0 vs C2 的解读里必须显式排除掉旋钮，否则会把"effect 里本来就有的
   信息"记到 region 头上。
2. **擦拭（主任务）**：绝对量不高（0.120），但它占了家族级参照的 95%——
   这符合直觉：擦拭的 effect 就是"哪片污渍被清掉"，而 region 是"在哪接触"，
   两者近乎同义。**主任务上 region 相对 effect 的增量也需要谨慎声称。**
   `plan/05` §2.5 本来就预期擦拭主要检验 mode 与法向/切向作用，不是 region，
   这条实测与那个预期一致。
3. **抽屉是三个任务里唯一能干净检验 region 的**（0.029，占参照 19%）：
   同一个"把抽屉拉开 20 mm"可以由横杆背面、正面、单指钩等不同接触落点实现，
   effect 相同而 region 不同。**region 的必要性论证要以抽屉为主载体。**

这与 D-14 不冲突，但要分清楚两件事：D-14 说的是**力学可行性**（低摩擦轮缘
在安全力上限内推不动，`rim_only` 实测只转到 0.019 rad），那是 `plan/05`
实验五的反事实；这里说的是**信息量**（region 字段相对 effect 有没有增量）。
前者仍然成立，后者在旋钮上基本不成立。

⚠️ 抽屉与擦拭的 family 参照本身都不高（0.13~0.15），说明热图在**家族之间**的
差异本来就有限。所以这两个任务上这条检查的读法只能是"**至少 effect 推不出它**"，
不能反过来说"region 一定有很强的独立信息"。

⚠️ **抽样必须覆盖所有家族。** 第一版直接取 manifest 前 300 条，旋钮那份
**300 条全是同一个家族**，family 参照因此恒等于 mean，读出来的结论是错的。
现在先打乱再截断，三份分别覆盖 5 / 6 / 4 个家族。

## 传感可观测性（S4.6）：三份都可用（P-54 已修）

`sensing_{drawer,wipe,knob}.txt`。**曾经有一版擦拭的数是废的**——0.5 mm 的面位姿
噪声对应 23 mm 的接触点偏移，根因是接触体位姿（含 env 偏移的世界系）与被操作物体
位姿（当时缺失、只能假定在原点）不在同一个坐标系（P-54）。修好后是 0.69 mm，
与噪声幅值 1:1。

**修复后最有价值的一条**：三个任务的功能接触区尺度差一个数量级，region 的降级
速度就差一个数量级——5 mm 误差下，销钉 Ø20 只剩 0.158，把手 140 mm 还有 0.720，
擦拭区 190×290 mm 有 **0.956**。所以硬件指标是"**≤ 功能特征尺寸的 ~10%**"，
不是一个绝对毫米数。**越是大面积接触的任务，对面位姿越宽容。**

`lever_check.txt` 是那一类 bug 的普查：接触点到接触体原点的力臂现在四份数据
分别是 17.6 / 46.0 / 17.6 / 21.6 mm（修前擦拭 7156 mm、探针方块 9001 mm）。
提取器里现在有一条硬不变量，力臂 > 0.5 m 直接抛异常。

## 重新生成

**一条命令，判据是退出码**（`tools/s4_all.sh`，P-55 的结构性补救）：

```bash
./tools/sync.sh
./tools/run_remote.sh "bash tools/s4_all.sh" s4all        # 只跑验收，约 25 min
./tools/run_remote.sh "bash tools/s4_all.sh --extract" s4all   # 连提取一起重跑
```

它逐项跑 verify / leak / region_probe 三类检查 × 三个数据集，把报告写进
`/tmp/s4_reports/`，**收齐所有退出码**，任一项非零则整体非零；退出码之外还会
grep 一遍 `Traceback` 兜底。跑完把 `/tmp/s4_reports/*.txt` 拷回本目录。

⚠️ **不要再手敲单条命令然后看报告开头。** 那正是 P-55：
`cmd > report.txt` 的退出码没人看的时候，报告开头只证明"脚本启动了"。

提取默认不跑——它是幂等的重活（16 640 条，约 20 min），而验收是每次改完提取器
都要重来的那一半。`is_measurement` 这类只被检查脚本用到的改动**不影响提取输出**，
不需要重采、也不需要重提取。

本机还有三套不依赖 Isaac 的单元测试，改完提取器立刻能验（共 38 条）：
