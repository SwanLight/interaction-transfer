# 03 — Source 多样性、数据集与 Shared Structure Model

## 1. Source 的定位

双板 Source 只负责产生多样、成功、物理有效的示教。它不是最终算法的一部分，也不需要模仿人类骨骼。

仅靠同一个policy的随机噪声不能代表“不同人”。数据集必须同时包含：

- 明确不同的策略家族；
- 每个策略家族内部的自然连续变化。

## 2. Source 策略家族

### 2.1 旋钮

至少包含：

1. 双板夹销钉后绕轴转动；
2. 一块板主推销钉，另一块板稳定；
3. 双板接触轮缘，不使用销钉；
4. 中途松开并regrasp。

### 2.2 抽屉（已实现，五个家族，见 `log/decisions.md` D-37）

1. `pinch_center` 把手中央对称夹持（手指在杆背、拇指在杆前）；
2. `pinch_offset` 偏左/偏右夹持；
3. `asym_primary` 两板非对称，一块承担主要拉力；
4. `hook_both` 双板都在杆背，纯勾不夹——接触拓扑与 1–3 不同；
5. `single_finger` **只用一块板**，另一块全程不参与。

第 5 条不只是多一种打开方式：`02` §7 第 3 条要求"改变 source 板数量后表示维度不变"，那条泄漏检查**需要真的存在只有一个接触体的示教**才能验。

⚠️ **初版的"不同手面姿态"一档已取消**，理由是几何上不成立：平板贴圆柱只有在板面与柱轴平行时才是面接触，绕任何轴一转最近的就变成板的一条棱（实测接触力冲到 75 N、板被压低 23 mm、接触部位 100% 判成把手底面）。手面姿态的多样性改由贴在杆背的**高低差**（±4 mm，对 Ø22 的杆是 ±21° 的接触角变化）和接触体数量提供。倾斜手面这一档留到**擦拭**任务——那里被操作物体是平面，倾斜是成立的。

### 2.3 擦拭

至少包含：

1. 居中抓黑板擦；
2. 偏心抓；
3. 轻微倾斜抓持；
4. 高压力慢速与低压力快速；
5. 不同擦拭方向和路径；
6. **双板不用工具，直接以板面擦拭**（对应 `01` §5.1(b)）。

第 6 条必须有。它是 `02` §7 第 8 条泄漏检查的数据来源——没有它就无法验证 envelope 与"是否使用工具"无关。

### 2.4 预训练物体集（供 E-I 使用）

E-I 需要覆盖交互指令空间，而三个任务的 envelope 只是这个空间里很窄的一片。因此另建一组**只用于产生指令多样性、永不作为任务评估**的物体。

这组数据只进 E-I 的训练，**不进 E-T、不进 Shared Structure Model、不进任何评估**。

#### 2.4.1 先问一个问题：够不够，怎么判？

"够不够"不能靠数物体个数。判据只能从 `04` §5.4 的留出划分倒推——**每个执行器的留出任务需要哪些交互原语，这组物体里必须都有**：

| 执行器 | 训练指令来源 | 留出任务 | 留出任务要求的原语 |
|---|---|---|---|
| Allegro | 预训练集 + 抽屉 + 旋钮 | 擦拭 | 固定面上带法向力持续滑移 |
| **垫头杆** | **仅预训练集** | 擦拭 | 同上（**它只有预训练集**） |
| 平行夹爪 | 预训练集 + 抽屉 | 擦拭 | 同上 |
| **钩杆** | **仅预训练集** | 抽屉 + 旋钮 | 勾住凸出结构**拉**受约束平移件；绕固定轴转动；**曲面上建立接触** |

初版那四个物体（方块 / 立柱 / 滑块 / 斜面垫）有三个洞，任何一个都会让 Gate E 不通过而**无法归因**：

1. **没有"受约束转动"**。立柱是自由刚体，搓转它靠的是摩擦，与"绕固定轴、带阻尼的关节"不是一回事。钩杆的留出任务里有旋钮，而它只训预训练集——若这类动作完全不存在，Gate E 失败只能说明训练分布没覆盖到，说明不了执行器不是任务无关的。
2. **只有"推"没有"拉"**。滑块只能被推。而抽屉是"勾住凸出结构往外拉"。
3. **没有曲面接触**。四个物体的接触面全是平面，而抽屉把手是圆柱。

第三条尤其隐蔽：`02` §3.3 的 engage 方向在平面上是常量，在曲面上随接触位置变化，执行器从没见过后者。

#### 2.4.2 修订后的物体集（六个）

全部参数化 primitive（D-07），由 `src/it/build_assets.py` 生成。

| 物体 | 几何 | 关节 | 策略家族（≥3） | 它负责覆盖的规格轴 |
|---|---|---|---|---|
| 桌面方块 `block` | 60×45×40 mm 自由刚体 | 无 | 平推 / 侧推翻倒 / 按住不动 | effect：自由平移、翻转、**静止**；region：不同面功能不同 |
| 立柱 `column` | Ø56×120 mm 自由刚体 | 无 | 侧推 / 双面搓转 / 推倒 | mechanics：**切向摩擦主导**（与法向主导对照） |
| 滑块导轨 `slider` | 行程 150 mm，阻尼随机，**块上带凸缘** | prismatic | 沿轴推 / **勾凸缘拉** / 压住侧拉 | effect：受约束平移；**拉**这一档（洞 2） |
| 转盘 `dial` | Ø90 圆盘 + 3 均布凸耳，阻尼随机 | revolute | 推凸耳正转 / 反转 / 蹭轮缘 | effect：**受约束转动**（洞 1）；mechanics：绕轴力矩、力臂 |
| 擦板 `wipeboard` | 400×300 固定面，倾角 0/15° | 无（kinematic） | 定压直线扫 / 变压扫 / 往复折线扫 | mode：**持续 sliding**；mechanics：法向力带 + 切向 |
| 凸棱台 `ridge` | 固定台面 + Ø20 横棱 | 无（kinematic） | 贴棱侧推 / 跨棱滑过 / 沿棱滑动 | **曲面接触**（洞 3）；engage 方向随曲率变化 |

后三个是本次新增。固定件用 `kinematic_enabled=True` 而非静态碰撞体（`01` §1 规则 7 / P-17）。

#### 2.4.3 与留出任务的边界——这条必须写进论文

新增的三个物体，每一个都是为了补上某个留出任务所需的原语。这看起来很接近"为留出任务做准备"，所以边界必须说死：

> **预训练集提供的是交互原语（能力），不是任务。**
> 留出任务的**物体、几何、reward、envelope** 一律不得出现在预训练集里。

对照检查：

| | 擦拭任务 | 擦板 `wipeboard` |
|---|---|---|
| 平面尺寸 | 600×500 | 400×300 |
| 倾角 | 水平 | 0 / 15° |
| dirt grid | 有，且是成功判据 | **无** |
| 黑板擦 | 有（实现 a） | **无** |
| envelope | 由 S5 从示教归纳 | 不产生 envelope，只产生 record |

| | 旋钮任务 | 转盘 `dial` |
|---|---|---|
| 半径 | 70 mm | 45 mm |
| 可推结构 | **单个**偏心销钉 | **三个**均布凸耳 |
| 轮缘低摩擦（D-14） | 有，且是 region 可检验性的前提 | **无** |
| 目标角 | 1.0–2.2 rad | 无目标，只求转动 |

**为什么这条边界是对的而不是自欺**：本工作的主张（`00` §5 第 1 条）是"执行器是任务无关的"，即它学的是**自己这个形态能实现哪些交互**，再由上游给的规格驱动。若预训练集里连"绕固定轴转动"这类动作都没有，那么钩杆在旋钮上失败，说明的是训练分布的缺陷，不是主张的对错——`05` §11 的失败解释表会直接失效。反过来，只要留出任务的物体、判据和 envelope 从未出现，"没见过这个任务"就成立。

**这段论证必须在论文里正面写出来，不能藏。** 审稿人一定会问"你的预训练集是不是照着留出任务设计的"，答案是"是，照着留出任务需要的**原语**设计的，但不含留出任务本身"，并附上上面两张对照表。

#### 2.4.4 冻结

物体集与其覆盖论证在 **2026-08-29** 定稿并冻结，**早于任何 E-I 训练**（见 `log/decisions.md` D-39）。这是本条不构成 P-13 的关键：不是看到留出任务失败之后才去补物体。

`05` §3.4 允许在留出任务不通过时扩充这一组（且明令禁止把留出任务加进训练）。**若将来真的扩充，必须新增一条 D-xx 记录扩了什么、为什么、扩之前的结果是多少**，不得静默进行。

## 3. 生成方式

第一轮使用脚本化阶段机保证策略覆盖：

```text
approach → establish contact/grasp → manipulate → release
```

每种策略内部随机化接触位置、板姿态、速度、压力和phase时长。

有余力后训练多个Source RL policy作为补充。不同RL policy需要使用不同策略约束或reward偏好，不能只换随机seed后假设它们一定不同。

## 4. 多样性验收

每个任务的数据集必须同时通过：

- 至少3个策略家族各有足够样本；
- source动作轨迹、接触区域或接触拓扑在家族之间明显不同；
- 所有家族达到相同任务目标；
- 训练一个简单source-strategy分类器时，原始source动作上的准确率应明显高于随机水平；
- 不能只用“视频看起来有点歪”作为多样性证据。

## 5. 数据记录

物理频率由仿真器确定，控制与记录频率50 Hz。每帧保存：

- source板位姿、速度和控制目标，仅用于追查；
- 物体/工具/参照物状态；
- 原始接触点、法向、法向力、摩擦力、相对速度；
- 关节状态和动力学参数；
- Oracle Interaction Record；
- task、strategy、episode、phase和success元数据。

source动作和物理参数必须由训练数据加载器显式排除，不能进入Shared Structure或Executor输入。

## 6. 数据规模

第一轮目标：

| 任务 | 策略家族 | 每家族成功轨迹 | 总量下限 |
|---|---:|---:|---:|
| 旋钮 | ≥4 | ≥250 | ≥1000 |
| 抽屉 | ≥3 | ≥150 | ≥450 |
| 擦拭 | ≥5（含直擦） | ≥250 | ≥1250 |
| 预训练物体集 | 每物体 ≥3 | ≥200 | **≥3600**（6 物体 × 3 家族 × 200） |

失败、近成功和物理不可行样本单独保存，不与成功 shared-structure 标签混合。

## 7. 数据划分

不能只随机划 episode。建立**一个校准集 + 四种测试集**：

| 划分 | 用途 | 是否冻结 |
|---|---|---|
| 训练集 | 训练 | 否 |
| **校准集** | **conformal 阈值标定（`02` §4.1）** | 生成后冻结 |
| 同分布测试 | 未见 episode | 冻结 |
| 未见 source 策略测试 | 留出至少一个策略家族 | 冻结 |
| 未见物理参数测试 | 留出摩擦/阻尼区间 | 冻结 |
| 小幅几何变化测试 | 留出销钉位置、把手位置或黑板擦尺寸 | 冻结 |

校准集是本版本新增，且**必须独立于训练集和所有测试集**——用训练集标定 conformal 阈值会使覆盖率保证失效。

**擦拭任务额外留出**：`01` §5.1 的两种实现中，至少留出一种实现的全部 episode 作为跨实现测试（对应 `02` §7 第 8 条）。

开发集用于调参；确认集一旦生成即冻结，不根据 baseline 结果修改环境。

**划分必须按 episode，不得按帧**（见 `log/pitfalls.md` P-10）。

## 8. Shared Structure 标签构建

第一版使用明确、可检查的统计程序生成 Functional Envelope 标签：

1. 按 phase 和 object progress 对齐同一任务实例的成功轨迹；
2. effect 取成功轨迹共同达到的目标及允许时间范围；
3. region 保存多峰热图或允许区域集合，不取单一平均点；
4. mode 保存各 phase 必须满足的状态；
5. **mechanics 用 pinball loss 回归 τ=0.1/0.9 分位数**得到上下界，不用"均值 ± k·标准差"（接触力分布通常单侧截断，对称假设不成立）；
6. **region 阈值用 conformal prediction 在校准集上标定**，目标：coverage ≥ 90%；
7. 明显异常策略或动力学脏帧不参与标签构建。

这个程序是训练 Shared Structure Model 的监督标签，也是模型失败时的 oracle 上限。

### 8.1 Envelope 的两个数

初版"必须覆盖成功示教但不过度宽泛"没有可操作定义。改为两个可测量的数：

- **coverage**：确认集上，实际接触/受力完全落在 envelope 内的成功示教比例；
- **width**：region 允许集合的面积占物体表面积的比例；mechanics 上下界的相对宽度。

目标函数：**在 coverage ≥ 90% 的约束下最小化 width**。过宽的 envelope 会在 coverage 上通过但在 width 上暴露，无处可藏。两个数都必须在最终报告中出现。

## 9. Shared Structure Model

### 输入

- 一条或少量source示教的Oracle Interaction Record；
- 物体表面点云和法向；
- 当前任务目标和参照物状态。

### 网络

- 表面点云：PointNet，共享MLP 64→128→128，池化为128维；
- 时间序列：两层GRU，hidden 128；
- 融合：两层MLP，256→256；
- 多个显式输出头：effect、region heatmap、mode、mechanics range、phase。

第一版不使用不可解释latent作为唯一输出。

### 训练目标

- 预测Functional Envelope各显式字段；
- 同任务同目标的不同source策略输出应接近；
- 不同任务目标不能塌缩成同一个输出；
- mechanics范围必须覆盖成功示教但不过度宽泛；
- region应允许多峰，不能被平均到物体内部或不可接触位置。

### 通过条件

- 未见 source 策略上的 effect、region、mode 和 mechanics 预测达到预设精度；
- **coverage ≥ 90%**，且 width 不劣于 oracle envelope 的 1.5 倍；
- 使用模型输出而非 oracle 标签时，冻结 executor 的成功率下降不超过 10 个百分点；
- 从模型输出预测 source 策略身份的准确率显著低于从原始 source 动作预测的准确率；
- **擦拭上，从两种实现（持工具 / 直擦）分别提取的 envelope 可互换使用**，互换后成功率下降不超过 10 个百分点。

## 10. 防止循环论证

- Shared Structure Model不能用target executor的动作作为输入；
- Functional Envelope不能根据某个target失败后事后改写；
- target可行性适配必须单独报告，不能混入shared structure标签；
- 同一确认集只能评估，不能继续训练或调任务参数。
