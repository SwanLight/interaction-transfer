# 03 — Source 多样性、数据集与 Shared Structure Model

## 1. Source 的定位

双板 Source 只负责产生多样、成功、物理有效的示教。它不是最终算法的一部分，也不需要模仿人类骨骼。

仅靠同一个policy的随机噪声不能代表“不同人”。数据集必须同时包含：

- 明确不同的策略家族；
- 每个策略家族内部的自然连续变化。

## 2. Source 策略家族

### 2.1 旋钮（✅ 已完成，五个家族，见 `log/decisions.md` D-46）

1. `pin_pinch` 双板夹销钉（一块推、一块留缝跟随）绕轴转动；
2. `pin_push_single` 一块板主推销钉，另一块全程不参与；
3. `pin_push_dual` 两块板沿销钉**上下错开**同侧推，分担载荷；
4. `pin_regrasp` 中途松开并 regrasp；
5. `rim_only` 双板接触轮缘，不使用销钉。

**销钉是竖直插在圆盘面上的拨杆**（Ø20 从盘面伸出 48 mm，偏心 52 mm），
不是灶台旋钮那种握住拧的东西。所以推力的方向**必须随圆盘一起转**：
控制器把参考系挂在**销钉当前的实际角度**上，力控方向取该处的切向，
每个控制步重算。把参考系挂在"领先角"上时，板会跑到销钉的斜前方，
接触法向最多偏离切向 42°，力大半变成顶向圆心的无用功（P-42）。

⚠️ **第 5 条在 D-14 之后不是一个"正常策略"，而是一个预期失败的对照。**
初版把它列为普通家族，那是加低摩擦轮缘之前写的。实测在**压足 19.5 N**
（安全上限 25 N 之内）的条件下只转到 **0.019 rad**，而销钉家族转到
2.31~2.81 rad：

    τ_rim = μ·F·R = 0.10 × 19.5 × 0.070 = 0.137 N·m
    τ_need = 阻尼 × ω = 0.28 × 1.5      = 0.420 N·m

这是 D-14 的**操作级**证据（S1 只做了静态标定），也是 `05` 实验五那条反事实
镜头的数据来源。它的 episode 判为失败、进 `failed` 桶。

### 2.2 抽屉（已实现，五个家族，见 `log/decisions.md` D-37）

1. `pinch_center` 把手中央对称夹持（手指在杆背、拇指在杆前）；
2. `pinch_offset` 偏左/偏右夹持；
3. `asym_primary` 两板非对称，一块承担主要拉力；
4. `hook_both` 双板都在杆背，纯勾不夹——接触拓扑与 1–3 不同；
5. `single_finger` **只用一块板**，另一块全程不参与。

第 5 条不只是多一种打开方式：`02` §7 第 3 条要求"改变 source 板数量后表示维度不变"，那条泄漏检查**需要真的存在只有一个接触体的示教**才能验。

⚠️ **初版的"不同手面姿态"一档已取消**，理由是几何上不成立：平板贴圆柱只有在板面与柱轴平行时才是面接触，绕任何轴一转最近的就变成板的一条棱（实测接触力冲到 75 N、板被压低 23 mm、接触部位 100% 判成把手底面）。手面姿态的多样性改由贴在杆背的**高低差**（±4 mm，对 Ø22 的杆是 ±21° 的接触角变化）和接触体数量提供。倾斜手面这一档留到**擦拭**任务——那里被操作物体是平面，倾斜是成立的。

### 2.3 擦拭（✅ 已完成，六个家族，D-44 / D-48）

**两块板夹黑板擦的两个 90×25 长侧面**（本体 90×45×25），不是 45×25 的短端面——
生活中捏黑板擦就是捏长边，而且扫掠沿 Y、长侧面的法向也是 Y，推力由**法向力
直接传**。夹短端面时只能靠摩擦传，工具跟不住路径（实测滑脱 13 mm、
路径区域内 68%；改完 0.6 mm / 92.5%，成功率 82.7% → 96.6%）。见 D-48。

至少包含：

1. 居中抓黑板擦；
2. 偏心抓；
3. 轻微倾斜抓持；
4. 高压力慢速与低压力快速；
5. 不同擦拭方向和路径；
6. **双板不用工具，直接以板面擦拭**（对应 `01` §5.1(b)）。

第 6 条必须有。它是 `02` §7 第 8 条泄漏检查的数据来源——没有它就无法验证 envelope 与"是否使用工具"无关。

### 2.4 交互原语库与探针物体集（供 E-I 使用）

E-I 需要覆盖**交互指令空间**，而三个任务的 envelope 只是这个空间里很窄的一片。
因此另建一组**只用于产生指令多样性、永不作为任务评估**的物体。

这组数据只进 E-I 的训练，**不进 E-T、不进 Shared Structure Model、不进任何评估**。

#### 2.4.1 先说一个被否掉的做法，以及它错在哪

初版（和 2026-08-29 上午的第一次修订）是这样选物体的：**看留出任务需要什么，
就补一个能产生那种交互的物体**。擦拭需要"带法向力持续滑移"，就加一块可以在
上面滑的板；旋钮需要"绕固定轴转动"，就加一个转盘。

**这个做法是错的**，理由不是它覆盖不够，而是它**把留出任务的答案提前教了进去**，
且从外面看无法与"作弊"区分：

> 如果物体集是照着留出任务反推出来的，那么执行器在"摸索能力"阶段
> 学到的就是留出任务本身，只是换了个物体标签。
> `plan/00` §5 第 1 条声称的"任务无关"就退化成了"同一件事做两遍"。

**修正后的方法**：物体集必须从一套**独立于本项目三个任务**的交互分类框架推出来，
判据是是否覆盖预先声明的轴值，而不是是否覆盖留出任务。注意：下面五轴是本项目对
多条文献与自身表示的**工程综合**，不是某篇文献给出的完备分类学；覆盖每个轴的边缘
取值也不等于张满它们的笛卡尔积。留出任务被覆盖到只能是经验分布覆盖的结果，不能
由“每格打勾”推出。

#### 2.4.2 分类学从哪来

三条已有文献线索，加上本项目表示自身的结构：

| 来源 | 提供什么 |
|---|---|
| [Huang, *Robotic Manipulation Primitives*](https://publications.ri.cmu.edu/storage/publications/2021/05/main.pdf)（CMU 博士论文 2021） | **用接触模式枚举原语**：刚体接触点的相对运动只能是 separating / sticking / sliding，给定接触模型后，活跃的接触模式集合决定运动方程。这与 `02` §3.4 记录的字段**逐字对应** |
| [Bullock, Ma & Dollar 2013](https://www.eng.yale.edu/grablab/pubs/bullock_icorr2011.pdf)，*IEEE T-Haptics* 6(2) | 手中心分类：5 个二值描述子（是否接触 / 是否力封闭 / 是否运动 / 是否手内运动 / 接触处是否有相对运动）→ 15 个互斥类 |
| Lynch & Mason 的非抓握操作谱系（[stable pushing 1996](https://www.ri.cmu.edu/pub_files/pub2/lynch_kevin_1996_2/lynch_kevin_1996_2.pdf)、toppling 1999、Mason 1999 综述；pivoting 溯源 Aiyama 1993） | 非抓握原语的既有命名：推、撬翻、滑、滚、戳 |
| `plan/02` §3 本身 | 指令由 effect / region / engage 方向 / mode / mechanics / phase 组成，分类学必须建在这些字段上，否则覆盖了也没用 |

**本轮的范围限制**（与 `00` §4 第 6 条一致，必须先写明，否则"张满"没有意义）：
刚体、准静态、单个被操作物体、**至多两个接触面**。
因此 Lynch 的动态原语（抛、击、接、杂耍）**不在范围内**，不算缺口。

#### 2.4.3 五个轴

| 轴 | 取值 | 依据 |
|---|---|---|
| **S 接触结构** | S1 单面 / S2 双面同侧 / S3 双面对置（力封闭） | Bullock 的 contact、prehensile 两个描述子 |
| **M 接触模式** | M1 持续 sticking / M2 持续 sliding / M3 stick→slip 过渡 / M4 通断循环 | Huang 的接触模式枚举；`02` §3.4 |
| **F 力学通道** | F1 法向载荷主导 / F2 切向摩擦主导 / F3 力矩（力臂）主导 | `02` §3.5 的 object-frame traction 与其积分 wrench；task-relevant generalized force 只作评估投影 |
| **E 物体自由度与 effect** | E1 自由平移 / E2 自由转动 / E3 受约束平移 / E4 受约束转动 / **E5 物体不动**（effect 在接触或表面状态上） | `02` §3.1 |
| **G 接触面几何** | G1 平面 / G2 凸曲面 / G3 棱与角 | engage 方向在曲面上随位置变（`02` §3.3） |

**E5 必须单列**：`02` §1.1 已经规定擦拭的被操作物体是**平面**，而平面全程不动——
"物体不动、效果体现在接触本身"是一个独立的 effect 类别，它的存在与擦拭任务无关，
只与"物体可以被固定"这件事有关。

#### 2.4.5 探针物体集（十个），以及"冗余"这条硬规则

> **硬规则：每条原语必须由至少两个几何结构不同的物体提供。**

这条是上一节那个错误的直接解药。只要满足它，"你是照着任务 X 设计物体 Y 的"
这句指控就失去力量——把 Y 删掉，那一格仍然被别的物体覆盖着。

| `roller` 卧柱 | Ø60×140 圆柱**横躺** | 无 | P7 P12 |

冗余核对（**实测**，10740 条 episode / 9250 成功，`out/s3_probe/coverage.txt`）：

```
OK push          232 / 2               OK hook_pull    407 / 2
OK slide_push    251 / 2               OK twist        263 / 2
OK rub           420 / 2               OK pinch_hold   414 / 2
OK shear         624 / 3               OK pinch_move   414 / 2

OK pivot         278 / 2               OK roll         588 / 2

                                       原语覆盖与每原语双物体：15 / 15
```

**五格是怎么补上的**（此前只有 10/15，见 `log/decisions.md` D-43）：

* **P7 roll 从 0 补到 399 / 2 物体**。原因不是新的物理改动，而是
  **`ball` 从来没有被采集过**——它在采集器里早有定义，但物体集只列了九个，
  于是 roll 那一格只有卧柱在扛，而自由卧柱的滚动 210 条全失败。
  把球采进来之后 210/210 全通过，卧柱在角阻尼+线阻尼（滚阻代用）下 189/810。
  球面与卧柱是两种不同的曲面几何，冗余成立。
* **P8 twist 增加 `ball`**。两块板对置压住球、切向反向搓 -> 绕竖直轴转
  （71/210）。立柱是竖直柱面、球是球面，几何确实不同。
* **P3 slide_push 增加 `column`**：与 `push` 用同一个低位点，把它推到打滑
  （45/205）。稳定推移与推到打滑本就是同一处接触的两种力学状态。
* **P13 pinch_hold / P14 pinch_move 增加 `slider` 的挡片侧面**：
  挡片 10 mm 厚、34 mm 高、比块本身宽 10 mm，两侧都够得到；捏住它再沿导轨推
  就是"力封闭对捏 + 受约束平移"（各 210/210）。
  ⚠️ 挡片的 ±X 面**不能**拿来做 pinch_move——那两个面的法向就是导轨方向，
  捏住之后要移动的方向与法向重合，几何上不成立。

**试过而不成立的，也记下来**：自由卧柱的**两个端面对捏**不可行——板还没夹上来
圆柱就先滚跑了（1020 条里 pinch_hold 只成功 2 条、pinch_move 与 twist 各 0 条，
物体位移 215~1399 mm）。位点留在 `s3_source_probe.py` 的表里并注明，
是为了让下一个人不必重试一遍。

**物体是按"最简单地实现某一格"选的，不是按"像哪个任务"选的。** 例如 E5
（物体不动）这一格由 `block`（压住不动时顶面就是静止表面）、`ridge`、`slab`
三个几何完全不同的物体共同提供——其中最像擦拭平面的 `slab` 只是三分之一。

#### 2.4.6 边界与**可测量的**辩护

边界仍然是那条：

> 预训练集提供**交互原语**。留出任务的**物体、几何、reward、envelope、成功判据**
> 一律不出现。

但"边界够不够远"不能靠嘴说。**`05` 实验二必须同时报告一个数**：

> **指令距离**：对每条留出任务的交互规格，计算它到**训练指令分布中最近一条**的
> 距离（在归一化的规格特征空间里：effect 方向与幅值、region 质心与展布、
> mode 直方图、mechanics 方向与幅值），并报告**零样本成功率随该距离的变化**。

这把"这算不算作弊"从争论变成一条曲线。如果执行器在**远离**任何训练指令的
留出规格上仍然成功，主张就成立，且与物体集怎么选无关。若成功率只集中在
距离很小的那一端，那就是如实报告"覆盖到了才会做"，主张相应减弱。

**这一段必须原样写进论文。** 审稿人一定会问"预训练集是不是照着留出任务设计的"，
回答是四段：(1) 五轴与原语在 E-I 训练前冻结，(2) 每个边缘轴值有覆盖且每条原语
有 ≥2 个不同物体，(3) 明确不声称笛卡尔积完备，(4) 用指令距离与局部训练密度曲线
量化实际外推距离。

除最近邻距离外，必须同时报告：

- 每个留出 candidate 的 kNN 半径/局部训练密度，防止“最近一条远但周围仍很密”或
  “最近一条近但只是孤点”被同一个数掩盖；
- 五轴的**成对组合覆盖矩阵**，明确哪些组合从未训练；
- leave-one-primitive 与 leave-one-object 评估。它们不是主 Gate E 的替代，而是判断
  E-I 学到组合规律还是只记住 15 个原语标签。

#### 2.4.7 冻结

分类学、物体集与冗余核对在 **2026-08-29** 定稿并冻结，**早于任何 E-I 训练**
（`log/decisions.md` D-41）。这是本条不构成 P-13 的前提：不是看到留出任务失败
之后才去补物体。

`05` §3.4 允许在留出任务不通过时扩充这一组。**若将来真的扩充，必须新增 D-xx
记录扩了什么、为什么、扩之前的结果是多少，并重新做一次张满检查与冗余核对**，
不得静默进行。

## 3. 生成方式

第一轮使用脚本化阶段机保证策略覆盖：

```text
approach → establish contact/grasp → manipulate → release
```

每种策略内部随机化接触位置、板姿态、速度、压力和phase时长。

有余力后训练多个Source RL policy作为补充。不同RL policy需要使用不同策略约束或reward偏好，不能只换随机seed后假设它们一定不同。

## 4. 多样性验收

每个任务的数据集必须同时通过：

- 至少3个策略家族各有足够样本；
- source动作轨迹、接触区域或接触拓扑在家族之间明显不同；
- 所有家族达到相同任务目标；
- 训练一个简单source-strategy分类器时，原始source动作上的准确率应明显高于随机水平；
- 不能只用“视频看起来有点歪”作为多样性证据。

## 5. 数据记录

物理频率由仿真器确定，控制与记录频率50 Hz。每帧保存：

- source板位姿、速度和控制目标，仅用于追查；
- 物体/工具/参照物状态；
- 原始接触点、法向、法向力、摩擦力、相对速度；
- 关节状态和动力学参数；
- Oracle Interaction Record；
- task、strategy、episode、phase和success元数据。

source动作和物理参数必须由训练数据加载器显式排除，不能进入Shared Structure或Executor输入。

## 6. 数据规模

第一轮目标：

| 任务 | 策略家族 | 每家族成功轨迹 | 总量下限 |
|---|---:|---:|---:|
| 旋钮 | ≥4 | ≥250 | ≥1000 |
| 抽屉 | ≥3 | ≥150 | ≥450 |
| 擦拭 | ≥5（含直擦） | ≥250 | ≥1250 |
| 探针物体集 | 每物体 ≥2 原语 | ≥200 | **≥7000**（35 个物体×原语组合 × 200） |

失败、近成功和物理不可行样本单独保存，不与成功 shared-structure 标签混合。

## 7. 数据划分

不能只随机划 episode。建立**一个校准集 + 四种测试集**：

| 划分 | 用途 | 是否冻结 |
|---|---|---|
| 训练集 | 训练 | 否 |
| **校准集** | **conformal 阈值标定（`02` §4.1）** | 生成后冻结 |
| 同分布测试 | 未见 episode | 冻结 |
| 未见 source 策略测试 | 留出至少一个策略家族 | 冻结 |
| 未见物理参数测试 | 留出摩擦/阻尼区间 | 冻结 |
| 小幅几何变化测试 | 留出销钉位置、把手位置或黑板擦尺寸 | 冻结 |

校准集是本版本新增，且**必须独立于训练集和所有测试集**——用训练集标定 conformal 阈值会使覆盖率保证失效。

**擦拭任务额外留出**：`01` §5.1 的两种实现中，至少留出一种实现的全部 episode 作为跨实现测试（对应 `02` §7 第 8 条）。

开发集用于调参；确认集一旦生成即冻结，不根据 baseline 结果修改环境。

**划分必须按 episode，不得按帧**（见 `log/pitfalls.md` P-10）。

## 8. Shared Structure 标签构建

第一版使用明确、可检查的统计程序生成 Functional Envelope 标签：

1. **按 phase 分段对齐**，每段的命令格数按该段的**交互活动量占比**分配（每个有帧的段
   保底 2 格），段内也按累计活动量分格。活动量 = 接触冲量率 + effect 变化率，两路各自
   在 episode 内归一化后相加，不含任务分支（D-65）。
   ⚠️ **不要只按 `progress` 分格**：它是任务完成度，接近段恒为 0、到达目标后恒为 1，
   实测会让抽屉 83.9%、旋钮 73.3% 的帧挤进 2 个格，而所有校验照常通过（P-58）；
2. 每条 episode 在每个命令格内先汇总，再跨 episode 等权聚合；
3. effect 保存中位数、10/90 分位数与 future-window support count；
4. region 保存法向力加权表面分布，mode 保存逐表面点概率，engage 保存平均方向
   **与集中度**（各 episode 单位方向的合矢量长度，∈[0,1]，是方向多峰性的直接度量）；
5. 先按物体表面 cell 聚合 object-frame traction 与 local moment density；
   task-relevant generalized force 只保留为诊断投影，不进 E-I contract；
6. **同一个 cell 上的 engage / mode / traction / moment density 必须来自同一组 episode
   与同一批帧**——一律只用该 cell 实际有接触的那些（D-66）。同时落盘
   `region/support`（几条 episode 碰过）与 `region/duty`（碰过的人里多大比例的帧在接触）。
   ⚠️ 混用 NaN 与 0 两套"没碰过"的表示，会让过半的 cell 同时被要求"接触"和"零力"，
   而每个字段单独看都正常（P-59）；
7. 同一个命令格的全部字段作为一条 command 传递，不从边缘区间任意拼接新样本；
8. 第一版分位数是描述性统计；CQR、聚类或其他模型只有在冻结数据诊断显示需要时再加；
9. 在独立测试划分报告 episode coverage、region force-mass coverage 和 width；
10. 明显异常策略或动力学脏帧不参与成功标签构建；失败/near-success 单独保存。

这个程序是训练 Shared Structure Model 的监督标签，也是模型失败时的 oracle 上限。

### 8.0 守恒性只在聚合前成立

per-cell traction + local moment density 在**单条 episode** 上可积回 object-frame
6D wrench；跨 episode 取中位数/分位数之后**不再守恒**（中位数是非线性的）。这是任何
统计聚合的固有性质，不是缺陷，但产物文档不得写成"积分恢复 6D wrench"。

同样地，**"cell 内局部力矩 + `cross(代表点, F)` 等于对接触点直接求力矩"是代数恒等式**，
拿它对拍只会得到浮点精度级的数，不构成验证（P-60）。能失败的检查是：被
`on_surface`/`weight > 0` 滤掉的接触占了多少力，以及由此与 S4 独立记的
`mech/wrench_obj` 差多少。

### 8.1 Envelope 的两个数

初版"必须覆盖成功示教但不过度宽泛"没有可操作定义。改为两个可测量的数：

- **coverage**：确认集上，各物理字段落入统计带的成功 episode 比例；region
  子指标为至少 95% 法向力加权接触质量落入允许集合的 episode 比例；
- **width**：region 允许集合的面积占物体表面积的比例；mechanics 上下界的相对宽度。

目标函数：**在 coverage ≥ 90% 的约束下最小化 width**。过宽的 envelope 会在 coverage 上通过但在 width 上暴露，无处可藏。两个数都必须在最终报告中出现。

**允许集合怎么定**：每个命令格上，按 region mass 降序累计到 95% 的**最小 cell 集合**
（超水平集）。取超水平集而不是"mass > 某阈值"，是因为给定要覆盖的质量，超水平集的
面积最小——只有这样 width 这个数才真的有"在 coverage 约束下最小化"的含义。

**mechanics 的带内率只报数、不设门槛。** 10/90 分位数是描述性统计，不是 conformal
guarantee（D-59/D-63）。要给保证得先在冻结校准集上做 CQR，那是另一步。
逐点带内率与 episode 级同时带内率必须**并排报**：前者高而后者低，正说明需要
functional/simultaneous 的构造而不是逐点分位数。

**必须另报的子群 coverage**：按 strategy family 分开。envelope 若被某一族主导，
整体 coverage 可以很好看而其余族被系统性排除——那才是 `02` §7 第 4 条泄漏的实质。
落地工具是 `tools/s5_eval_envelope.py`，八项检查逐项收退出码（P-55）。

## 9. Shared Structure Model

### 输入（2026-08-30 修订）

- **一组** source 示教的 Oracle Interaction Record（**不是一条**）；
- 物体表面点云和法向；
- 当前任务目标和参照物状态。

⚠️ **"输入一条示教"是原文的一个逻辑漏洞，已改。** Functional Envelope 是
"**还允许哪些别的成功做法**"的集合，而一条示教在原理上给不出这个信息：
只看到把手中央对称夹持，无从知道偏心夹、双指纯勾、单指拉也都成立。
要从多条里归纳共享结构，模型就必须**同时看到多条**。

### 网络（2026-08-30 修订）

- 表面点云：PointNet，共享 MLP 64→128→128，池化为 128 维；
- **示教集合：置换不变的 set encoder**（逐条编码后做对称池化），
  **不是把某一条喂进 GRU**。示教之间没有顺序，用 GRU 编码集合等于凭空引入
  一个顺序，而且天然只能吃一条；
- 单条示教内部的时间序列：两层 GRU，hidden 128；
- 融合：两层 MLP，256→256；
- 多个显式输出头：effect、region heatmap、mode、task-agnostic traction range、
  command time index。是否需要混合头或能量模型由第一版统计 artifact 的多峰诊断决定，
  当前不预设。

第一版不使用不可解释 latent 作为唯一输出。

### ⚠️ 必须有的对照：goal + geometry only 基线

本轮只有三个任务。模型完全可以**无视示教**，只凭"任务目标 + 物体几何"记住
"抽屉对应这份 envelope、旋钮对应那份"——那样即使未见策略测试通过，
也**证明不了它从不同示教里发现了共享结构**。

所以必须并排跑一个**只看目标与几何、不看任何示教**的基线：

- 若基线 ≈ 完整模型 → 模型没有在用示教，"shared structure"这个说法不成立，
  如实报告；
- 只有完整模型**显著优于**基线，才谈得上它归纳了示教间的共享结构。

这条与 `02` §7 第 9 条（region 可推导性探针）是同一种思路：**先证明这件事
不是从别处平凡地推出来的**，再谈它有没有价值。

### 顺序（2026-08-30 修订）

**第一版先用 §8 的统计程序产出 oracle envelope，把"多条示教 → 共享约束集合"
这条链跑通并驱动 Executor；神经网络模型放到那之后。** 理由是失败可归因：
oracle envelope 驱动不了 Executor 时，问题在表示或执行器；先上网络的话，
分不清是"模型没学好"还是"表示本身不够"。

### 训练目标

- 预测Functional Envelope各显式字段；
- 同任务同目标的不同source策略输出应接近；
- 不同任务目标不能塌缩成同一个输出；
- task-agnostic traction 范围必须覆盖成功示教但不过度宽泛；
- region应允许多峰，不能被平均到物体内部或不可接触位置。

### 通过条件

- 未见 source 策略上的 effect、region、mode 和 mechanics 预测达到预设精度；
- **coverage ≥ 90%**，且 width 不劣于 oracle envelope 的 1.5 倍；
- 使用模型输出而非 oracle 标签时，冻结 executor 的成功率下降不超过 10 个百分点；
- 从模型输出预测 source 策略身份的准确率显著低于从原始 source 动作预测的准确率；
- **擦拭上，从两种实现（持工具 / 直擦）分别提取的 envelope 可互换使用**，互换后成功率下降不超过 10 个百分点。

## 10. 防止循环论证

- Shared Structure Model不能用target executor的动作作为输入；
- Functional Envelope不能根据某个target失败后事后改写；
- target可行性适配必须单独报告，不能混入shared structure标签；
- 同一确认集只能评估，不能继续训练或调任务参数。
