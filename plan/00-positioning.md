# 00 — 定位、相关工作与可声称的边界

本文件回答"这个工作相对已有工作到底新在哪"，并为 `05` 的对照条件提供依据。开工前必读，写论文前重读。

## 1. 一句话定位

> 我们研究一种**物体中心的功能交互接口**：从同任务、多采集者示教中形成 interaction，
> 再由每种 embodiment 各自训练的 executor 解码为自己的 action。实验检验它对跨形态
> 执行是否足够、相对几何 intent 是否有物理信息增量、以及对 source 策略有多大不变性。

三个性质缺一不可。只证充分性 = 重复已有工作；只证最小性 = 消融报告；只证不变性 = 表示学习练习。

## 2. 最近的三个工作，必须正面处理

### 2.1 KITE（arXiv:2606.22113，Cornell，2026-06）

**这是最接近的相邻架构，必须作为主要对照，而不是笼统归为 related work。**
contact-based interaction intent（3D 接触位置 + engage 方向）→ 置换不变 Transformer
编码为 latent → 每 embodiment 一个 action decoder。五种 embodiment，三个任务，
真机 7–8/10。它与本项目共享“交互接口隔开任务意图与本体动作”的骨架，但 decoder
的训练方式、物理反馈、命令语义与留出任务检验均不同，不能写成“完全同一个系统”。

截至本文件撰写时**未开源**（项目页 kite-manip.github.io 的 code 图标是纯文本 "Code soon"）。已去信询问，不把计划建立在拿到代码上。

它的四条 limitation 就是本工作的四个差异点：

| KITE 的洞 | 本工作 | 对应实验 |
|---|---|---|
| intent 纯几何：只有位置+方向，无力、无接触模式 | mechanics 范围 + stick/slide | `05` 实验一，C2→C4 |
| decoder 从 URDF 前向运动学采样训练，**全程无物理** | 物理仿真 + RL 学形态能力 | `05` 实验二 |
| 接触由 MANO + 物体几何**几何推断**，非测量 | 触觉直接测（本轮仿真中为 oracle，Phase II 起为传感） | 本轮不声称，见 §4 |
| "closest-feasible-contact 是局部启发式"，位姿偏移 30cm 掉到 37% | 用各形态的物理交互训练与闭环反馈检验更大偏移；额外选择器只作可选消融 | `04` §5.3、`05` 实验四 |

**对照方式**：不复刻 KITE 系统，而在本框架内加一个信息条件 C2（接触位置 + engage 方向，无 mode 无 mechanics）。论文中表述为 "KITE-style geometric contact intent, reimplemented within our framework"，不表述为 "KITE"。理由：KITE 的 decoder 无物理、其三个任务均非摩擦主导，原样搬到擦拭任务上失败属于 handicapped baseline，那样的比较站不住。若后续拿到代码，补真·KITE 对比进附录。

### 2.2 ART-Glove（arXiv:2606.16370，2026）

16 个**刚性功能面**覆盖手指+拇指+掌，22 个解剖对齐关节，2048 taxel @120 Hz，明确主张"用刚性功能面而非骨架表示手"。

**后果：PPT slide 7 的 "No need for human hand poses / skeleton, just focus on interaction surfaces" 不能再作为卖点。** 这句话已经被说过了。

仍存在的差异：ART-Glove 靠关节编码器 + 连杆恢复面位姿，本质是简化外骨骼；本方案的面无运动链，位姿直接测量/由触觉配准恢复。但这是工程路线差异，不是概念新颖性。

**重新定位**：硬件的卖点不是"不采骨架"，而是"**规格是物体系的，所以传感指标也是物体系的**"——见 `07` §3。这条是别人没有的，因为别人不从表示反推硬件指标。

### 2.3 CHORD（arXiv:2607.00033）

用 object-centric **contact wrench space** 作为接触引导，在 1,831 个评估任务上报告
82.12% 平均成功率。CHORD 并不要求复制一条实测的 exact 6D wrench：它从接触位置、
法向与摩擦锥构造 primitive wrench，比较人/机器人 wrench-space 的 support function，
并带相对容差；论文还明确说明这不是精确的多接触净 wrench polytope。

**因此不能再把 C4（范围）vs C5（精确 source realization）写成“相对 CHORD 的差异点”。**
该对照仍然有价值：它检验本项目自己的最小性——是否需要复制 source 的具体受力实现。
相对 CHORD 真正要检验的差异是：多成功示教得到的时序 interaction、显式
region/mode/local surface wrench，以及由不同形态 executor 实际闭环解码的结果。

### 2.4 Transferring Contact, Not Just Motion（arXiv:2606.15516，2026）

**这条是 2026-08-30 审计时补上的，此前漏了。** 它不是“接触中心抓取”：方法保留
共享的 15-D MANO pose latent，并把每种手的 effort 经系统辨识标定成关节力矩、
指尖力与 load descriptor，再用统一 force-position 接口训练接触感知策略；其原语还被
复用于运输、交接等长程流水线。

**与本工作的差异，必须写清楚**：它的学习核心仍是共享手姿运动 latent + 标定后的
跨手载荷接口，主要学习对象是柔顺抓取/持物原语；本项目不传手姿 latent，而要从多种
成功策略得到物体表面的**时序 interaction**，并由各形态自己的 E-I 执行持续接触
操作。它已经证明“标定后的接触/力反馈可帮助跨手迁移”，这句话不能再
作为本项目的新颖点。

### 2.5 模态消融的既有结论（arXiv:2512.01358）

该工作在 **G1 的单个 Pick Apple to Bowl 任务**上分别报告：零样本 0%、标准微调
48%、独立接触编码器 74%、深度 82%、接触信号并入 state 94%。74/82/94 是并列配置，
不是依次叠加的增长链；GR1 的三任务平均是 51%→63%。两条结论约束本工作的措辞：

1. 在该 G1 任务和这些配置中，显式接触/力输入的收益大于深度；只能把它作为
   “接触模态可能很重要”的先验，不能外推成所有接触任务的普适排序；
2. 模态收益随 embodiment/任务变化，所以 `plan/07` 的传感指标必须按任务几何和
   执行器形态分别陈述，不得写成一个全局数字。

### 2.6 OmniContact（arXiv:2606.26201）

OmniContact 用“未来关键身体目标 + 四肢二值接触状态”的 contact flow 驱动统一的
低层 CF-Track，并用高层 CF-Gen 串联长程 humanoid loco-manipulation；其消融中显式
contact 把 `[torso, end-effector]` 基线从 11.5% 提到 98.7%。这与本项目的“共享交互
接口 + 统一低层执行器”高度相关，不能只列一行带过。

边界也明确：contact flow 仍包含 embodiment-side body targets，接触只有 binary，
高层是手工 phase template；本项目要检验的是物体中心、无 body target、带 mode 与
surface wrench 的 interaction，及各形态独立训练的 decoder。若这些差异没有实验增量，
不能只靠命名宣称新颖。

## 3. 其余需要引用但不构成威胁的工作

- **HACMan**（2305.03942）：非抓握操作中，随机化接触位置显著掉点 → 支持"region 有信息量"，但只在非抓握、单一形态上。
- **Where to Touch, How to Contact**（2601.10930）：contact intention（接触位置 + 物体子目标位姿）→ contact-implicit MPC。去掉子目标预测从 100% 掉到 20.6%。**这是 effect 侧必要性的强证据**，与本工作互补而非竞争（它不做跨形态）。
- **CordViP**（2502.08449）：去掉接触预训练在 Flip-Cup 上显著掉点。
- **FoAR**（2411.15753）/ **ForceFlow**（2605.11048）：力反馈的必要性**因任务而异**——ForceFlow 报告单轴压力调节任务上力反馈单独就够（80–90%）。**这条要求本工作的充分性声称按任务几何类别陈述，不得全局化。**
- **Tac2Pose**（2204.11701）：触觉→物体位姿估计。本工作 `07` §3 的"触觉反向精化面位姿"直接借用这条思路。

## 4. 本轮明确不声称什么

沿用并扩充 `README` §2：

1. 不证明真实人类传感数据能恢复这些变量（Phase II/III，本轮不做）；
2. 不证明真实触觉或 RGB-D 精度已足够；
3. 不证明上游 interaction model 能泛化到新任务/新物体——**这是 VLA 规模的数据问题，本轮不碰**；
4. 不证明一个网络零样本控制**从未训练过的新形态**（本轮每个形态各训一个执行器）；
5. 不把浮动底座实验声称成完整机械臂泛化；
6. 不声称本表示覆盖所有 manipulation（尤其：动态、非准静态、多物体长程）。

## 5. 本轮**要**声称什么

按系统逻辑排序，第 1–3 条是核心验证，第 4 条是 executor 的更强泛化测试，第 6 条
直接对应原始装置路线，
但本轮目前只做到仿真观测模型，不能把它包装成已完成的硬件新颖性：

1. **同一份未改写的 interaction，可被至少三种形态明显不同的执行器实现**，且其动作、接触拓扑、能量分布明显不同。（`05` 实验三）
2. **功能 interaction 在接触主导任务上优于几何接触意图（C2）和纯结果（C0）**，且优势是否在扰动条件下放大由实验决定。（`05` 实验一、实验四）
3. **多采集者统计表征比单条 source realization 更少依赖示教策略**，同时仍能驱动执行。（`05` 实验五、六）
4. **更强 executor 泛化测试**：在任务 A、B 的 interaction 上训练后，能否对留出任务 C
   零样本执行；通过才声称该模型与数据规模下成立，不把它写成协议的先验。（`05` 实验二）
5. **复制 source 精确受力实现可能是冗余的**：task-agnostic surface wrench 范围
   达到与 exact source traction/wrench realization 相当的性能。（`05` §7）
6. **仿真观测模型下可重建**：只给“接触面相对物体的位姿 + 面上的触觉”的
   模拟观测，量化重建 region/mode/mechanics 相对 oracle 的退化。（`05` 实验七）
   这一步不含下游 executor，不能称“装置够用”或 sensor sufficiency；装置观测驱动
   E-I 的性能要等 S6 后补测，真机充分性仍属于 Phase II/III。

   ⚠️ **第 6 条此前完全没有实验支撑**，`plan/00` §4 把它整个推给了 Phase II，
   于是本轮没有直接检验原始装置的观测前提。审计后新增 `05` 实验七（S4.6）
   补仿真可观测性；它与 §2.3 CHORD、§2.4 的跨手 force-position transfer 仍有清楚
   边界，但不能替代下游控制或真机实验。
