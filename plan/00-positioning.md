# 00 — 定位、相关工作与可声称的边界

本文件回答"这个工作相对已有工作到底新在哪"，并为 `05` 的对照条件提供依据。开工前必读，写论文前重读。

## 1. 一句话定位

> 我们提出一份**物体中心的功能交互规格**，它同时满足三个性质——对跨形态执行**充分**、在字段上**最小**、对示教者策略**不变**——并给出一个**任务无关的执行器**，使任意末端执行器能够零样本实现未见任务的交互规格。

三个性质缺一不可。只证充分性 = 重复已有工作；只证最小性 = 消融报告；只证不变性 = 表示学习练习。

## 2. 最近的三个工作，必须正面处理

### 2.1 KITE（arXiv:2606.22113，Cornell，2026-06）

**这是同一个架构，不是相关工作。** contact-based interaction intent（3D 接触位置 + engage 方向）→ 置换不变 Transformer 编码为 latent → 每 embodiment 一个 action decoder。五种 embodiment，三个任务，真机 7–8/10。

截至本文件撰写时**未开源**（项目页 kite-manip.github.io 的 code 图标是纯文本 "Code soon"）。已去信询问，不把计划建立在拿到代码上。

它的四条 limitation 就是本工作的四个差异点：

| KITE 的洞 | 本工作 | 对应实验 |
|---|---|---|
| intent 纯几何：只有位置+方向，无力、无接触模式 | mechanics 范围 + stick/slide | `05` 实验一，C2→C4 |
| decoder 从 URDF 前向运动学采样训练，**全程无物理** | 物理仿真 + RL 学形态能力 | `05` 实验二 |
| 接触由 MANO + 物体几何**几何推断**，非测量 | 触觉直接测（本轮仿真中为 oracle，Phase II 起为传感） | 本轮不声称，见 §4 |
| "closest-feasible-contact 是局部启发式"，位姿偏移 30cm 掉到 37% | capability-aware 的可行接触选择 | `04` §6 可行性评价器 |

**对照方式**：不复刻 KITE 系统，而在本框架内加一个信息条件 C2（接触位置 + engage 方向，无 mode 无 mechanics）。论文中表述为 "KITE-style geometric contact intent, reimplemented within our framework"，不表述为 "KITE"。理由：KITE 的 decoder 无物理、其三个任务均非摩擦主导，原样搬到擦拭任务上失败属于 handicapped baseline，那样的比较站不住。若后续拿到代码，补真·KITE 对比进附录。

### 2.2 ART-Glove（arXiv:2606.16370，2026）

16 个**刚性功能面**覆盖手指+拇指+掌，22 个解剖对齐关节，2048 taxel @120 Hz，明确主张"用刚性功能面而非骨架表示手"。

**后果：PPT slide 7 的 "No need for human hand poses / skeleton, just focus on interaction surfaces" 不能再作为卖点。** 这句话已经被说过了。

仍存在的差异：ART-Glove 靠关节编码器 + 连杆恢复面位姿，本质是简化外骨骼；本方案的面无运动链，位姿直接测量/由触觉配准恢复。但这是工程路线差异，不是概念新颖性。

**重新定位**：硬件的卖点不是"不采骨架"，而是"**规格是物体系的，所以传感指标也是物体系的**"——见 `07` §3。这条是别人没有的，因为别人不从表示反推硬件指标。

### 2.3 CHORD（arXiv:2607.00033）

用 object wrench 作为核心抽象，1831 个任务，82.12% 平均成功率。**它证明了 exact wrench 可用，没有证明 exact wrench 必要。** 本工作的 C4 vs C5 对照（力范围 vs 精确力）正是针对这一点：若 C4 ≈ C5，说明 source 的精确 6D 分量是形态特异的冗余，应从功能表示中删除。这是可发表的最小性结论。

### 2.4 Transferring Contact, Not Just Motion（arXiv:2606.15516，2026）

**这条是 2026-08-30 审计时补上的，此前漏了。** 它做的正是"迁移接触而不是迁移
动作"的跨手抓取，用接触中心的表示在不同灵巧手之间迁移柔顺抓取。

**与本工作的差异，必须写清楚**：它（以及 AnyDexGrasp 一类的接触中心抓取表示）
**限于抓取合成**，不延伸到序列操作；本工作的 envelope 带 mode、mechanics 范围
与 phase，目标是持续接触的操作过程。但"contact-centric 表示可跨形态迁移"
这个**命题本身已经被它证过**了——本工作不能再把它当作新颖点，
只能声称"扩展到序列的、力学主导的操作"。

### 2.5 模态消融的既有结论（arXiv:2512.01358）

GR00T N1.5 在 GR1/G1 上的模态消融：零样本 0% → 微调 48% → +接触编码 74% →
+深度 82% → +接触状态 94%。两条结论直接约束本工作的措辞：

1. **显式接触/力状态是接触密集任务里最高价值的单一模态**——这一条已知，
   本工作不能拿它当结论；
2. **充分性是形态相关的，不存在普适的"够用模态集"**。所以 `plan/07` 的传感
   指标必须按**执行器形态**分别陈述，不得写成一个全局数字。

## 3. 其余需要引用但不构成威胁的工作

- **HACMan**（2305.03942）：非抓握操作中，随机化接触位置显著掉点 → 支持"region 有信息量"，但只在非抓握、单一形态上。
- **Where to Touch, How to Contact**（2601.10930）：contact intention（接触位置 + 物体子目标位姿）→ contact-implicit MPC。去掉子目标预测从 100% 掉到 20.6%。**这是 effect 侧必要性的强证据**，与本工作互补而非竞争（它不做跨形态）。
- **CordViP**（2502.08449）：去掉接触预训练在 Flip-Cup 上显著掉点。
- **FoAR**（2411.15753）/ **ForceFlow**（2605.11048）：力反馈的必要性**因任务而异**——ForceFlow 报告单轴压力调节任务上力反馈单独就够（80–90%）。**这条要求本工作的充分性声称按任务几何类别陈述，不得全局化。**
- **OmniContact**（2606.26201）：contact flow 作为中间表示。
- **Tac2Pose**（2204.11701）：触觉→物体位姿估计。本工作 `07` §3 的"触觉反向精化面位姿"直接借用这条思路。

## 4. 本轮明确不声称什么

沿用并扩充 `README` §2：

1. 不证明真实人类传感数据能恢复这些变量（Phase II/III，本轮不做）；
2. 不证明真实触觉或 RGB-D 精度已足够；
3. 不证明上游 interaction model 能泛化到新任务/新物体——**这是 VLA 规模的数据问题，本轮不碰**；
4. 不证明一个网络零样本控制**从未训练过的新形态**（本轮每个形态各训一个执行器）；
5. 不把浮动底座实验声称成完整机械臂泛化；
6. 不声称本表示覆盖所有 manipulation（尤其：动态、非准静态、多物体长程）。

## 5. 本轮**要**声称什么

按强度排序，第 1 条是主张，第 2–4 条是支撑，第 5 条是 2026-08-30 审计后
补上的——**它是本方案唯一别人没做过的那一条**：

1. **执行器是任务无关的**：在任务 A、B 的交互分布上训练的执行器，可对**留出任务 C** 的交互规格零样本执行，且不需要 C 的 reward、不需要微调。（`05` 实验二）
2. **同一份未改写的交互规格，可被至少三种形态明显不同的执行器实现**，且其动作、接触拓扑、能量分布明显不同。（`05` 实验三）
3. **功能交互在接触主导任务上严格优于几何接触意图（C2）和纯结果（C0）**，且优势在扰动条件下放大。（`05` 实验一、实验四）
4. **精确力是冗余的**：力的方向 + 范围达到与精确 6D wrench 相当的性能。（`05` §7）
5. **装置能测的那点东西够用**：只给"接触面相对物体的位姿 + 面上的触觉"，
   重建出的交互规格与 oracle 相当，下游执行器性能下降有限。（`05` 实验七）

   ⚠️ **第 5 条此前完全没有实验支撑**，`plan/00` §4 把它整个推给了 Phase II，
   于是本轮剩下的内容与 §2.3 的 CHORD、§2.4 的接触中心抓取迁移高度重叠。
   审计后新增 `05` 实验七（S4.6）补上，纯离线、不需新训练。
