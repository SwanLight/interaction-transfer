# 工程日志

目的：**避免重复造轮子、避免重复踩坑、避免反复推翻已经做过的决定。**

## 三个文件的分工

| 文件 | 记什么 | 什么时候写 |
|---|---|---|
| `progress.md` | 每个步骤的状态、实际参数、闸门数值 | 每完成一个步骤（或一个子项）就写 |
| `pitfalls.md` | 踩过的坑 + 解法 | **踩到的当下立刻写**，不要等 |
| `decisions.md` | 做过的技术决策 + 理由 + 被否决的方案 | 做决定的当下写 |

## 写入规则

1. **追加，不覆盖。** 旧记录即使过时也保留，在后面补一条更新，不要删。
2. **每条带日期。** 格式 `YYYY-MM-DD`。
3. **`pitfalls.md` 记"现象 → 原因 → 解法"三段。** 只记现象不记解法等于没记。
4. **`decisions.md` 必须写被否决的方案和否决理由。** 否则三个月后会有人重新提出同一个方案。
5. 参数一旦调整（尤其是 `../plan/01` §3.1 的摩擦标定和随机化范围），**新旧值都要记**。
6. **修订已有决策时，新增一条 D-xx 说明"修订 D-yy"，不要改写 D-yy 原文。** 例：D-11 修订 D-04、D-13 修订 D-05、D-14 修订 D-06。

## 三条必须记进 decisions.md、不得静默处理的情况

这三件事都会让数字变好看，也都会让结论作废：

1. **留出任务不通过后动了训练数据**（`pitfalls.md` P-13）；
2. **为了制造条件间差距而调了任务参数或随机化范围**（P-11）；
3. **四宫格/跨形态结果里对某个 target 单独改写了 envelope**（P-15）。

## 与 plan 的关系

`../plan/` 是设计意图，`log/` 是实际发生的事。**两者冲突时以 log 为准**，然后回头更新 plan 并在 `decisions.md` 里记一笔。
