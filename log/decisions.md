每条包含：**决定 / 理由 / 被否决的方案及否决理由**。

被否决的方案必须写下来，否则三个月后会有人重新提出同一个方案。

## D-01 · 仿真器选 Isaac Sim / Isaac Lab

**日期**：2026-08-27

**决定**：主仿真器用 Isaac Lab，锁定版本，不做双仿真器。

**理由**：服务器上 Isaac Sim 环境已就绪，这是预演阶段最大的 de-risk。求解器差异带来的收益远小于重新搭环境的成本。

**被否决**：
- **Genesis**：触觉支持更好（Tactile Genesis 建在它上面），但要重新装、迭代快、稳定性未知
- **MuJoCo / MJX**：contact-rich 上最经过验证，但同样要重新搭
- **双仿真器交叉验证**：预演阶段不需要，留给正式研究

**风险**：PhysX 在扭转摩擦上可能不稳。若旋钮任务出现异常，备选任务是"靠墙翻转方块"（纯 primitive，无关节，数值最稳）。

## D-02 · Source 用 2 块独立薄板，不拟真人手

**日期**：2026-08-27

**决定**：采集装置代理 = 2 块各自 6-DoF 独立的薄板，脚本驱动。

**理由**：对旋钮和抽屉这两个任务，两个接触面就够。不需要 MANO / 手模型 / IK / retarget，与"接触面才是交互主体"的核心主张一致，且脚本化极其省事。

**被否决**：
- **17 个 ring + 掌心的完整装置建模**：能测覆盖问题，但需要拟人手载体、成本高。**推迟到硬件方案定型前的第二轮**
- **仿真拟人手 + RL 做 source**：多一个 RL 训练阶段，且与验证目标无关
- **公开 HOI 数据集（ARCTIC/OakInk2/TACO）回放**：最像真人，但运动学捕捉数据穿模严重、物体质量靠猜，力只能靠逆动力学+摩擦锥 QP 估计，太脏。**留作预演通过后的 sanity check**

**代价**：本预演**不验证**接触面覆盖/布局是否够用。已写进 `plan/README.md` §2。

## D-03 · 第三执行器用钩杆，不用吸盘

**日期**：2026-08-27

**决定**：第三个执行器 = L 形钩杆（2 个圆柱，0 自由度）。

**理由**：零风险，且动作（钩住销钉绕圈推 / 钩把手拉）与捏握毫无相似之处，是四宫格视频里最有说服力的一格。

**被否决**：
- **Isaac Sim 原生 `SurfaceGripper`**：截至 5.0 **只支持 CPU 后端**，无法开大规模并行环境，不能用于 PPO 训练（见 `pitfalls.md` P-08）
- **自实现吸盘软约束**（PD 外力 + latch/unlatch + 断裂阈值）：技术上可行且 GPU 友好，但是第 0 步的一个不确定项。**预演跑通后有余力再做为加分项**

## D-04 · 灵巧手用 Allegro，靠放大物体解决"太大"

**日期**：2026-08-27

**决定**：灵巧手用 Isaac Lab 内置的 Allegro；Allegro 场景下物体统一 `SCALE = 1.6`。

**理由**：避免 URDF 导入风险（这是最容易陷进去的地方）。仿真里"手太大"是可以靠放大物体解决的伪问题。

**被否决**：
- **因时 Inspire RH56**（6 DoF，人手尺寸，真机好对接）：需要导 URDF。**推迟到预演通过、往真机走的时候**
- **XHand**（12 DoF）：同上
- **Shadow Hand**（内置，人手尺寸）：24 DoF，训练太慢
- **LEAP**：用户已排除（太大），且 16 DoF

**已知风险**：Allegro 是 16 DoF，训练比低自由度手慢。若拖慢进度，退路是**锁死部分手指自由度**（改 actuator config，不改资产），**而不是**去导 Inspire 的 URDF。

**日期**：2026-08-27

## D-06 · 不加挡板，用"圆盘 + 偏心销钉"让 region 成为必需

**日期**：2026-08-27

**决定**：旋钮 = 圆盘 + 一根偏心销钉 + revolute joint，销钉初始角每 episode 随机。

**被否决**：

## D-08 · Executor 做成 task-agnostic 的 goal-conditioned RL

**日期**：2026-08-27

**决定**：每个执行器一个 policy，同时覆盖两个任务，观测里没有 task id。用 goal-conditioned PPO 而非 BC/DAgger。

**理由**：
1. per-task 训练 = 任务信息从后门进来，等于什么都没证明
2. goal-conditioned RL 天然就是 idea 里说的「让执行器自己摸索一阵、了解自己形态的交互特性」
3. 探索过程的副产品直接就是 capability map
4. 加任务只增加数据、不增加 run 数

**被否决**：
- **BC → DAgger**（原实验方案的做法）：executor 只见过自己 expert 产生的 interaction 分布，跨形态测试时输入是 OOD，会因与假设无关的原因失败。这是原方案里的**循环论证**

## D-10 · 主实验改为「留出任务零样本」，拆出 E-I 交互跟踪执行器 ⭐

**日期**：2026-08-27

**决定**：设两个执行器。**E-T**（任务 reward）承载信息条件对照，不进入最终系统；**E-I**（交互跟踪 reward，任务无关）是最终系统，主指标是**留出任务零样本成功率**。主实验从"表示消融"改为"E-I 的留出任务零样本"。

**理由**：

1. **D-08 存在一处概念混淆。** 它说"goal-conditioned RL 天然就是 idea 里说的让执行器摸索自己形态的交互特性"——不成立。goal-conditioned RL 的 reward 里仍然有任务（角度/开度/清除量），观测里没有 task id 不等于训练信号里没有任务。新任务仍需新 reward、需重训。那是多任务策略，不是 executor。
2. **原主实验大概率打平，且打平原因与 idea 无关。** `04` §4 规定所有条件获得相同当前反馈（含接触力），再加稠密 effect reward，PPO 完全可以自行发现该往哪接触、用多大力。desired 字段只是提前告知答案，而 RL 擅长自己找答案。
3. **interaction 信息的价值不在"给定好 reward 时的策略性能"，而在"只给一份规格、没有 reward 可调时的充分性"。** 后者才是 idea 描述的场景，也才是硬件存在的理由。
4. E-I 同时是相对 KITE 最硬的差异点：KITE 的 decoder 是 URDF 前向运动学采样 + L2 回归，**全程无物理**；用物理 + RL 学形态能力是它 limitation 2 明确承认的洞。

**被否决**：

- **只加一个稀疏 reward 条件**：便宜，但仍是 E-T 框架，回答不了"任务无关"。降级为 `04` §8.2 的子实验保留。
- **用交互跟踪 reward 直接跑 C0–C5 对照**：循环论证（C0 连要跟踪的字段都没有）。`04` §8 的禁令因此保留，但**只约束 E-T**。
- **单一执行器同时承担两个实验**：无法同时满足"reward 对所有条件公平"和"reward 任务无关"，必须拆。

**代价**：训练运行数增加（+12 次 E-I），且需要新建预训练物体集（`03` §2.4）。

## D-12 · 擦拭任务重定义为「清除污渍」，允许持工具与直擦两种实现 ⭐

**日期**：2026-08-27

**决定**：擦拭的成功判据是清除目标区域污渍，允许 (a) 抓工具擦、(b) 用执行器自身接触面直擦。物体系定在**平面**上（`02` §1.1），两种实现共享同一份 envelope。dirt 清除判据从"黑板擦底面"泛化为"任一接触体"。

**理由**：

1. **主任务原本只有 1 个主执行器。** 按 D-05，擦拭可行执行器是 Allegro + 夹爪，而夹爪被排除在主结果外 → 最能检验 mode/mechanics 的任务上没有跨形态对照，这是原计划的一个结构性缺陷。
2. 重定义后擦拭有 3 个主执行器（Allegro 持工具、Allegro 直擦、垫头杆直擦），**且动作与接触拓扑差异达到最大**。
3. 它直接检验"表示与是否存在中间工具无关"——这是 idea 的核心主张之一，原本没有可检验的形式，现在有了（`02` §7 第 8 条）。
4. 更贴近 idea 本意："不同形态用各自的方式实现同一功能"，而非"不同形态都去抓同一个工具"。

**被否决**：

- **给黑板擦加把手让钩杆参与**：钩杆无法稳定施加法向压力，是伪可行。
- **接受擦拭只有一个主执行器**：主任务失去跨形态对照，Gate F 只能靠旋钮/抽屉支撑，而那两个任务恰恰是 region/mechanics 最可能冗余的。

**代价**：dirt 模型和 reset 逻辑需改（工作量小）；`02` §1.1 需要明确"被操作物体"的判定规则（已写）。

## D-14 · 旋钮加轮缘低摩擦，使 region 在信息论上不可推导

**日期**：2026-08-27

**决定**：圆盘轮缘摩擦系数 0.15，销钉 0.8（`01` §3.1）。

**理由**：D-06 用"偏心销钉 + 随机初始角"让 region 成为必需，但这不成立——执行器观测里有物体表面点云，销钉直接可见；转轴由 effect 推出。**对刚性单自由度铰接物体，`effect + 物体几何` 在构造上几乎蕴含 region。** 必须让"几何可达但功能后果不同"的区域存在，才谈得上检验 region。摩擦差异是纯参数改动，不动几何，符合 D-07。

**配套**：`02` §7 新增第 9 条"region 可推导性探针"——训练一个只看 effect + 点云的网络预测 region，若准确率接近上限，该任务不适合检验 region，如实报告而非调参掩盖。

**注意**：摩擦值在**任何实验开始前**基于上述几何论证设定，不是看到结果后回调的。这一点须在论文中写明，否则会被质疑为"调到 baseline 失败为止"。

## D-15 · 表示分辨率由敏感度扫描确定，不预先拍板

**日期**：2026-08-27

**决定**：`02` §2 的 256 表面点改为由 S4.5 扫描 {64, 256, 1024, 4096} 确定；初值按目标 pitch ≈ 2 mm 换算点数，而非固定点数。

**理由**：256 点在 90×45×25 mm 的黑板擦上 pitch ≈ 7.8 mm，而真实指尖触觉 16×16 覆盖 20×20 mm、pitch ≈ 1.25 mm——传感器测到的斑块结构在写进表示时被抹平了 6 倍。但也不能直接改成 4096：物体侧分辨率的上限由 taxel pitch、**面位姿精度**、物体跟踪精度三者取最松，面位姿精度大概率才是真瓶颈。所以必须实测饱和点，而非按传感器能力定。

原计划把"表示分辨率""传感 pitch""面位姿精度"分别在三处各自拍定，互不一致。现由同一实验共同确定（`07` §1）。

**配套**：若判定需要高分辨率，executor 输入按 `02` §2.3 采用"低分辨率全局 + 接触邻域局部高分辨率"，避免 PointNet 成为训练瓶颈。

## D-16 · 新增扰动恢复实验，作为触觉必要性的唯一论证

**日期**：2026-08-27

**决定**：新增 `05` 实验四。episode 中途注入摩擦/质量突变、外部冲量、诱导滑移，测恢复率、恢复时间、纠正方向正确率。纯评估，不需新训练。

**理由**：整个硬件 pitch 建立在触觉上，但原计划把接触反馈统一发给所有条件之后，就再没有任何实验测它的价值——**算法验证里触觉不产生任何可测收益，这是审稿人一眼会看到的洞**。

而且这大概率是 C0 真正失败的地方：物体偏离期望轨迹时，effect 只说"该到哪"，不说"为什么没到、该改什么"；mode（现在在 slide 而非 stick）和 mechanics 范围（法向力不够）直接指出纠正方向。

**注意**：ForceFlow 报告单轴压力调节任务上力反馈单独就够（80–90%），因此结论必须**按任务几何类别陈述，不得全局化**。

## D-17 · Envelope 范围用分位数回归 + conformal 校准

**日期**：2026-08-27

**决定**：mechanics 上下界用 pinball loss 回归 τ=0.1/0.9 分位数；region 阈值用 conformal prediction 在**独立校准集**上标定至 coverage ≥ 90%。评估必须同时报 coverage 与 width。

**理由**：原文"必须覆盖成功示教但不过度宽泛"没有可操作定义，无法判定通过与否。改成两个可测量的数后，目标函数明确：coverage ≥ 90% 约束下最小化 width。过宽的 envelope 会在 coverage 通过但在 width 暴露。

不用"均值 ± k·标准差"：接触力分布通常单侧截断，对称假设不成立。

**配套**：`03` §7 新增独立校准集（用训练集标定会使覆盖率保证失效）。

## D-20 · 不升级 Isaac Lab，直接用 PhysX tensor view 读逐点接触/摩擦数据

## D-24 · 旋钮摩擦重标定，并强制 `frictionCombineMode="min"`

**日期**：2026-08-27（S1 实测后）

**背景**：D-14 设的初值（μ_rim=0.15, μ_pin=0.80, damping=0.05）在 S1 标定中**未通过**：

```
τ_rim = 0.15 × 25 × 0.070 = 0.263 N·m
τ_need = 0.05 × 1.5 + 0.15 = 0.225 N·m
→ τ_rim > τ_need，轮缘推得动，D-14 不成立
```

**决定**：改为 μ_rim = **0.10**、μ_pin = 0.80、joint_damping = **0.28**。新裕量：

```
τ_need = 0.28 × 1.5           = 0.42  N·m
τ_rim  = 0.10 × 25 × 0.070    = 0.175 N·m   比值 0.42  （要求 < 0.5）
τ_pin  = 25 × 0.052           = 1.30  N·m   比值 3.10  （要求 > 3.0）
```

判据从"解析估算"升级为"**实测**"：纯轮缘接触在安全力上限内推不到目标角 1.0 rad，销钉接触可以。解析值只作为设计裕量参考。

**同时发现并修复一个会让 D-14 静默失效的问题**：

PhysX 默认 `frictionCombineMode = average`。低摩擦轮缘（0.10）碰上高摩擦执行器（0.7）时，实际接触摩擦是 **(0.10+0.7)/2 = 0.40**，τ_rim 变成 0.70 N·m，远超 τ_need。**整个 D-14 失效，且没有任何报错。**

因此所有物理材质强制 `friction_combine_mode="min"` / `restitution_combine_mode="min"`，写进 `plan/01` §1 规则 9。S1 的标定推子故意设 μ=0.9，就是用来验证这条生效的。

**合法性**：本次调整发生在 **S1 阶段、任何实验开始之前**，依据是 §3.1 的几何论证（推销钉靠法向力、蹭轮缘靠摩擦力），不是看到实验结果后回调的。符合 D-21 的边界（S2 开始训练后才冻结）。论文中须写明标定发生的时点与依据。

## D-30 · Expert 从「9 个先训完」改为「按需训」，用一条硬规则锁住诊断逻辑 ⭐

**日期**：2026-08-28

**背景**：用户提问——「我们不是先用 source 模拟人采集、再用 interaction 泛化到不同执行器吗？为什么变成每个执行器每个任务都用 RL 训练？」

这个提问是对的，值得正面回答：

- **正式流水线里没有 Expert。** 链路是 `双板 source（脚本化）→ Oracle Interaction Record → Functional Envelope → 各执行器的 E-I`。source 数据由脚本化阶段机产生（`plan/03` §3），D-08 也已否决 BC→DAgger。
- **Expert 是诊断基线**（`plan/04` §1.4、§3）：先证明环境本身可学，免得后面把环境的问题算到表示头上。

但**代价不成比例**。S2 第一个组合的实践证明：真正确认「抽屉×钩杆可行」的是**脚本验证**（3 分钟），不是 PPO 训练（1.5 GPU 小时 + 三轮 reward 返工）。

**决定**：

| 层 | 内容 | 范围 |
|---|---|---|
| **强制** | 脚本可行性验证（**走 policy 动作接口**）+ reward 量纲标定 | 全部 9 个组合 |
| **按需** | Expert 训练 | Tier 1 的 2 个组合（主表需要性能上限）+ 任何需要甄别失败原因的组合 |

**硬规则（这条是全部的关键，不得违反）**：

> **在没有为某个组合训练过 Expert 之前，绝不允许把该组合的失败归因于「表示信息不够」。**

省的是**什么时候花钱**，不是严谨性。原方案是「先把 9 个都付了以备不时之需」，新方案是「需要甄别时必须真的去训」。只要这条规则不破，`plan/05` §11 的失败解释表原样成立。

**为什么脚本验证能替掉大部分**：Expert 证明三件事，脚本验证覆盖前两件——

1. 任务几何+动力学上做得到 → 脚本验证直接证明（真实物理）
2. 动作空间够用 → **必须走 policy 的动作接口**才算数。直接调底层 PD 只验证几何，验证不了「策略能不能用它的动作表达出来」。已实现：把期望位姿增量换算成归一化动作，统计触到幅度上限的步数比例（实测抽屉×钩杆为 1.0%，够用）
3. reward 可学 → 量纲标定覆盖「配比是否合理」，**不覆盖「是否可学」**，这部分靠上面的硬规则兜底

**被否决**：

- **完全取消 Expert**：`plan/05` §11 的失败归因就失去依据，Gate A 形同虚设。
- **维持 9 个全训**：S2 实践证明每个组合都要经历「几何调试 + reward 返工」，9 个的成本挤占的是 E-I 留出任务零样本的算力——而后者才是本工作的主张（`plan/00` §5 第 1 条）。

**配套**：`plan/04` §3、`plan/05` Gate A 已同步修改。

## D-31 · reward 的三个洞（S2 实测）

**日期**：2026-08-28

抽屉×钩杆的 Expert 训练前后返工三轮，每一轮都是 reward 设计问题而非算法问题。记下来，后面 8 个组合别再踩：

**洞 1 · 塑形项可以靠悬停刷分。** `reach = exp(-4·距离)` 直接给分，随机策略每步就能拿 +0.29、累计 +31.65，而抽屉几乎没开——最优解是「在把手附近悬停但不开抽屉」。
→ 改**势函数式**（只奖励距离的减少量），求和 telescope 到「起止之差」，刷不了。

**洞 2 · 量纲失衡，最优解是「不动」。** 初版 success 加权 +122、progress 只有 +2.2，而 action 惩罚 −32。训练 40 轮 reward 从 −44.8 只爬到 −19.7、episode 长度 399/400（从没成功）。
→ 权重必须在**一条成功的脚本轨迹**上标定，不能拍。

**洞 3 · 提前终止可以用来自杀刷分。** 每步 reward 可能为负，而策略只要让执行器飞出边界就能立刻结束 episode——**主动自杀比继续做任务划算**。实测 episode 长度掉到 247 而 reward 一路走低到 −88，曲线剧烈震荡（52 → −90 → +17 → −51）。
→ 失败终止必须有**显式的一次性惩罚**，且大于「放弃任务」的收益。

**洞 4 · `sign()` 造成奖励悬崖。** `progress × sign(目标 - 当前)` 在开度超过目标时符号翻转，奖励不连续。
→ 改成「与目标差距」的势函数式差分，处处连续。

**通用做法**：任何新任务的 reward，先跑 `tools/s2_scripted.py` 在成功轨迹上打出各项累计值，看配比，再开训。三分钟省几个 GPU 小时。

## D-34 · 钩杆的已知特性：主杆承担 78% 接触，横钩只占 4.3%

**日期**：2026-08-28

**来源**：用户看录像后指出「勾的是把手侧面凸出来的那一小段，而不是正中心那片区域，
而且用的是长杆子那一端，不是更短的钩子」。实测（`tools/s2_probe_where.py`，
16 env × 200 步，1423 个接触点）**完全证实**：

**接触落在钩杆的哪个部位**

| 部位 | 占比 | 累计法向力 |
|---|---:|---:|
| **横钩（真正的钩子，50 mm）** | **4.3%** | 826 N |
| 主杆中上段 | **66.6%** | 17098 N |
| 主杆中下段 | 10.0% | 3046 N |
| 主杆下端 | 1.1% | 334 N |

**接触落在把手的哪个部位**

| 部位 | 占比 | 累计法向力 |
|---|---:|---:|
| 横杆中央 \|y\|<54 mm | 16.6% | 3588 N |
| **横杆柱外伸出段 62.5–70 mm** | **37.6%** | 8957 N |
| 支撑柱 | 8.8% | 1787 N |
| 非把手（面板/托盘） | 33.9% | 8628 N |

**几何原因（不是策略"偷懒"）**：

主杆 250 mm、横钩 50 mm，**半径都是 8 mm**。主杆比横钩长 5 倍。
竖直插进净空时，主杆总有一段落在把手高度上；横钩只有 50 mm 且固定在
主杆底端 z=−117，要对准把手高度就得整体抬高主杆——主杆照样穿过把手高度。
**两者能同时接触时，主杆的可接触面积压倒性地大。**

柱外伸出段同理：那是横杆的**自由末端**，侧向一靠就挂住；中央段要先把杆子
塞进 45 mm 净空。策略选了阻力最小的路——挂边角。

**决定：本轮不改，记为钩杆的已知特性。**

理由：

1. S2 的目的是物理可行性，已达到并关闭；
2. 主线的示教数据来自**脚本化双板采集器**（`plan/03` §3），不来自这个 Expert，
   所以不污染 Oracle Interaction Record；
3. `plan/05` 实验三要比较跨形态的接触拓扑，届时钩杆「偏爱挂边角」的特性
   会体现在数据里——**必须知道它的来源，才不会误读成表示学到的东西**。

**若将来要让横钩真正成为工作面**，应改几何而非改奖励：
缩短主杆、或把净空收窄到只有横钩进得去。**用物理约束，不用奖励引导**
（同 D-33 的原则）。

**原始数据**：`out/s2_expert/s2_probe_where.txt`

## D-35 · 采集板改为 USD 资产，加纯视觉朝向标记，质量 0.05 → 0.5 kg

**日期**：2026-08-29

**决定**：

4. `max_depenetration_velocity` 对板单独收到 0.25。

**理由**：

- **标记**：`plan/06` §7 要求人工看视频确认"接触发生在该发生的面上"。

  鳍突出 6 mm（板高的 24%），2 mm 级的标记在 960×540 的录像里只有 1~2 像素。
- **质量**：理由是**数值的**，不是物理的。见 `pitfalls.md` P-34——

- **把标记做成有碰撞的几何**：更"诚实"（背面撞到东西也该有反应），但会改动
  S1 已验过的碰撞几何，且 D-02 的板尺寸要重验。标记的唯一用途是让画面可读，

- **把板做大以增加惯量**：D-02 定的 35×25 mm 是"接触面"的尺度依据，
  改尺寸等于改研究对象。改质量不改几何。

**影响**：S1 双板自检需复跑（已跑，2/2 PASS）。S2 不涉及板，不受影响。

## D-37 · 抽屉 source 的五个策略家族；取消"手面倾斜"一档

**日期**：2026-08-29

**决定**：抽屉的 source 策略家族定为五个（`plan/03` §2.2 要求 ≥3）：

| 家族 | 站位 | 力 | 覆盖 `plan/03` §2.2 的哪一条 |
|---|---|---|---|
| `pinch_center` | 手指在杆背、拇指在杆前，把手中段 | 5.5~7.5 / 1.2~2.2 N | 第 1 条 中央对称夹持 |
| `pinch_offset` | 同上，整体沿杆平移 ±14~26 mm | 同上 | 第 2 条 偏左/偏右夹持 |
| `hook_both` | 两块都在杆背，y 相距 38~68 mm | 2.0~3.2 N 各 | 双指纯勾，接触拓扑与 pinch 不同 |
| `asym_primary` | 站位同 hook_both | 3.4~4.6 / 0.5~1.2 N | 第 3 条 一块承担主要拉力 |
| `single_finger` | **只用一块板**，另一块全程不参与 | 4.5~6.5 N | 见下 |

`single_finger` 是本轮新增的一档，理由不只是"多一种打开方式"：
`plan/02` §7 第 3 条要求"改变 source 板数量后表示维度不变"，
那条泄漏检查**需要真的存在只有一个接触体的示教**才能验。没有这一档，
第 3 条只能靠嘴说。

**取消"不同手面姿态"（原计划 §2.2 第 4 条）的原原本本的理由**：

试过绕水平轴（pitch）和绕竖直轴（yaw）两种倾斜，**几何上都不成立**。
平板贴圆柱只有在板面与柱轴平行时才是面接触；绕任何轴一转，最近的就变成
板的一条棱：

- pitch：棱扎进杆里，接触力冲到 75 N，板被压低 23 mm，
  接触部位 100% 判成 `bar_bottom`——采出来的 region 会说"开抽屉要压把手底面"。
- yaw：板面与柱轴不再平行，平面与柱轴相交，板的一角必然先顶上去，
  同样是棱接触。

**替代**：手面姿态的多样性改由两条提供——
`z_off`（贴在杆背的高低差 ±4 mm，对半径 11 mm 的杆是 ±21° 的接触角变化，
region 和 engage 方向都真的不同）和 `single_finger`（接触体数量不同）。

**这条必须写进论文的限制**：抽屉的把手是圆柱，平面采集板在它上面
**没有"手面倾斜"这个自由度**。擦拭任务的被操作物体是平面，那里倾斜是成立的，
`plan/03` §2.3 的第 3 条（轻微倾斜抓持）到擦拭再做。

**被否决**：

- **给倾斜档加上正确的贴合距离补偿**（按倾角算 `ENGAGE_DX`）：能避免扎进去，
  但接触会落在板的棱上，`plan/02` §3.2 的 region 记的就是"棱在蹭"——
  那不是我们想让 envelope 学到的东西。
- **把把手改成方杆**让倾斜成立：D-07 允许改参数，但把手几何是 S1/S2 已验过的，
  且"为了让某个策略家族成立而改物体"离 P-11 只有一步之遥。

## D-39 · 预训练物体集补三个物体并冻结覆盖论证 ⭐

**日期**：2026-08-29（**早于任何 E-I 训练**，这一点是本条成立的关键）

**决定**：预训练物体集从四个（方块 / 立柱 / 滑块 / 斜面垫）改为六个，
新增**转盘 `dial`**、**擦板 `wipeboard`**、**凸棱台 `ridge`**，
并给滑块的块加一圈**凸缘**使它可以被"勾住拉"而不只是被推。
完整覆盖论证写进 `plan/03` §2.4，此处只记决定与理由。

**理由**：判据不是"有几个物体"，而是从 `plan/04` §5.4 的留出划分倒推——
**每个执行器的留出任务需要哪些交互原语，这组物体里必须都有**。
初版四个物体有三个洞：

1. **没有受约束转动**。立柱是自由刚体，搓转靠摩擦，与"绕固定轴带阻尼的关节"
   不是一回事。而钩杆**只训预训练集**，留出任务里有旋钮。
2. **只有推没有拉**。滑块只能被推，而抽屉是"勾住凸出结构往外拉"，
   同样是钩杆的留出任务。
3. **没有曲面接触**。四个物体的接触面全是平面，而抽屉把手是圆柱；
   `plan/02` §3.3 的 engage 方向在平面上是常量、在曲面上随位置变化。

任何一个洞留着，Gate E 不通过都**无法归因**——只能说明训练分布没覆盖到，
说明不了"执行器不是任务无关的"，`plan/05` §11 的失败解释表会直接失效。

**边界（必须写进论文，不得回避）**：

> 预训练集提供的是**交互原语（能力）**，不是任务。
> 留出任务的**物体、几何、reward、envelope** 一律不出现在预训练集里。

新增的三个物体都刻意与对应任务做出区别，`plan/03` §2.4.3 有两张逐项对照表
（擦板 vs 擦拭平面：尺寸不同、可倾斜、无 dirt grid、无黑板擦；
转盘 vs 旋钮：三耳而非单销、无 D-14 的低摩擦轮缘、半径不同、无目标角）。

审稿人一定会问"预训练集是不是照着留出任务设计的"。答案是**"是，照着留出任务
需要的原语设计的，但不含留出任务本身"**，并附对照表。藏着不说才是问题。

**为什么这不构成 P-13**：P-13 禁止的是"留出任务不通过之后动训练数据"。
这一条是在**任何 E-I 训练开始之前**定的，依据是留出划分的结构，
不是任何实验结果。`plan/03` §2.4.4 已写明冻结时点。

**被否决**：

- **维持四个物体，Gate E 不过再补**：那正好落进 P-13 的形状——
  即使补的是原语不是任务，"看到失败才补"这件事本身就不可辩护。
  代价是现在多做三个资产，收益是结论可归因。
- **把擦拭平面直接放进预训练集（换个尺寸就算新物体）**：那是把留出任务
  的被操作物体拿来训练，`plan/02` §1.1 明确擦拭的被操作物体就是那个平面。
  擦板必须在尺寸、倾角、有无 dirt grid 上都不同，且不产生 envelope。
- **给转盘也做低摩擦轮缘**：那会把 D-14 的设计（旋钮 region 可检验性的前提）
  复制进预训练集，等于把旋钮任务的核心结构提前教给执行器。

## D-40 · 摩擦力按摩擦自己的下标取，并按法向力占比摊到接触点

**日期**：2026-08-29

**决定**：`extract_contact_points_padded` 不再用接触 buffer 的下标去索引摩擦
buffer。改为：摩擦锚点**按位置归属到 env**（同 D-38 的理由），
再按**法向力占比**把斑块级摩擦摊到该斑块的各接触点上。

**理由**：见 `pitfalls.md` P-36。两个 buffer 的 counts 不同（实测接触 4 个点
对应摩擦 2 个锚点），混用下标使 env0 的摩擦翻倍、env1 全零。
`plan/02` §3.4 的 Contact Mode 直接建立在 `|f_t|` vs `μ|f_n|` 上，
摩擦错了 mode 标签就整体是错的——S3 数据集实测 `stick_share`
从 0.72 变成 0.36。

**为什么按法向力占比摊派**：摩擦是**斑块级**的量，接触点是点级的量，
两者不同构，必须选一个摊派规则。库仑摩擦下同一斑块内摩擦力正比于法向载荷，
所以这个规则既有物理依据，又保证「各点之和 = 斑块实际摩擦力」，
不凭空多出或少掉；每点的 `|f_t|/(μ·f_n)` 仍是判 stick/slide 的正确量。

**被否决**：

- **只报每个接触体的摩擦合力，不摊到点**：`plan/02` §3.4 明确写了
  "不能只存全局 mode 比例，否则会丢失哪个区域在滑、哪个区域在支撑"。
- **把摩擦锚点当成接触点用**（直接以锚点为单位记录）：锚点数比接触点少，
  且没有法向力与法向量，region 热图和 mechanics 都构造不出来。
  锚点原始数据仍可从 buffer 取，需要时再加字段。

**影响**：S3 抽屉数据集已按修复后的代码**全量重采**。
S1/S2 用的 `extract_contact_points` 未改（它是既有依赖），
但已在 docstring 里写明它的摩擦力是错的；`src/it/envs/base.py::contact_summary`
的摩擦分量因此也不可信——S2 的 Expert 观测里含这一项，
但 Gate A 问的是"能不能学会"，结论不受影响。**S4 之后不得再用那条路径取摩擦。**

## D-41 · 探针物体集改由**独立分类学**推出，不再按留出任务反推 ⭐⭐

**日期**：2026-08-29（修订 D-39，**仍早于任何 E-I 训练**）

**背景**：用户指出 D-39 的做法"会不会产生误解，搞得像在摸索训练阶段执行器
就已经通过训练掌握了这个同样的任务了，逻辑上有点说不通"。

**这个质疑是对的，而且比"误解"更严重——那是一个真实的逻辑漏洞。**

D-39 的选物体方法是：看留出任务需要什么原语，就补一个能产生那种原语的物体。
擦拭要"带法向力持续滑移"就加擦板，旋钮要"绕固定轴转动"就加转盘。
问题不在覆盖够不够，而在**它把留出任务的答案提前教了进去，且从外面无法与
作弊区分**：若物体集是照着留出任务反推的，执行器在"摸索能力"阶段学到的
就是留出任务本身，只换了个物体标签，`plan/00` §5 第 1 条就退化成
"同一件事做两遍"。

**决定**：物体集改为从一套**独立于本项目三个任务**的交互分类学推出，
判据从"是否覆盖留出任务"改为"**是否张满该分类学**"。留出任务被覆盖到，
是"张满"的推论，不是设计目标。完整分类学、原语库与物体表见 `plan/03` §2.4。

分类学的三个外部依据：

- **Huang, *Robotic Manipulation Primitives*（CMU 2021）**：用接触模式
  （separating / sticking / sliding）枚举操作原语。与 `plan/02` §3.4
  记录的字段逐字对应。
- **Bullock, Ma & Dollar 2013（IEEE T-Haptics）**：5 个二值描述子 → 15 个互斥类。
- **Lynch & Mason 谱系**（stable pushing 1996、toppling 1999、Mason 1999 综述、
  Aiyama 1993 pivoting）：非抓握原语的既有命名。

五个轴（S 接触结构 / M 接触模式 / F 力学通道 / E 物体自由度与 effect /
G 接触面几何），15 条原语，**每个轴的每个取值都被占据**。

**新增硬规则——冗余**：

> **每条原语必须由至少两个几何结构不同的物体提供。**

这条是上述漏洞的直接解药：满足它之后，"你是照着任务 X 设计物体 Y 的"
失去力量——删掉 Y，那一格仍被别的物体覆盖着。物体集因此从 6 个扩到 **8 个**
（新增 `flap` 翻板与 `plunger` 柱塞，`wipeboard` 更名 `slab` 并缩小到 200×150）。

**新增可测量的辩护**（`plan/03` §2.4.6，写进 `plan/05` 实验二）：

> **指令距离**：对每条留出任务的交互规格，算它到训练指令分布中最近一条的距离，
> 报告零样本成功率**随该距离的变化**。

把"这算不算作弊"从争论变成一条曲线。远离任何训练指令仍然成功，主张就成立，
且与物体集怎么选无关。

**被否决**：

- **维持 D-39 的六个物体，在论文里把边界讲清楚**：讲清楚也改变不了
  "物体是照着留出任务反推的"这个事实。审稿人只要问一句
  "如果去掉擦板，垫头杆还能零样本擦拭吗"，就没有答案。冗余规则让这个问题
  变得可回答。
- **完全不给"物体不动、接触在滑"这一格**（避嫌）：那一格由 E5 轴决定，
  与擦拭无关——物体可以被固定是一个独立事实。为了避嫌而留一个空格，
  会让 Gate E 不通过时无法归因，反而更糟。
- **只在留出任务需要的原语上做冗余**：那还是在按留出任务设计，只是隐蔽一层。
  冗余规则**统一适用**。

**状态**：D-39 的覆盖论证被本条取代；D-39 中"补三个洞"的具体理由仍然成立，
只是不再作为**选物体的依据**——现在的依据是张满分类学。

## D-42 · 擦拭的 effect 只保留平面表面状态，删掉"接触体 6D 位姿增量"

**日期**：2026-08-29

**决定**：`plan/02` §3.1 里擦拭的 Object Effect 从

> 目标区域内 dirt 状态的未来变化，**以及擦拭接触体相对平面的未来 6D 位姿增量**

改为**只有前半句**。

**理由**：擦拭接触体是黑板擦或执行器自己的接触面，**两者都是 source 侧的东西**。
把它写进 effect，envelope 就携带了"用什么姿态、沿什么路径移动你的手"——
那是**动作层面的迁移**，正是本工作声称不做的事（`plan/00` §1），
并且直接违反：

- `plan/02` §1「不输出 source 的板位姿、速度、动作」；
- `plan/02` §7 第 8 条「擦拭的 envelope 不得包含工具的存在与否、工具位姿或工具几何」；
- `plan/04` §5.4 垫头杆那一格的全部意义——一个不能抓握的杆子执行同一份
  envelope；若 envelope 里写着黑板擦的位姿轨迹，它根本无从执行。

**这条是本轮自查中发现的第二个逻辑漏洞**，与 D-41 那个同源：
都是在"给下游更多信息"的动机下，把 source 特有的东西混进了物体中心的规格。

**代价**：擦拭的 effect 通道因此只剩表面状态变化，是一个**稀疏**信号
（`plan/04` §5.1 的 `r_effect` 在擦拭上梯度很弱）。这不是缺陷而是事实——
擦拭的信息本来就主要在 region / mode / mechanics 上，
`plan/05` §2.5 早就预期"擦拭主要检验 mode 和法向/切向作用"。

**被否决**：**保留但只给方向不给幅值**——方向同样是 source 的运动方向，
一样是动作层面的东西，减半不解决性质问题。

## D-43 · 交互原语库落地：15 条原语、9 个探针物体、原语×位点的采集器

> **后续（同日）：15 格已全部补满，物体集扩到 10 个，见 D-47。**
> 下面这条保留原样，包括它如实列出的五个未满足格——那份"不好看也不删"的
> 记录正是后来定位到解法的起点。

**日期**：2026-08-29（实现 D-41 的设计）

**决定**：探针物体集的采集器 `tools/s3_source_probe.py` 按
**原语 × 接触位点**组织，不按"每个物体一段脚本"。

- **物体**只声明它表面有哪些位点（物体局部系的位置、外法向、切向、进入方向）；
- **原语**只声明贴上去之后怎么动（法向力多大、切向是扫掠/加力/脉冲、
  一块板还是两块对置、扫掠锚在物体系还是世界系、法向走力控还是速度控制）。

两者叉乘。加一个物体不需要写新的阶段机。这不只是省代码——`plan/02` 的交互规格
本身就是「region（位点）+ engage 方向（法向）+ mode + mechanics」，
脚本按同一结构组织，采出来的数据与规格字段天然对齐。

**物体从 8 个变成 9 个**：新增 `roller` 卧倒滚柱。理由是冗余规则暴露的：
立着的 `column` 受侧推只会**倒**不会滚（实测 97.7% 的操作步脱手、跑出 2 米），
P7 rolling contact 需要一个真能滚的物体。

**实现过程中被物理否掉的三处设计**（都记在这里，避免有人再提）：

1. **翻板做成"平放的板、沿水平边铰接"** → 平板执行器伸不到板底下把它掀起来，
   只能压，而压被底座挡住。改成**竖直铰接的门**，推板面就是最自然的动作，
   而且接触点离转轴多远直接改变所需力矩，P9 crank 的力臂含义因此是真的。
2. **柱塞的套筒做成实心圆柱** → 杆推进去就是两个实体互相穿插，关节被卡死
   （关节位移恒为 0）。改成 U 形槽，约束本来就由 prismatic joint 提供。
3. **在自由方块和立柱上做 rub** → 板-物体与物体-地面同为 μ=0.9，
   "板滑而物体不动"的力窗口只有 2 N 宽，实测方块被拖走 35 m。
   P4 rub 改由 `slab` / `ridge` 两个**固定**物体承载，冗余仍满足。

**一条未达成的原语，如实记下**：

> **P7 rolling contact 本轮没有做成。** `roller` 资产已建、`poke` 在它上面
> 9/9 通过，但 `roll` 全部失败：自由圆柱的滚动阻力接近零，PhysX 也不建模滚阻，
> 位置控制的推板追不上它（实测脱手 79%、物体跑出 200 mm 而推板只前进 105 mm）。
> 已试过角阻尼 4.0 + 线阻尼 3.0（把 poke 从 33% 救到 100%）、
> 推进方向在贴合时锁定（不跟着物体转）、速度控制替代力控——都不足以留住接触。
>
> **后果**：`plan/03` §2.4.5 的冗余规则在 P7 这一格上**未满足**（现为 0 个物体）。
> 下一步的方向是给推板加一个"跟随物体速度"的前馈（把物体测速直接加进推板的
> 速度指令），而不是继续调阻尼。**在做成之前，不得声称原语库已张满。**

**为什么把它写出来而不是悄悄删掉这一格**：删掉就等于把分类学改成
"我们做得到的那些"，而 D-41 的全部意义在于分类学独立于我们的实现。
张不满就报张不满。

## D-44 · 擦拭 source：三轴全位置控制，压力由位置干涉给

**日期**：2026-08-29

**决定**：擦拭采集器 `tools/s3_source_wipe.py` 的两块板**三个轴全部走位置控制**：
X 夹持（位置干涉）、Y 扫掠、Z 下压（位置干涉）。**不用力控。**

**理由**：一开始 Z 走力控，结果**同一个指令力在不同家族上量出来差一个数量级**
（2.4 N 的指令，`tool_center` 量到 7.5 N、`tool_light_fast` 量到 0.67 N）。
原因是力从板经"摩擦抓持"传到黑板擦、再传到平面，这条链是软的，
而力控轴没有位置参考，板会在 260 帧里慢慢漂走。位置干涉把高度钉死：
下压力 = 板刚度 × δ，可预测、可复现。

**配套**：`plan/01` §5.3 的清除判据是**逐接触体**判法向力，
所以 δ 的换算按接触体数量分（见 `pitfalls.md` P-41）。

**六个策略家族**（`plan/03` §2.3 要求 ≥5 且必须含直擦）：
`tool_center` / `tool_offset` / `tool_tilt` / `tool_heavy_slow` /
`tool_light_fast` / `direct_wipe`。

「高压慢速 / 低压快速」的**速度**用**蛇形趟数**表达，不用速度倍率——
倍率 <1 会让路径根本走不完（实测清除率卡在 67%），趟数少则每趟走得慢
而路径总能走完。

**被否决**：

- **用力控 + 更大的 kd_force**：治标。链是软的这件事不会因为阻尼变大而改变。
- **把黑板擦焊在板上**：`plan/01` §5.4 明确要求"抓持仍由真实接触维持，
  不能刚性焊接"——焊上就没有抓持交互可采了。

**结果**：1800 条 / 1389 成功（77.2%），六个家族齐全，
`direct_wipe` 250 条成功——那一档是 `plan/02` §7 第 8 条泄漏检查
（envelope 与"是否用工具"无关）唯一的数据来源。

⚠️ **这两行是当天那一次采集的数，S4 用的不是它**（2026-08-30 补记）。
按最新契约重采的 `/tmp/s3_wipe_v5` 是 **2700 条 / 2606 成功（96.5%）**，
`direct_wipe` 373 条成功；成功率的提升来自本条决定本身（软链耦合改掉之后
脱手率归零），**不是判据放松**。**引用擦拭成功数时以 `out/s3_wipe/report.txt`
为准，不要引这一段。**

1. **参考系挂在销钉的实际角度上，推进量由力控给**（P-42）。
   领先角方案会让接触法向偏离切向最多 42°，力大半变成径向的无用功。
   力控方向 = 销钉当前位置的切向，每个控制步重算 —— 圆盘转多少，
   力的方向就跟着转多少。

2. **轮缘家族不走力控，走位置干涉**（P-44）。光滑柱面上力控轴没有侧向约束，
   板会钻到圆盘底下（1229 N，力矩为零）。干涉量按**实测力**取到安全上限
   附近（6.5 mm → 19.5 N < 25 N）：轮缘必须被**压足**，对照才算数。

3. **板的长边与销钉轴平行**（P-46）。横放时板会从销钉上滑脱，
   纯销钉段接触力 0.0~0.4 N；竖放 3.7~13.3 N；而静态位控下两种都正常。
   例外是 `pin_push_dual`——48 mm 的销钉放不下两块 35 mm 的竖板。

**D-14 的操作级证据（本轮的主要产出）**：`rim_only` 在**压足 19.5 N**
（安全上限 25 N 之内）的条件下只转到 **0.019 rad**，而销钉家族转到
2.34~2.76 rad。τ_rim = μ·F·R = 0.10 × 19.5 × 0.070 = **0.137 N·m**，
τ_need = 阻尼 × ω = 0.28 × 1.5 = **0.42 N·m**。差 3 倍，转不动。
S1 只做了静态标定，这里是真实操作轨迹上的验证，`plan/05` 实验五的反事实
（region 从销钉换到轮缘 -> 打滑失败）有数据基础了。

**安全上限没有被放宽**。`MAX_PUSH_FORCE` 反而从 18 N 降到 13 N，
因为 `pin_push_dual` 两块板上下夹住销钉时指令力几乎全部落到物体上，
18 N 时有 6.6% 的操作帧越过 25 N。**上限对所有家族一律相同**——
按家族分别放宽才是把上限当成可调参数。

**目标角改为由角速度导出**（`goal = ω × 1.55 s`）。独立采 goal 和 ω 时驱动
时长在 0.5~1.8 s 之间变，而窗口是固定的，转完之后的空转会被算进脱手率
（P-47）。绑定之后所有 episode 的驱动时长一致。

## D-48 · 擦拭改为夹黑板擦的**两个长侧面**，并把"张开落下 → 夹拢 → 再下压"定成顺序

**日期**：2026-08-29（用户审核录像时提出）

**结论**：两块板从夹 ±X 的 45×25 **短端面**改为夹 ±Y 的 90×25 **长侧面**。
这既是生活常识（捏黑板擦捏长边），也在每一项上都更好：

| | 夹短端面 | 夹长侧面 |
|---|---|---|
| 成功率 | 82.7%（2233/2700）| **96.6%（2609/2700）** |
| 工具滑脱 | 1.6~13.2 mm | **0.6~0.7 mm** |
| 路径区域内 | 67~69% | **92.4~92.6%** |
| 清除率 | 75~88% | 75~92% |
| `tool_offset` 成功 | 250/450 | **450/450** |

⚠️ **右列是当天那一次采集的数**（2026-08-30 补记）。S4 用的 `/tmp/s3_wipe_v5`
是同一套控制器的重采：**2606/2700（96.5%）**，工具家族路径区域内 92.0~92.3%，
`direct_wipe` 不用工具、区域内 85.3%（它没有工具可滑脱，那一列是 0.0）。
差别是重采的随机种子，**对比的方向与量级没变**。
**引用擦拭的数时以 `out/s3_wipe/report.txt` 为准。**

**为什么更好，不只是更像**：

1. **扫掠沿 Y**，而长侧面的法向也是 Y —— 推力由**法向力直接传**；夹短端面时
   同样的推力只能靠摩擦传，工具跟不住路径（滑脱 13 mm、区域内只有 68%）。
2. `tool_offset` 的偏心 ±6~10 mm 落在长侧面的 90 mm 上，两边各有 27.5 mm 余量；
   落在短端面的 45 mm 上时余量只有 5 mm，板有一小半悬空——这就是它原来
   250/450 的原因。
3. `tool_tilt` 绕**扫掠轴 Y** 侧倾，而绕 Y 转**不改变 ±Y 面的法向**，
   抓持面始终与板平贴；板也跟着一起倾（`quat_mul(q_tilt, q_face)`），
   就是人捏着长边把工具侧一侧。夹短端面时 ±X 面的法向会跟着倾，板不倾，
   变成边角接触。

**顺序也必须改**（两个坑，见 P-51）：

* 夹持位比工具本体窄 2×GRIP_INTERF，**直上直下落下去等于拿板的下边缘楔在
  工具顶面上**。夹短端面时工具要沿长轴挪 45 mm 才脱得出，勉强夹得住；
  夹长侧面只要挪 22 mm，实测工具被顶高 23 mm、随即甩出 200 mm。
  改成**先张开 6 mm 落到位、再夹拢**。
* 但"张开落下"之后板不受阻，会一路落到**已经下压**的高度，等夹拢时竖直方向
  的位置误差已归零，压力也归零（板 z 误差 +1.5 mm -> +0.15 mm，
  平面法向力 4.8 N -> 0.45 N，清除率 0%）。所以顺序必须是
  **张开落下 -> 夹拢 -> 再下压**，三段各占 establish 相位的 40%/30%/30%。

**没有改任何判据。** 清除判据仍是 `plan/01` §5.3 的三条同时满足；
法向力 6.1~6.7 N 仍在 3~8 N 的允许区间内。

## D-49 · contact mode 改由**两刚体位姿差分**判，原始判据并排保留 ⭐

**日期**：2026-08-29 初版；**2026-08-30 修订，初版的主判据选错了**

**背景**：`log/progress.md` 记过一条"要带进 S4 决定怎么处理"的观察——抽屉数据
里 separating 占到 26.7%，而几何上接触是连续的（板与杆的间隙全程稳定在
−0.5 mm）。S3 的判据先按摩擦锥比值分 stick/slide，再用 `separation > 0`
**覆盖一切**；PhysX 会在接触带着力的同时报出正的 separation（P-31 的逐子步
采样伪影），于是带力的接触被标成了"正在分开"。

**决定**：

1. **有没有接触**由**法向力**判，不由 separation 判。`separation > 0` 只在
   法向力已经归零时才产生 separating。
2. **stick / slide** 由接触点处的**相对切向速度**判，阈值 5 mm/s；那个速度由
   **接触体与被操作物体的位姿差分**算（`interaction._pose_slip`），
   不用 PhysX 报的瞬时速度——后者被采集板的姿态极限环污染（P-52）。
3. **四路量全写进记录**：`mode/raw`（S3 原值）、`mode/slip_speed`（主判据的
   连续值）、`mode/pose_slip` / `mode/patch_slip` / `mode/inst_slip` / `mode/cone_ratio`
   （三条并存证据）。报告里并排出，**不用新判据去掩盖旧判据**。

### ⚠️ 初版把主判据定成了"接触斑块在物体表面上的位移"，那是错的

初版的理由是"提取器不该读 `source/*`"。**那条规矩是我自己加严的**——
`plan/02` §1 禁的是把 source 字段**写进表示**，不是禁 oracle 用特权数据去算
物体中心的物理量。代价是斑块位移会把"平板贴圆柱时接触线随姿态微动而迁移"
误判成滑移：

| sticking 占比（法向力加权） | S3 原始 | 初版（斑块位移） | **修订（位姿差分）** |
|---|---:|---:|---:|
| 抽屉（夹住把手往外拉） | 32.6% | 35.9% | **92.5%** |
| 旋钮（推销钉） | 42.6% | 48.5% | **80.8%** |
| 擦拭（sliding 占比） | 44.4% | — | **86.9%** |

板夹住把手往外拉，接触当然全程是贴着的；擦拭当然是滑的。**修订后三个任务
才按物理分得开**，初版三个任务都挤在"一半滑一半贴"。

**位姿差分这条判据的三重理由**：

1. **在干净数据上与瞬时速度等价**。擦拭数据集的板角速度是 0，三种估计
   逐帧相关 0.95、各阈值下 sticking 占比差 0.5 个百分点以内。
2. **在被污染的数据上不受影响**。位姿是**位置量**，50 Hz 上差分等于对 6 个
   物理子步取平均，极限环自然抵消。
3. **它就是真实装置能测的量**。`plan/07` §3 的传感方案给的正是"面相对物体的
   位姿"，差分即得相对速度——oracle 与硬件在这一项上算的是同一个东西。
   这条是修订后才看清的，也是 `plan/05` 实验七能成立的前提。

**这个阈值是敏感的，必须连敏感度一起报**（工作方式第 4 条），所以记录里存的是
**连续量**，标签只是按 5 mm/s 切出来的便利品，S5 可以自己重切。

**已知盲区**：接触斑块停在物体同一处、而接触体沿自身表面滑过去时，位姿差分
判得对而斑块位移判不出；反过来纯滚动时斑块位移会误报滑移。两者都在记录里，
摩擦锥比值是第三条交叉证据。

**被否决**：

- **只做时间闭运算**：治得了"报告断续"，治不了"贴着却被判成 separating"。
- **原样保留 PhysX 的判据**：separating 这一档的采样伪影会直接进 envelope，
  E-I 的 `r_mode`（`plan/04` §5.1）就会去跟踪一个伪影。
- **用瞬时相对速度**：见 P-52。
- **用接触斑块位移**（初版的选择）：见上表。

## D-50 · 物体表面采样：按 pitch 定点数、逐部件配额、嵌套多分辨率、hash 冻结

**日期**：2026-08-29（S4，`src/it/surfaces.py`）

**决定**：`plan/02` §2 的表面采样落地为四条：

1. **点数按目标 pitch 换算**，不固定 256（`plan/02` §2.1 原文就是这么要求的）。
   目标 pitch 3 mm，封在 [4096, 16384]。实测：抽屉 16384 点 / 4.12 mm，
   旋钮 8192 / 2.22 mm，球 4096 / 1.94 mm，擦拭平面 16384 / 6.3 mm。
2. **逐部件配额**（每个部件至少 64 点，其余按面积分）。**这一条不是美观问题**：
   纯按面积分配时，抽屉把手横杆只占物体总面积的 3.5%，"横杆背面"——S3 实测
   90.2% 的接触落在那里——只分到 20 个采样点，region 热图在最要紧的部位上
   反而最糊。加地板后是 210 个点。
3. **嵌套多分辨率**：先撒候选点，再逐部件 FPS 定序、交错成全局序列，于是
   前 64 ⊂ 前 256 ⊂ 前 1024 ⊂ 全部。S4.5 要扫这四档（`plan/05` 实验零），
   四套互不包含的采样会把"分辨率的影响"和"采样点恰好落在哪的影响"混在一起。
4. **每份采样一个 sha256，写进每条记录的 meta**，验收时重算比对。
   `plan/06` §3.1 要求四宫格标 envelope 的 hash，源头就在这里。

另加两条实现上的规矩：

- **埋在别的部件里的采样点要剔掉**（销钉底面贴着圆盘顶面那一圈）。留着会让
  `plan/03` §8.1 的 width（region 占物体表面积的比例）分母虚高。
- **几何变体必须显式传**。`surface_for("block", "g1")` 直接抛异常而不是
  退回 nominal——沉默地退回会让 `unseen_geometry_test` 那一档的接触点
  归到错误的表面点上，而这件事从数字上看不出来。

**配套**：几何参数从 `it.build_assets` 拆到新模块 `it.geom_cfg`。原因是
`build_assets` 在 import 时就要 `from pxr import ...`（拿不到 pxr 就自己拉起
一个 SimulationApp），于是"读一下把手多高"这种纯数值的事也要先启动 Isaac Sim，
本机根本做不到。拆分是**纯搬运**：改动前后逐个 dataclass 的 `asdict` 与
`GEOM_VARIANTS` 逐位相同（已比对），`build_assets` 原样再导出全部名字。

**被否决**：

- **读 USD 网格来采样**：要起 Isaac Sim，还把"资产文件当前是什么样"这个额外
  状态引进来。D-07 已经规定资产由参数生成，从同一份参数解析地采样更一致。
- **固定 256 点**：`plan/02` §2.1 明确算过，256 点在 90×45×25 mm 的黑板擦上
  pitch 7.8 mm，会把传感器测到的斑块结构抹平 6 倍。
- **纯按面积均匀撒点**：见上面第 2 条，会把点全给不接触的大面。

## D-51 · 新增 S4.6 传感可观测性：本轮补上对 idea 硬件前提的检验 ⭐⭐

**日期**：2026-08-30（用户要求重新审视"是不是真在验证 idea"之后）

**背景**：idea 的核心是"不采人手动作，只采各接触面的位姿 + 面上的触觉"。
审计发现**整轮计划没有一处碰这句话**——`plan/00` §4 把"真实传感能否恢复这些
变量"整个推给 Phase II，于是本轮验证的只剩"物体中心表示 + 任务无关执行器"，
而那部分与 CHORD 的 object-centric contact wrench、以及
[Transferring Contact, Not Just Motion](https://arxiv.org/pdf/2606.15516)
一类的接触中心抓取迁移高度重叠。**属于本方案自己的那一条主张，一个实验都没有。**

**决定**：新增 `05` §0.1 实验七 / 步骤 S4.6，`tools/s4_sensing.py`。
拿已验收的 S4 Oracle Record 当真值，**模拟装置的观测模型**重建
region / mode / mechanics，扫四个维度：面相对物体位姿误差、**误差的时间结构**、
taxel pitch、触觉模态。纯离线，不需新训练。

**为什么这不是"给表示加噪声"**：加噪只回答"表示对误差敏不敏感"；这里换的是
**信息来源**——只允许用装置能测的量重新算一遍。法向-only 的皮肤给不出切向力，
那一档的 mechanics 是**残缺**而不是带噪的。

**首批结果（抽屉）与它们改变了什么**：

1. **误差的时间结构比幅值更要命**。同样 0.5 mm：配准型偏置下 stick 一致率
   0.824，每帧独立白噪声下只有 0.081——mode 由位姿差分得到，白噪声被放大成
   √2·σ/dt。**所以硬件指标要写成"帧间稳定性 < 0.5 mm"，不是"精度 < 0.5 mm"。**
   这直接支持 `plan/07` §3 的"粗跟踪 + 触觉配准"路线，而不是高精度绝对跟踪。
2. **taxel pitch 2 mm 够，4 mm 开始掉**（region 余弦 0.968 → 0.886）。
3. **binary 触觉不够**（法向力误差 67%）；法向-only 足以给 region 与法向力；
   **切向通道只对 C4 的力方向必需**。

**边界**：按 [GR00T 模态消融](https://arxiv.org/pdf/2512.01358) 的既有结论，
**充分性是形态相关的**，以上是双板 source 在抽屉上的数，**不得推广成全局结论**。

**被否决**：

- **维持 Phase II 的划分**：那样本轮结论无法支撑"只用接触面 + 触觉就够"这句话，
  而它是整个硬件路线的立足点。
- **改成给表示加噪声**：便宜但答非所问，见上。

## D-52 · 数据契约区分"采集侧动作"与"接触面测量"，schema 升到 v2 ⭐

**日期**：2026-08-30（外部审查指出，采纳）

**问题**：`plan/02` §1 写的是"不输出 source 的板位姿、速度、动作"，
而 `it.interaction` 顶部一度写成"这一层永不读 `source/*`"。两者不是一回事，
而后者**在实现上是错的**：D-49 初版为了守它，放弃了唯一准确的 mode 判据
（两刚体位姿差分），改用接触斑块位移，把抽屉 92.5% 的 sticking 判成一半在滑。

**决定**：

1. **概念上分成两类**（`plan/02` §6.1）：采集侧的**动作与身份**绝对不许进表示；
   接触面与物体的**测量位姿**可以、而且必须用来算物体中心的交互量。
   判据是"这个量是'谁在怎么操作'，还是'交互本身的物理性质'"。
2. `records.is_measurement()` 显式区分，泄漏检查改测**正确的不变量**：
   去掉 source 后只允许滑移那一路变化，其余字段逐位相同。
3. **命名**应当是 `measurement/contact_surface_pose_world`；本轮为了不重采
   四份数据集暂时留在 `source/` 下，**下次重采时改名**。
4. **schema 升到 `s4-record-v2`，v1 列入作废名单、读到就报错。**
   v1→v2 有三处实质变化：mode 判据换了（语义变，不是数值抖动）、物体位姿
   一律世界系、新增任务无关 effect 接口。不升版本的话，旧记录与新记录
   混用会让下游拿到一半新一半旧的 mode 标签，**而那从数字上看不出来**。

**为什么第 4 条值得单列**：本项目已经栽过两次"零征兆的错"（P-53、P-54）。
版本号是防止它们跨批次扩散的唯一手段，而"尽量兼容旧数据"恰恰是最危险的做法。

### 补记（2026-08-30 晚，P-55 一并查出）：第 2 条当初落地得不对

上面第 2 条写的是"去掉 source 后**只允许滑移那一路变化**，其余字段逐位相同"。
实现里它变成了一张白名单 `allowed = {mode/pose_slip, mode/slip_speed, mode/label}`，
**等于给 mode 开了一个不设上限的口子**——mode 恰恰是 D-49 改过两次、最容易错的
那个字段，白名单一放，这条检查就管不到它了。而且判据仍然是"删掉全部 `source/*`"，
与 P-54 之后提取器**必须**读物体测量位姿直接冲突，检查当场抛异常（P-55）。

**改成**：提取器在 `interaction.SOURCE_READS` 里**显式声明它读哪些采集侧字段**
（按完整尾名匹配），泄漏检查围绕这张表做四件事，**零容差**：

| | 做什么 |
|---|---|
| 2a | 记录里不含任何 `source/*` |
| 2b | 删掉**声明表以外**的全部 `source/*`，重跑提取，**逐字段 `array_equal`** |
| 2c | 删掉**声明表以内**的字段，提取器必须**报错**——宁可炸，也不在"物体大概在原点"之上算出一份看起来正常的记录（P-54） |
| 2d | 每个 `source/*` 都被归成测量或动作之一，**分类表不许有缝** |

2b 与 2c 是一对：单有 2b，"什么都不读"也能通过；单有 2c，读了指令也能通过。
`is_measurement()` 同时从模糊后缀 `"_pose"` 改成完整尾名 + 显式 `ACTION_TAILS`
禁读表——旧写法把 `source/plate0/target_pose`（**指令**）判成了测量，
与本条第 1 点自相矛盾（P-55）。

## D-53 · E-I 的 effect 通道统一成"刚体位移 + 表面状态场"，禁止任务分支 ⭐⭐

**日期**：2026-08-30（外部审查指出，采纳）

**问题**：各任务的 effect 语义与维度完全不同——抽屉是一个关节位移、旋钮是
一个关节角、自由体是 6D 位姿增量、擦拭是平面上的 dirt 场。`plan/04` §7 只说
"effect 序列进 GRU"，没说这些东西怎么进**同一个任务无关的 policy**。
照原样写下去，网络里必然出现 ``if task == "drawer" ... elif task == "wipe"``，
**`plan/00` §5 第 1 条的"任务无关"当场作废**。

**决定**：任何 effect 都改写成"**被操作物体的表面接下来会怎么变**"，两路定长通道：

| 通道 | 形状 | 含义 |
|---|---|---|
| `effect/rigid` | (T, H, 6) | 物体整体的刚体位移，表达在**物体当前系**（平移 3 + 旋转矢量 3） |
| `effect/surface_state` | (T, H, 64) | 逐表面采样点的表面状态变化（目前只有擦拭的 dirt 用它） |

关节量按**关节轴**换算成刚体位移（抽屉 = 沿导轨平移、旋钮 = 绕轴转动、
立板门的铰链不过原点则连原点一起搬），自由体直接就是位姿增量，固定物体是零。
于是"抽屉拉开 20 mm"与"旋钮转 0.3 rad"走的是同一条通道。

**两路都不含任何任务标识，维度固定，E-I 全程没有分支。**

任务原生的 `effect/current` / `effect/future` **保留但降级**：只给 S5 构造
oracle envelope 与诊断用，meta 里的 `fields.effect_interface` 写明 E-I 只许吃
前两路。

**被否决**：

- **typed effect tokens**（类型 one-hot + 轴 + 幅值）：也能定长，但"类型"这个
  离散标签会顺着网络进来，等价于给了一个弱化的 task id；而刚体位移这条路
  连类型都不需要——**同一个物理量，不同任务只是取值不同**。
- **每个任务一个 effect head**：那就是任务分支换个写法。

## D-54 · Shared Structure Model 改吃**示教集合**，并加 goal+geometry 基线 ⭐

**日期**：2026-08-30（外部审查指出，采纳）

**两个漏洞**：

1. **原文写"输入一条或少量示教"**。但 Functional Envelope 是"还允许哪些别的
   成功做法"的**集合**，一条示教在原理上给不出它——只看到把手中央对称夹持，
   无从知道偏心夹、双指纯勾、单指拉也都成立。
2. **本轮只有三个任务**。模型完全可以无视示教，只凭"任务目标 + 物体几何"
   记住"抽屉对应这份 envelope、旋钮对应那份"。那样即使未见策略测试通过，
   也证明不了它归纳了共享结构。

**决定**：

- 输入改为**一组**示教，编码器用**置换不变的 set encoder**，不用 GRU 吃单条
  （示教之间没有顺序，用 GRU 等于凭空引入一个顺序，而且天然只能吃一条）；
- **必须并排跑一个 goal + geometry only 的基线**。基线 ≈ 完整模型 →
  模型没在用示教，"shared structure"不成立，如实报告；
- **顺序**：第一版先用 `plan/03` §8 的统计程序产出 oracle envelope、把链跑通并
  驱动 Executor，神经网络放到之后。理由是失败可归因——先上网络会分不清
  "模型没学好"与"表示本身不够"。

这条与 `plan/02` §7 第 9 条（region 可推导性探针）是同一种思路：
**先证明这件事不是从别处平凡地推出来的**，再谈它有没有价值。

## D-55 · phase 与 progress 不得作为 E-I 的观测 ⭐

**日期**：2026-08-30（外部审查指出，采纳）

**问题**：`plan/04` §4 把"当前 phase 和 progress"列进所有执行器的共同观测。
但那两个值是**采集脚本的任务状态机标签**——"现在进入操作阶段了""现在擦到
60% 了"。直接发给 E-I，等于递给它一个任务专用状态机，**"任务无关"当场作废**。

**决定**：E-I 侧的 phase / progress 必须由四个通用量导出（是否建立接触、
实际 effect 与指令 effect 的误差缩减、mode 匹配率、上述满足后才前移窗口），
全程不含任务分支。S4 记录里的 `phase` / `progress` 相应**移出模型输入前缀**
（`records.SCHEMA_PREFIXES` 归到丢弃侧），只作为 S5 对齐示教的**标签**与诊断量
保留——**标签可以用，观测不行**。

## D-57 · 修正 CHORD、跨手接触迁移与 GR00T 的文献定位 ⭐⭐

**日期**：2026-08-30（接管审计，逐段核对论文正文）

**发现的三处事实错误**：

1. CHORD 不是“复制 exact wrench”。它比较由接触位置、法向和摩擦锥构造的
   wrench-space support function，带相对容差，并明确说没有恢复精确多接触净 wrench
   polytope；
2. *Transferring Contact, Not Just Motion* 不是“接触中心抓取”。它保留 15-D MANO
   pose latent，把各手 effort 标定为关节力矩、指尖力与 load descriptor，并把原语复用
   到运输/交接流水线；
3. GR00T 那篇的 74%（contact encoder）、82%（depth）、94%（contact state）是 G1
   单任务上的**并列配置**，不是逐项累加链，也不能推出所有任务中接触都是最高价值模态。

**决定**：`plan/00` 按原文改写；C4 vs C5 保留为项目内部最小性实验，但不再声称是
相对 CHORD 的直接差异。OmniContact 升为正面相邻工作，因为它同样用 contact flow
驱动统一低层执行器；真正差异必须靠 object-centric、无 body target、mode/traction
范围和留出任务 E-I 的实验来证明。

## D-58 · E-I mechanics 改成定长 task-agnostic surface traction contract ⭐⭐⭐

> ⚠️ **本条的 traction 表示形式已被 D-71 按实测否决**：下面第 2 点写的"切向方向锥 + 幅值区间"在四族候选的对照里体积最大（抽屉 2.4×、擦拭 56×）且无 coverage 收益。现行形式是物体系三维轴对齐盒 + 校准集上标定的联合标量。
> **仍然有效**的是：固定维度、无任务分支、同部件 force-conserving 散射、禁止 task id / 任务原生 effect / phase / source action 进入 payload。

**日期**：2026-08-30（接管审计）

**问题**：D-53 已把 effect 改成固定物理接口，但 mechanics 仍写成“旋钮绕轴力矩、
抽屉沿导轨力、擦拭法向/切向力”。该向量维度、名字和投影轴都由任务决定；若 E-I
观测或 reward 使用它，就存在任务分支，“任务无关”在接口层已经失败。

**决定**：

- 把 object-frame contact force 用同部件、归一化的邻域核散射到冻结表面点，再除以点
  代表面积得到 surface traction density；核带宽只跟 surface/sensor pitch 走，不按任务
  调。归一化必须守恒合力，积分力矩必须与 raw contact wrench 做硬阈值对拍；禁止
  “最近点力 / 点面积”这种随分辨率任意尖峰化的实现；
- C4 给每个联合分量内的法向 traction 区间、切向方向锥与幅值区间；合 6D wrench
  由表面点位置积分，只作固定维度一致性检查；
- task-relevant generalized force 只保留为 oracle 标签构造后的诊断投影和论文图，
  不得进入 FunctionalEnvelope、E-I 观测或 reward；
- C5 改称 exact source realization（精确 traction/wrench realization），不再含混地叫
  exact wrench；
- S5 实现前冻结 `FunctionalEnvelope` schema；S6 的 E-I dataloader 用 exact allowlist，
  对 `mech/generalized`、任务原生 effect、phase/progress、task id/name 硬报错。

S4 v2 已有 surface index、force 与冻结 surface area，可离线派生 traction，无需重采 S3。

## D-59 · Envelope 必须保持字段联合性；成功示教只能给 empirical support ⭐⭐⭐

**日期**：2026-08-30（接管审计）

**两个逻辑漏洞**：

1. 分别学习 region heatmap、mode 和 mechanics 边缘范围后任意拼接，会造出从未共现的
   物理组合；“区域 A 的方向 + 区域 B 的力”可能各自合法但联合非法；
2. 只看成功示教无法识别必要条件，也无法排除未出现的替代成功策略。它能估计的是
   示教分布的 success support，不是任务的必要充分可行域。

**决定**：Functional Envelope 表示为少量**联合分量的并集**。每个分量同时绑定
phase-conditioned effect / region / engage / mode / traction；分量由物理 interaction
features 形成，不用 strategy label；部署一次采样完整 candidate，component id 不进 E-I。
失败与 near-success 独立保存为边界反证和 executability 负例，不混进成功聚合。
没有负证据和干预前，统一称 **empirical success-support envelope**。

**Conformal 也随之修正**：

- region 用 episode-level score，校准“至少 95% 法向力加权接触质量落入区域”；
- mechanics 用 CQR，而不只是 pinball quantile；
- joint score 检查同一分量内各字段同时满足；
- 可声称的是 exchangeability 下的 marginal coverage，不是任意新任务/每个 subgroup 的
  conditional guarantee；策略、物理、几何、任务 subgroup coverage 必须另报。

## D-60 · 十五原语只证明边缘覆盖，不证明张满交互空间 ⭐⭐

**日期**：2026-08-30（接管审计）

五个轴来自 Huang/Bullock/Lynch-Mason 与本项目字段的工程综合，并非某篇文献给出的

## D-61 · Capability evaluator 是 policy-conditioned executability，不是物理能力真值 ⭐⭐

**日期**：2026-08-30（接管审计）

只用 E-I replay 的成败训练分类器，会把当前策略没学会的区域误标成形态不可行；部署时
对 K 个候选裸取单模型 argmax，又会主动利用分类器在低密度区的过度自信。AUC 0.85

**决定**：统一称 empirical executability evaluator；replay 数据外，按固定预算主动

top-k selection regret 与下游成功率，并对照随机联合 candidate、最近训练 candidate、
几何启发式。Gate E 的 60% 只是推进阈值，必须配置信区间、基线和距离/密度曲线。

## D-63 · 冻结真实主流程；撤销“求交/选择器是核心算法”的误读 ⭐⭐⭐

**日期**：2026-08-30（用户重新澄清 idea 后）

**主流程只有四层**：

1. 多位采集者为很多任务采集多条示教，同一任务可以有多人、多策略数据；
2. 上游针对每个已采集任务形成可传递的 interaction 表征；
3. 每种 embodiment 各自经过统一的 interaction-conditioned 训练，学会如何把这类
   interaction 解码为自己的 action；新 embodiment 需要训练自己的 executor，不声称
   一个旧 executor 零样本控制新形态；
4. 部署时把 interaction 送给该 embodiment 自己的 decoder/executor，触觉、视觉或其他
   servo 作为闭环稳定层。

**两项纠正**：

- “能否从已采集任务泛化到未采集任务”取决于上游模型、数据与规模，不是这套传递
  协议本身的定义。E-I 的留出任务只是一项强泛化测试，不能反过来改写 idea；
- embodiment 的能力主要编码在它自己训练出的 executor 中。单独的 executability
  evaluator 只能是有实验增益时的可选增强，不存在一个必须显式计算的“形态能力集合
  与 interaction 集合求交”。D-59 中“必须用联合分量并集”、D-61 中“评价器进入主
  闭环”的强制性要求由本决定撤销；其中关于“不把成功数据冒充必要充分条件”和
  “可选分类器不能冒充物理能力真值”的警告仍保留。

**S5 第一实现**：先做直接、可审计的多示教统计传递。按归一化 interaction progress
对齐；每条 episode 先在时间格内汇总，再跨 episode 等权统计；输出固定 surface 上的
effect、region mass、engage direction、mode probability 与守恒 traction。10/90 分位数
只称描述性统计。真实数据若显示严重多峰或下游无法使用，再用冻结实验比较聚类、条件
模型或校准方法，不能先凭语义想象出复杂算法再宣称它是创新。

## D-64 · Surface mechanics 使用守恒的 coarse cell wrench；surface 必须随数据冻结 ⭐⭐⭐

## D-65 · S5 命令轴换成"相分段 + 活动量"，`progress` 单独用会退化 ⭐⭐⭐

**日期**：2026-08-30（接手复核 S5 contract，实测 33 条真实 S4 记录）

**问题**：v1 按全局 `progress` 把每条示教切成 32 格。`progress` 是**任务 effect 完成度**
（抽屉 `opening/goal`、擦拭 `cleared`），接近段恒为 0、到达目标之后恒为 1。实测：

| 任务 | 帧落进"首格 + 末格"的比例 | 中间 30 格每格帧数中位数 |
|---|---:|---:|
| 抽屉 | **83.9%** | 2 |
| 旋钮 | **73.3%** | 2 |
| 擦拭 | 37.9%（另有 15.4% 空格） | 7 |

也就是说，抽屉那份 artifact 里 30 个命令格各由 1~2 帧描述，而两个退化格吞掉了
整条 episode 的 84%。**所有既有校验照常通过**：`support/episodes` 是满的、
`command/valid` 全 True、`empty_bins` 报 0。见 P-58。

`plan/03` §8 第 1 条原文是"按 **phase 和** object progress 对齐"，v1 只实现了后半句。
`phase` 是记录里已有的、四个任务共用的 int8（approach / establish / manipulate /
release），按 D-55 它作为**离线对齐标签**是允许的（进模型观测才不允许）。

**决定**：命令轴改为

1. 先按 `phase` 把 episode 切成四段；
2. 每段分到的格数按该段的**交互活动量占比**分配，每个**有帧**的段保底 2 格；
3. 段内也按累计活动量分格。

活动量 = 接触冲量率（`aux/frame_force`）+ effect 变化率，两路**各自在 episode 内
归一化**后相加，因此不需要在牛顿与米之间拍权重（D-31 的第 2 个洞），也不含任务分支。
effect 一路不取 `norm(concat(dp,dr))`，而是把固定 effect 契约（D-53）的刚体增量作用在
冻结 surface 点上取**表面点平均位移**（米），`surface_state` 取面积加权变化量。

**为什么按活动量而不是按帧数**：另一个候选 `phase_time`（四段均分、段内按帧序）在
占用均匀度上最好看，但它让**抽屉只有 18%、旋钮只有 26% 的命令格里有接触**——接近段和
松开段本来就没有接触，操作段里到达目标之后还有很长一截无接触的保持，命令通道的容量
被花在"这一步不需要接触"上。活动量分配后接触格占比是 87% / 88% / 100%。

**判据**：五个候选用 `tools/s5_align_probe.py` 实测（产物 `out/s5_align/probe.txt`）。
主判据是 **binJS**——同一条 episode、同一格内各接触帧的接触分布不一致度。它**不受格子
大小混淆**（格子越大越平均、看起来越像），直接回答"这个格有没有把物理上不同的接触状态
混进同一条命令"：

| key | 抽屉 binJS | 擦拭 binJS | 旋钮 binJS | 接触格占比 | 空格率 |
|---|---:|---:|---:|---|---|
| `progress`（v1） | 0.145 | 0.305 | 0.210 | 99.5 / 84.6 / 100 | 0.3 / **15.4** / 0 |
| `phase_time` | 0.146 | 0.383 | 0.357 | **18.0 / 100 / 26.4** | 0 |
| `phase_progress` | 0.134 | 0.397 | 0.325 | 43.5 / 100 / 38.2 | 1.0 / 0 / **17.0** |
| `phase_effect` | 0.130 | 0.381 | 0.332 | 44.8 / 100 / 36.1 | 2.6 / 0 / **20.5** |
| **`activity`** | **0.114** | **0.260** | 0.215 | **87.2 / 100 / 88.5** | **0 / 0 / 0** |

**如实记下不利的一面**：另一项 `within_family_js`（同族两条示教在同一格上的分布差异）
在抽屉/旋钮上反而是 `progress` 略低（0.301 vs 0.307、0.383 vs 0.354 —— 旋钮是 activity 更低）。
**没有按这一项选**，因为它被占用量混淆：把 84% 的帧倒进 2 个格会得到高度平均、
彼此trivially相似的分布。这一条写在这里，是为了下一个人看到那两个数时不必重新怀疑。

**被否决**：

- **DTW / GCTW 对齐**（Zhou & De la Torre）：原理上更强，但引入不可审计的对齐路径，
  且本项目的 `phase` 标签已经提供了粗粒度的非线性对齐。数据显示需要时再上；
- **按帧数比例分配格数**：把容量给了没有接触的段，见上；
- **固定 2/6/20/4 的格数预算**：四个魔数没有依据。按活动量占比分配只留一个参数
  （保底格数 = 2），而且它记在 `meta.aggregation.phase_budget` 里可审计。

## D-66 · 同一个 cell 的所有字段必须来自同一组 episode 和同一批帧 ⭐⭐⭐

**日期**：2026-08-30（同上，实测 33 条真实 S4 记录）

**问题**：v1 对"这条 episode 没碰过这个 cell"用了**两套不一致的表示**——
`region` / `engage` / `mode` 填 NaN（跨 episode 统计时被 `nanmedian` 排除），
而 `traction` / `moment_density` 填 0（被算进统计）。于是同一个 cell 上：

- 方向是"碰过的那几条示教的平均"；
- 力是"全部示教的平均"，被没碰过的那些用零稀释。

实测每个 occupied cell 的中位支持度只有 **5/12**（擦拭 3/12），所以过半的 cell 上
零值占多数，中位数直接落到 0。结果是**自相矛盾的指令**——同一格同一个 cell 同时说
"这里应该接触（region mass > 0）"和"这里的力必须恰好为零（traction median = 0）"：

| 任务 | v1 中出现该矛盾的 occupied cell 占比 |
|---|---:|
| 抽屉 | **57.9%** |
| 擦拭 | **80.7%** |
| 旋钮 | **48.7%** |

这正是 D-59 警告的"分字段边缘量拼出物理非法组合"，只不过它不是通过显式拼接进来的，
而是通过 NaN 策略不一致溜进来的——**更隐蔽，因为每个字段单独看都对**。见 P-59。

**决定**：

1. `traction` / `moment_density` 改为**接触条件化**：每条 episode 在每个 cell 上只用
   **该 cell 实际有接触的那些帧**求平均，没碰过就是 NaN，与 `engage` / `mode` 完全一致。
   于是同一个 cell 的四个字段来自同一组 episode、同一批帧；
2. 新增 `region/support` (B,S)：多少条 episode 在这个格里碰过这个 cell。下游此前
   **完全无法分辨 1/12 与 12/12** —— artifact 里只有逐格的 `support/episodes`；
3. 新增 `region/duty` (B,S)：碰过的 episode 里，这个格内有多大比例的帧在接触。
   它是从接触条件化 traction 还原逐帧平均力的那个因子；
4. 新增 `engage/concentration` (B,S)：各 episode 单位方向的合矢量长度 ∈[0,1]。
   v1 把它阈值化成 `engage/valid` 一个 bool 就扔了，而它正是**方向多峰性的直接度量**，
   代价为零；
5. `validate()` 增加硬约束：`support == 0` 的 cell 上所有接触条件化字段必须为 0，
   `support > 0` 的 cell 上 `mode/prob` 必须归一化。矛盾指令在契约层就进不来。

**同时更正一处措辞**（这条比上面更容易骗到人）：v1 的 smoke README 把
"6D wrench 重建误差 6.18e-6 N"当成 mechanics 契约的验证。**那个数在代数上是恒等式**：
cell 内先算相对代表点的局部力矩、再加上 `cross(representative, F)`，恒等于直接对接触点
求力矩，所以拿它跟自己对拍只能得到浮点精度。真正有信息量的是**表面投影完整性**——被
`on_surface` / `weight>0` 滤掉的接触占了多少力，以及由此与 S4 **独立**记的
`mech/wrench_obj` 差多少。诊断字段改名为 `projection_residual_*` 并增报
`dropped_force_mass_fraction`。

**并且**：跨 episode 取中位数/分位数之后 6D wrench 守恒**不再成立**（中位数是非线性的）。
这是任何统计聚合的固有性质，不是缺陷，但**不得再声称"积分恢复 6D wrench"**。守恒只在
聚合前的单条 episode 上成立，`_projection_diagnostics` 查的就是那一层。

**schema 提到 `interaction-transfer-v2`，v1 读到即报错。** 与 `s4-record-v2` 同一个理由：
v1/v2 的对齐轴与 cell 统计口径都变了，混用会让下游拿到一半新一半旧而看不出来。
S6 尚未开始，此时改代价最低。

**被否决**：

- **保留 v1 的逐帧平均 traction，只补 support/duty 让下游自己判**：下游要正确使用就
  必须自己重做一次条件化，而 `[q10,q90] = [0,0]` 的带在任何跟踪 reward 里都是硬约束
  "力必须为零"。把矛盾留在产物里、指望消费者绕开，正是 P-11 那类问题的温床；
- **只把 traction 改成条件化、不加 support**：`support == 1` 的 cell 上 q10 = q90，
  带宽为零而中位数非零。不暴露支持度，下游分不出"所有人都这么做"与"只有一个人碰过"。

## D-67 · region 允许集合在冻结校准集上做 split conformal；width 才是要报的数 ⭐⭐

**日期**：2026-08-30（S5 全量评估）

**问题**：`plan/03` §8.1 的目标函数是"在 coverage ≥ 90% 的约束下最小化 width"，
但 v1 的允许集合是**未标定的描述性超水平集**（每格按 pooled region mass 降序累计到
95%）。全量实测它做不到那个约束：

| 任务 | 未标定 τ=0.95 的留出 coverage |
|---|---|
| 抽屉 | in-dist 0.781 / 未见物理 0.788 / 未见策略 0.676 |
| 擦拭 | in-dist 0.868 / 未见物理 0.868 / 未见策略 0.637 |
| 旋钮 | in-dist 0.954 / 未见物理 0.925 / 未见策略 0.941 |

**决定**：允许集合的大小只由一个参数 τ 控制，而 ``A(τ)`` 这一族集合随 τ **嵌套**，
所以直接对 τ 做 split conformal：在**冻结的 calibration 划分**上取每条 episode
"达到 95% 接触质量所需的最小 τ"的 ``⌈(n+1)(1-α)⌉/n`` 分位数，得到 τ*。
（`plan/05` §9 本来就写了"校准集独立于两者，只用于 conformal 阈值标定"。）

标定之后 **width 才是要报的那个数**，coverage 是被约束住的那一个。抽屉实测：
τ*=0.990，留出 coverage 0.970~1.000，代价是允许区域从表面积的 1.47% 涨到
**2.25%**（平均 6.9/256 个 cell）——用 0.78 个百分点的面积换回 20~32 个百分点的
coverage。

**同时加两条防空转**：

1. **τ* 顶到 1.0 时判 FAIL**。那意味着允许集合就是整个表面，coverage 必然 100%
   而 envelope 没有约束任何东西——"通过"是空的；
2. **子群 coverage 必须用同一个 τ***（第 3 项）。早先它用未标定的 τ=0.95，
   于是第 1a′ 项在标定集合上 PASS、第 3 项在另一个集合上 FAIL，两个数根本不可比。

**边界必须说清**：conformal 给的是 exchangeability 下的 **marginal** coverage。
`unseen_physics_test` / `unseen_strategy_test` / `unseen_implementation_test` 按设计
就违反 exchangeability，那里的数字是**泛化结论**，不是标定质量的结论。
两者不得混称（D-59）。子群落差另报，正是第 3 项。

**没有因为看到 FAIL 而放宽门槛**：0.90 这个数来自 `plan/03` §8.1，改的是允许集合的
**构造方式**（从无保证的描述性集合换成有限样本有效的标定集合），不是判据本身；
未标定那一档仍然并排报出来作对照。这一点写在这里，是因为"看到失败再改判据"正是
P-11 禁止的事，而本条不是那一类，需要留下可核对的记录。

**被否决**：

- **逐格独立标定 τ_b**：格数是 32，每格的校准样本不足，且会破坏"允许集合随 τ 嵌套"
  这个让 split conformal 成立的性质；
- **直接放宽 95% 质量判据**：那是在改判据本身（P-11），而且质量判据来自
  `plan/03` §8.1 的 region 子指标定义；
- **对 mechanics 也一并做 CQR**：`1b` 的实测显示逐点带内率只有 0.32~0.70，
  且**按支持度分层后不变**，说明问题在"逐点边缘分位数"这个形式本身，不是标定不够。
  换 CQR 还是换 functional simultaneous band（Diquigiovanni et al., JMVA 2021 的
  modulation function 构造），要拿 S6 的下游成功率来选，现在只报数不动手。

## D-68 · 粗粒代表点只在同部件内部找 ⭐⭐⭐

**日期**：2026-08-30（S5 全量评估时从"擦拭两种实现互不覆盖"倒查出来）

**问题**：`surfaces.py` 的 `parent[level]` 用的是**纯几何最近邻**
（`_nearest(sel_pts, sel_pts[:level])`），没有任何部件约束。薄物体的两个面因此被
并进同一个 cell。实测在 S5 使用的 **256 档**上：

| 物体 | 代表点跨部件的表面点占比 | 主要错配 |
|---|---:|---|
| 黑板 | **26.0%** | `back` ↔ `work_face`（各约 1500 点） |
| 旋钮 | **13.3%** | `rim_side` ↔ `disc_top/bottom` |
| 抽屉 | 5.1% | `panel` ↔ `other`、`bar_back` ↔ `bar_bottom` |

黑板厚 20 mm，而 256 档的粗粒 pitch 约 50 mm——**比厚度还大**，两个面必然混。
64 档更糟：黑板 45.5%。

**这不是精度问题，是语义错误**，而且恰好打在三个任务各自最关键的那条区分上：

- 擦拭的 effect 定义在**工作面**上，`plan/02` §3.1 经 D-42 修订后 effect 只有 dirt 变化；
- 旋钮最容易看懂的反证是"把 region 从销钉换到**低摩擦轮缘**"（`plan/05` 实验五）；
- 抽屉是三个任务里**唯一**能干净检验 region 必要性的载体，靠的正是
  "同一个拉开 20 mm 可由横杆**背面 / 正面**实现"（`plan/02` §7.2）。

被发现的路径值得记：先是擦拭的 `direct_wipe` 在 tool-only envelope 下 coverage 为
**0.000**，倒查接触分布时发现 21~25% 的接触质量被记到了 `back` 上，而逐帧检查显示
**所有接触都在 z=+0.010 的工作面**。矛盾指向池化而不是数据。

**决定**：`parent[level]` 改为**只在同部件的代表点里找最近邻**。某个部件在某一档
一个代表点都没有时**直接报错**，不静默并进别的部件——那正是要修的行为。
修复后六个物体在全部四档上跨部件占比均为 **0.000**。

**兼容性（关键）**：identity `sha256` 只覆盖 points / normals / part，**不含 parent**，
所以本次改动**不改变 surface identity，S4 记录全部继续有效**，只需重建 S5 artifact。
已用黑板实测确认：identity 一致、points 一致、part 一致、parent 不同。

**连带修一个会让改动白做的坑**：`tools/s5_freeze_surfaces.py` 原先靠 identity hash
判断"已冻结的文件还新不新"，而 identity 不含 parent，于是旧文件照样被 SKIP——
**修好的代码等于没生效**（P-38 的同一个形状）。改为直接检查当前要求的不变量
（代表点必须同部件），不满足就标 STALE 重新生成。

**顺带的实测**：本机重新生成的**抽屉/旋钮** surface 与服务器冻结的那份 points 不一致
（黑板一致）。这是 **P-57 的直接确证**——FPS 的 tie-breaking 确实会跨环境改变点序，
冻结 surface 文件不是可选项。

**被否决**：

- **把 S5 的 `n_surface` 从 256 提到 1024**（黑板跨部件占比降到 6.3%）：那是在替
  S4.5 做分辨率决定，而 S4.5 的判据是下游成功率、卡在 S6 上（`plan/README` §7）。
  同部件池化与分辨率**正交**，在每一档上都严格更好，不该用调分辨率来掩盖；
- **只在薄物体上特判**：`side` 这类部件在任何物体上都可能与主面混，特判会漏。

## D-69 · `direct_wipe` 的记录含寄生接触；§7 第 8 条在重采之前不可评估 ⭐⭐⭐

**日期**：2026-08-30（S5 全量评估倒查）

**事实**：`direct_wipe`（不持工具、两块板直接擦）的 S4 记录里，**每一帧**都有一个
固定在板角 (0.260, 0.200)、法向力 0.196 N（std 0.004，方差 2%）的接触，
**60 条 episode 全部存在**，力占比稳定在 9.2~12.2%，且在 approach / establish /
manipulate / release **四个 phase 都在**。作为对照，真正的擦拭接触只出现在
283/390 帧，力 1.228 N、std 0.171。

**归因**：那是**没被使用的黑板擦**。`direct_wipe` 把 `tool` 置零不再抓它，但工具
本体仍在场景里、仍在接触过滤名单里，就那么搁在板角上被逐帧记成"物体受到的交互"。
详见 P-64。

**它造成的假结论**（差点被写进报告）：`direct_wipe` 在只用 `with_tool` 构造的
envelope 下 region coverage 是 **0.000**（305 条全灭），两实现 envelope 的 region
JS 距离 **0.657**。照字面读就是"擦拭的两种实现产生的功能交互不可互换"——
而 `plan/README` §5 的四宫格、`plan/02` §7 第 8 条、乃至"同一份 envelope 被持工具的
Allegro 和不能抓握的垫头杆各自实现"这个最有说服力的论证，全都建立在可互换上。
**把一个采集缺陷写成科学结论，正是本项目明令禁止的那一类事。**

**决定**：

1. `plan/02` §7 第 8 条在 `direct_wipe` 重采之前**标记为不可评估**，
   既不得报"通过"，也**不得报"不可互换"**；
2. 修在**采集侧**：`direct_wipe` 不生成工具，或把它挪到板外。不在 S4/S5 侧按位置
   排除——那会把"哪些接触算数"变成任务专用规则，正是 D-58 要消掉的东西；
3. 重采只重采擦拭的 `direct_wipe` 一档（373 条成功），其余三份数据不受影响；
4. `tools/s3_source_wipe.py` 的验收增加一条：**逐接触体报接触帧占比与法向力方差**。
   接触率 ≈100% 且力方差近零的接触体一律当作"搁着没动的东西"报出来。

**没有顺手改数据**：本轮不动 `/tmp/s3_wipe_v5` 与 `/tmp/s4_wipe`，只如实标注。
重采属于 S3，要在明确授权下单独做一轮，并按 D-21 记录它是否让已有产物作废。

**波及范围**：擦拭的 region / mechanics 统计（envelope 主体）受污染；
**effect 不受影响**（板角上没有污渍，清除量照常），所以 S3 的 96.5% 成功率、
dirt 覆盖图与多样性结论仍然成立。`with_tool` 四个家族不受影响。

## D-70 · 擦拭只保留持工具实现；`direct_wipe` 移出范围 ⭐⭐

**日期**：2026-08-30（用户决定）

**决定**：擦拭任务只保留"抓黑板擦擦干净"这一种**采集侧**实现。`direct_wipe`
（双板以板面直擦，373 条成功）移出数据集范围。理由是这个变体本身不合理，且它已经
被证明会引入干扰（D-69 / P-64 的寄生接触）。

**必须写清楚的因果顺序**：这个决定是在**发现该批记录有缺陷之后**做的。所以文档里
一律写"因变体不合理且记录含寄生接触而移出范围"，**不得写成它通过了任何检查**。
`tools/s5_exclude_episodes.py` 强制要求 `--reason` 并把匹配条件、原划分分布、理由
一起写进 manifest 的 `exclusions`，就是为了让后人能分辨"范围决定"与"结果不好看就
拿掉"（P-11 / P-13 禁止的那类操作）。**不删文件**，只把 `split` 改成 `excluded_*`，
决定可复核、可撤销。

**影响面比看上去小**：

- **训练数据一条不动**。擦拭的 train split 本来就 100% 是 `with_tool`，
  artifact 不需要重建；
- 消失的是 `plan/02` §7 第 8 条——**两种采集实现**产生的 envelope 能否互换。
  这一条从范围里删除，`tools/s5_eval_envelope.py` 的第 6 项相应恒为 DEFER；
- `unseen_implementation_test` 这个划分随之空掉。

**四宫格与 Gate E/F 不受影响，而且主张变强了。** 那张图是**执行器侧**的事：
Allegro 持工具擦、Allegro 掌面直擦、垫头杆垫面直擦——与"采集时用没用工具"是两件事。
`plan/04` §5.4 里"0 自由度垫头杆从未见过三个任务、直接执行擦拭 envelope"那一格照样
成立。**而且现在 envelope 完全由持工具的示教归纳出来，却要由一根根本不能抓东西的
杆子用自己的垫面实现**——比原来"两种实现各出一半数据"更强。

**代价（必须如实记）**：源头侧不再有"同一 effect、不同实现"的对照，因此
**不能再声称 envelope 在采集实现之间不变**；只能声称它不含工具字段（第 6a 项，
已通过），以及执行器侧的跨形态实现（要 S6/S10）。`plan/README` §5 与 D-12 里
"两种实现产生同一份 envelope"的表述按此改写。

**被否决**：

- **重采 `direct_wipe`（把工具挪出场景）**：用户判断该变体本身不合理，重采只是把一个
  不该有的变体做干净；
- **在 S4/S5 侧按位置排除寄生接触**：会把"哪些接触算数"变成任务专用规则，正是 D-58
  要消掉的东西。

## D-71 · mechanics 保留物体系三维盒 + 一个联合标定标量；D-58 的方向锥经实测否决 ⭐⭐⭐

> ⚠️ **本条的实测是在 traction 修好之前跑的，D-72 之后已重跑。结论（选盒子）不变，
> 但有两处必须更正**：(1) "换不来**任何**一致的 coverage 收益"过强了——新 traction 上
> 方向锥在抽屉上确实买到 +0.06~0.09 的 coverage，代价是 2.45× 体积；擦拭仍是 57× 体积
> 换约等于零。正确说法是"**没有一致的收益**"，不是"没有收益"。(2) 旋钮"未见物理"
> 的 coverage 从 0.780 掉到 0.543。见 D-72 末尾。

**日期**：2026-08-30（`tools/s5_mech_setform.py` 实测，产物 `out/s5/mech_setform.txt`）

**起因**：D-58 规定 C4 给"法向 traction 区间、切向方向锥与切向幅值区间"。我一度准备
照此把 v2 的物体系三维分位数改掉，理由是"逐点带内率只有 0.24~0.68"。**那个理由是
错的**（P-65：那是三个边缘区间取交集的产物，逐轴刻度实测 0.75~0.89，名义 0.80）。
用户随后指出不该把 D-58 当成约束。于是把"允许集合该长什么形状"改成一个**可测的问题**。

**实验**：四族候选集合，用**同一套** split conformal 在冻结校准集上各标定一个标量 k，
使 ≥90% 的 episode 有 ≥95% 的力加权接触点落进集合；再在冻结测试集上比 coverage
与体积（取立方根，得到可与 traction 幅值直接比较的线性尺度，N/m²）。

| 集合形状 | 抽屉尺度 | 擦拭尺度 | 旋钮未见策略 coverage |
|---|---:|---:|---:|
| `box_obj` 物体系轴对齐盒 | **7361** | **1274** | 0.013 |
| `box_surface` 局部系盒 | 9554 | 1274（平板上与前者恒等） | 0.010 |
| `ellipsoid` 马氏椭球 | 8745 | **1065** | 0.007 |
| **`cone`（D-58 规定的那种）** | **17764** | **71567** | 0.000 |

**决定**：

1. **保留 v2 的物体系三维 traction 表示**，不做法向/切向重参数化。坐标只是换基——
   执行器拿 payload 里的 `surface/normals_obj` 自己就能转，**待定的是集合形状不是坐标**；
2. **D-58 的方向锥形式按实测否决**：体积大 2.4×（抽屉）到 **56×**（擦拭），
   换不来任何一致的 coverage 收益。`plan/02` §6 的 C4 描述与 D-58 相应改写；
3. **补上真正缺的那一件**：一个在冻结校准集上标定的**联合**标量，把边缘区间变成一个
   有覆盖保证的联合集合。这是 v2 从头到尾没有的东西；
4. 椭球在擦拭上小 16%、在抽屉上大 19%，**没有一族占优**。选盒子是因为它不拟合训练
   分布的相关结构、实现最简单、且与现有 payload 形状一致。**椭球的数字一并落盘**，
   若 S6 显示盒子过松，它是第一顺位备选。

**另一条不该被埋掉的事实**：旋钮的未见策略（`pin_regrasp`，375 条）上**四族全部
崩到 ≤0.013**，而它的 **region coverage 是 0.941**。**接触位置能泛化，力不能。**
这是关于数据与任务的事实，不是表示的缺陷——`pin_regrasp` 在同一位置用了不同的
力模式。它必须进论文的限制一节，也是 S6 上"旋钮留出策略"要预期的困难。
（上一版报的 box_obj 0.687 是绝对尺度地板设成 1 N/m² 造成的假象；改成与本任务
traction 量级挂钩的相对地板后，四族一致崩塌。**地板是这个实验唯一的自由参数，
必须随结果一起报。**）

**被否决**：

- **法向/切向/方向锥重参数化**（D-58 原文）：见上，实测最差；
- **马氏椭球**：互有胜负，且它拟合逐 cell 协方差，在分布漂移下更脆；留作备选；
- **继续用三个边缘区间的交集**：那不是一个有覆盖保证的集合，只是三个一维区间。

## D-72 · traction 改成固定物理带宽的核散射 + 力加权池化；D-58 的禁令终于落实 ⭐⭐⭐

**日期**：2026-08-30（`tools/s5_units_probe.py` 实测，产物 `out/s5/units_probe.txt`）

**起因**：`mech/traction_obj` 标着 `N/m²`，读起来像压强。实测把命令表面从 64 格换到
1024 格（格面积缩小 16 倍），同一批示教上：

| 任务 | 64 格 | 256 格 | 1024 格 | 漂移 |
|---|---:|---:|---:|---:|
| 抽屉 | 3868 | 3942 | 10949 | 2.8× |
| 旋钮 | 12711 | 56153 | 163033 | **12.8×** |
| 擦拭 | 178 | 633 | 2498 | **14.1×** |

接触斑块远小于格子，一个接触点的力**整个**落进它最近的那一格，于是 `F/A` 里的 A 是
**我们任意选的采样分辨率**，不是接触斑块的物理面积。

**这正是 D-58 第一条明文禁止过的实现**（"直接 nearest-point force/area 会随分辨率
产生伪尖峰，禁止使用"，要求改用"同部件、归一化的邻域核散射"）。规矩写在决策记录里，
代码里一直没落实——而**所有单测、独立验收、泄漏检查全部通过**，因为它们查的是
"实现有没有 bug"，查不了"这个量的定义对不对"（P-68）。

**做法不由规格拍板，按 D-71 的同一个套路测**：四族池化候选，同一批示教、同一条命令轴，
比"换分辨率时数值变不变"。

| 池化做法 | 抽屉漂移 | 旋钮漂移 | 擦拭漂移 |
|---|---:|---:|---:|
| `nearest_area`（v3 现状） | 2.83× | 12.83× | 14.07× |
| `kernel_area` 核散射后按面积平均 | 2.03× | 4.74× | 11.02× |
| `kernel_point` 取代表点场值 | 退化（粗档恒为 0） | 退化 | 退化 |
| **`kernel_forcew` 核散射后按 \|f\| 加权** | **1.52×** | **1.25×** | **1.10×** |
| 同上，去掉最粗那一档（256→1024） | 1.12× | 1.14× | 1.07× |

⚠️ **抽屉 1.52× 没到 1.50× 的门槛，如实记 FAIL。** 不放宽门槛（P-11）。残差在最粗档：
64 格上整个把手横杆只落在少数几个 cell 里，一格里同时装下好几个互不相干的接触斑块。
**那是粗粒化本身的损失，与 1/面积 标度是两回事**，S4.5 扫抽屉时 64 档必须单列。

**决定**：

1. **散射**。每个 object-frame 接触力先用**同部件、面积加权、行和归一化**的高斯核摊到
   冻结表面点（`Surface.scatter_kernel`），合力逐帧严格守恒。带宽
   `SCATTER_SIGMA = 4 mm` 是**固定物理尺度**，跟 `plan/07` 的拟传感 taxel pitch 走，
   **不跟表面采样分辨率走**——这一条是整件事的关键；
2. **池化**。命令格的值取格内表面点 traction 的 **\|f\| 加权平均**。`kernel_area`
   为什么不行：格远大于核时力被摊进整格面积，等于换了个写法的同一个稀释；
   `kernel_point` 为什么不行：粗档下代表点几乎从不落在接触斑块上，读出恒为 0；
3. **核中心取接触点被归到的采样点**，不取接触点真实坐标。误差上界半个采样 pitch
   （~1.5 mm）≪ sigma，换来整张核表可按 surface 预计算并缓存。这个近似必须随产物记录，
   它是"traction 是 sigma 尺度上平滑后的面密度"这句话的确切含义的一部分；
4. **schema 提到 `interaction-transfer-v4`，v3 读到即报错。** 与 `s4-record-v2` 同一个
   理由：traction 的**数值含义变了**，混用会让下游拿到一半新一半旧的量而看不出来；
5. **`moment_density` 不做同样处理，并显式声明它跨分辨率不可比。** 它是 cell 内相对
   代表点的**粗粒化残差**（D-64 要的 cell wrench 记账项），力臂随 cell 边长走是定义
   决定的；核散射反而会抹掉力臂。实测它还**不单调**（抽屉 202→35→82 N/m）。
   S4.5 扫描时必须单列，不得照 traction 那条判据要求它。

**对已发布结论的影响**：S5 之前公布的 coverage / width / 带内率全程用同一个 256 档，
内部自洽，**结论不作废**；但 traction 的绝对数值全部改变，`out/s5/README.md` 里的
mechanics 一节按重跑结果更新。D-71 的集合形状比选也在新 traction 上重跑。

**被否决**：

- **保留 nearest-point 但在 S4.5 里归一化掉分辨率**：那是在给一个定义错误的量打补丁，
  而且 S4.5 要扫的正是分辨率，混杂项没法事后拆开；
- **把带宽跟着表面 pitch 走**：那样换分辨率时核也跟着变，漂移换个地方出现而已。
  带宽必须是物理量，这也是它能写进 `plan/07` 传感指标的前提。

### D-71 的集合形状比选在新 traction 上重跑

traction 的数值含义变了，D-71 的依据必须重测（否则就是拿旧量的结论替新量背书）。
同一套 split conformal、同一个 coverage 目标，`out/s5/mech_setform.txt`：

| 形状 | 抽屉尺度 | 抽屉 coverage | 擦拭尺度 | 旋钮尺度 | 旋钮未见物理 |
|---|---:|---|---:|---:|---:|
| **`box_obj`** ← 仍然选中 | **29147** | 0.875/0.818/0.853 | **20962** | **39681** | 0.543 |
| `box_surface` | 35645 | 0.875/0.848/0.831 | 20962 | 34634 | 0.601 |
| `ellipsoid` | 36320 | 0.859/0.788/0.882 | 16645 | 31788 | 0.584 |
| `cone`（D-58 那种） | **71530** | **0.938/0.909/0.919** | **1196316** | 72055 | 0.584 |

**结论不变，两处措辞要改**：

1. **方向锥仍然按体积否决**：抽屉 2.45×、擦拭 **57×**、旋钮 1.82×。但 D-71 写的
   "换不来**任何**一致的 coverage 收益"**过强了**——抽屉上它确实买到了
   +0.06~0.09。正确说法是"**没有一致的收益**，而代价在擦拭上是 57 倍体积"。
   若 S6 显示抽屉的 mechanics 太紧，方向锥是这一格的备选，**不是全局备选**；
2. **旋钮"未见物理"的 coverage 从 0.780 掉到 0.543。** 这不是回归，是修正后的量
   更诚实：新 traction 是 4 mm 尺度上的**局部**压强，而旧的是"力 ÷ 整格面积"，
   格内一平均就把物理参数（摩擦、质量）造成的局部差异抹平了。
   **局部压强对物理变化更敏感，本来就该更难跨物理泛化。**
   D-71 已记的"旋钮未见**策略**四族全崩到 ≤0.013"在新 traction 上更严重（≤0.005）；
   现在"未见**物理**"这一格也暴露出来了。两条都进论文的限制一节。

## D-73 · 连续滑移速度进 payload，`mode/prob` 降为诊断字段 ⭐⭐

**日期**：2026-08-30（`tools/s5_units_probe.py` 实测）

**问题**：`mode/prob` 的四档（没接触/黏住/滑动/分离）是拿 `SLIP_SPEED_MIN = 5 mm/s`
切出来的。把阈值在 1~10 mm/s 之间换，"黏住"占的**力**比例：

| 任务 | 1 mm/s | 3 mm/s | 5 mm/s（现用） | 10 mm/s | 摆动 |
|---|---:|---:|---:|---:|---:|
| 抽屉 | 0.592 | 0.805 | 0.898 | 0.964 | **37.2 pp** |
| 旋钮 | 0.583 | 0.867 | 0.947 | 0.977 | **39.4 pp** |
| 擦拭 | 0.125 | 0.125 | 0.125 | 0.126 | 0.1 pp |

抽屉和旋钮的接触滑移速度整片落在那个模糊带里，**这个标签基本是阈值的产物**；
擦拭一直在滑，远高于所有候选阈值，不敏感。

`plan/02` §3.4 明写"阈值只用于生成一致的标签，不把阈值本身作为研究结论"。
**S4 侧遵守了**（同时存连续量 `mode/pose_slip`，`s4_extract` 还附敏感度表），
**S5 侧没有**：v3 的 payload 只导出离散的 `mode/prob`，于是 `plan/04` §5.1 的 `r_mode`
只能拿阈值化的结果当跟踪目标——那个任意约定就成了研究结论的一部分（P-69）。

**决定**：

1. payload 增加 `mode/slip_speed/{median,lo,hi}`，口径与 `engage` 完全一致（同一批帧、
   同一个法向力权重，D-66 的不变量因此仍然成立），并与 mechanics 走**同一套** split
   conformal 标定（`mode_slip_speed_k`）。滑移速率非负，`lo` 夹到 0；
2. `plan/04` §5.1 的 `r_mode` 改用连续量。`mode/prob` 保留在 payload 里作可解释性/
   诊断字段，**阈值只出现在画图和讲故事时**；
3. `s5_eval_envelope.py` 增加第 1c 项（连续滑移速度集合带内率）。没有一条能失败的检查，
   那个字段就只是"存在"而没有被验证过——**修了一半和没修一样**。

**被否决**：

- **改一个"更好的"阈值**：把 5 mm/s 换成别的数不解决任何问题，只是换一个任意约定；
- **只在报告里附敏感度表**：S4 已经这么做了，而它**没有自动传到下游**。
  每跨一层接口都要重问一次：这一层导出的是原始量还是判完的结论？

## D-74 · `effect/rigid` 的误差用表面度量算，两路各带任务无关刻度 ⭐⭐

**日期**：2026-08-30（`tools/s5_units_probe.py` 实测）

**问题**：`effect/rigid` 是 6 维 `(平移 3 m, 旋转 3 rad)`。实测各任务 p90：

| 任务 | 平移 | 旋转 | 表面平均位移 |
|---|---:|---:|---:|
| 抽屉 | **0.0458 m** | 恒为 0 | 0.0458 m |
| 旋钮 | 恒为 0 | **0.9395 rad** | 0.0504 m |
| 擦拭 | 恒为 0 | 恒为 0 | 0（effect 全在污渍通道，p90 擦净 0.0088 m²） |

**每个任务恰好只有一路非零，而两路量级差 20.5 倍。** `plan/04` §5.1 的 `r_effect`
定义是"物体实际状态变化与指令 effect 的负误差"——直接对 6 维取 L2，同一组权重下旋钮
的 effect 项会比抽屉大一个数量级，而擦拭这一路**完全没有信号**。这正是 D-31 第 2 个洞
（量纲失衡，最优解是"不动"），只是它藏在一个"统一接口"里面（P-70）。

**注意不是 `effect/rigid` 设计错了**：把关节量换算成刚体增量正是它消掉任务分支的办法。
错在**下游拿它算误差时缺一个任务无关的归一化**。

**决定**：

1. payload 增加 `effect/rigid/metric`——一个 6×6 度量 `M`，使
   `ξᵀMξ` = 把 `ξ=(dp,dr)` 作用在冻结 surface 点上得到的**表面点均方位移**（m²）。
   它只由物体几何决定：任务无关（同一个公式）、有物理含义、且自动处理了旋转与半径的
   关系（大物体转同样角度表面走得更远，本来就该权重更大）。用**全分辨率**表面点做面积
   加权积分，因此与命令分辨率无关。换算后抽屉 0.0458 m、旋钮 0.0504 m，**从差 20.5×
   变成差 1.10×**；
2. `effect` 的**两路**各带一个在训练划分上标定的刻度（`effect/rigid/scale_m` 与
   `effect/surface_state/scale`），`r_effect` 是两项无量纲相对误差之和。刻度在成功轨迹
   上标定而不是拍，正是 D-31 第 2 个洞给的处方。恒为零的那一路刻度取 1.0（分子也恒零，
   等价于不贡献；取 0 会让 `r_effect` 变成 NaN 而不是"这一路没有要求"）；
3. `transfer.activity_rate` 早就用同一个办法解决同一个问题，只是当时没想到 `r_effect`
   也需要它。现在两处共用 `surface_metric`。

**顺带修掉的一个真错**：第一版把 `surface_state` 的刻度写成"格数 × 表面 cell 面积"。
`effect/surface_state` 存的是**被擦掉的 dirt 格数**，那样算出来的"擦净面积"是
1.24 m²，而整块板只有 0.30 m²。payload 改用这一路自己的 L1 量级（量纲在 `r_effect`
里被约掉），物理面积只在诊断里用 dirt 网格的 `cell_m` 换算。

**被否决**：

- **给 6 维拍一组固定权重**：那就是 D-31 第 2 个洞本身；
- **让每个任务自己定权重**：任务分支，"任务无关"在接口层当场作废；
- **把 `surface_state` 也换算成米**：两者是不同的物理量（物体动了多远 vs 表面状态变了
  多少），硬凑一个换算率就是又拍了一次。各自归一化再相加是诚实的做法。

## D-75 · 一条工作规则：给每个自定义量列出它的非物理依赖 ⭐⭐

**日期**：2026-08-30

P-68 / P-69 / P-70 是同一天从同一个问题里掉出来的三个洞，共同形状是：

> **单元测试查得了"实现有没有 bug"，查不了"这个量的定义对不对"。**

三条都不报错，三条都让所有既有校验照常通过。而只要问一句
**"这个量依赖了哪些不属于物理的东西"**，三条都当场暴露：

| 量 | 非物理依赖 | 实测 |
|---|---|---|
| `mech/traction_obj` | 表面采样分辨率 | 换一档变 2.8~14.1× |
| `mode/prob` | 一个滑移速度阈值 | 换阈值摆动 37~39 pp |
| `effect/rigid` 的范数 | 米与弧度的相对权重 | 两路差 20.5× |
| ~~`region/mass`~~ | 归一化分布，无依赖 | ✅ |
| ~~`engage/dir`~~ | 几何方向，无依赖 | ✅ |
| ~~`region/duty` / `engage/concentration`~~ | 无量纲，无依赖 | ✅ |
| ~~`effect/surface_state`~~ | 与命令分辨率解耦 | ✅ |

**决定**：任何新增字段进 `EXECUTOR_ARRAYS` 之前，必须在评审里答出这一栏；答案是
"有依赖"时，要么消掉它（D-72 的做法），要么把原始量一并导出让下游能重判（D-73 的做法），
要么给一个任务无关的归一化（D-74 的做法）。`tools/s5_units_probe.py` 是这条规则的
可执行版本，进 `s5_all.sh`。

**通用形状**：**带单位的量最容易骗人。** `N/m²` 读起来像压强，于是没人再问那个 m²
是从哪来的。凡是"某个量 ÷ 某个面积/体积/时间"，都要先答出分母是物理决定的还是实现
决定的；凡是拼接向量，都要问一句下游会不会对它整体取范数。
